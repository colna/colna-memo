## 全栈工程师（前端为主）· 独立负责社交陪聊产品三条核心产品线
以复杂 C 端交互、浏览器端自动化、运营后台前端为核心，兼具 Node.js 后端与 Android 容器交付能力。

### 一、PWA · C 端女方陪聊作战端（核心前端）
- **业务**:女方核心端 —— 聊天 / 音视频通话 / 实名探真 / 按分钟计费,直接决定女方留存与平台合规收入。
- **架构**:React + TypeScript 移动端 PWA,运行于 Android 套壳 WebView 容器;IM 基于腾讯云 TIM,音视频基于 TUICallKit,web / native / mock 多套通话栈并存。
- **前端产出**
  - 主导通话模块 web/native 双端解耦重构:统一两端一致的通话体验与业务规则,规则改一次两端同时生效,显著降低出错率与维护成本。
  - 搭建探真(自拍 / 语音)实名验证抽屉:完整交互状态机(录制→送审→通过 / 失败),UI 与后端审核解耦、可复用易扩展。
  - 集成实时音视频通话前端,并实现按分钟违规检测(静音 / 露脸 / 截图多路)与扣款结算,保障计费合规。
  - 重构聊天输入栏,统一语音 / 图片 / 礼物 / 探真多模式输入;攻克套壳 WebView 下的性能、内存与移动端手势 / 媒体兼容问题。
- **业务价值 · 量化**:【填:探真通过率 / 通话计费准确率 / 女方端崩溃率↓% / 通话相关 bug 数↓】

### 二、SP · Social-Proxy 社媒代理自动化
- **业务**:IG / Snapchat 多平台账号自动化运营中台 —— 自动完成加好友、回关、私信、主页同步等获客动作,把人工运营规模化。
- **前端 / 浏览器端产出（核心）**
  - 设计并交付注入式浏览器自动化框架:向 WebView 注入脚本驱动真实 DOM 交互,支持页面跳转后断点续跑;实现关注 / 私信 / 拉消息 / 切专业账号等能力,攻克多语言 DOM 适配、防误触发跳步、真机稳定性等问题。
- **后端 / 容器产出（全栈支撑）**
  - 设计三层自动化管线 Signal(事实)→ Todo(决策)→ Behavior(执行),后端 NestJS + WebSocket 设备连接管理 + Redis 实时在线;打通获客动作链(交换 → 回关 → 静音 → 开场私信)与私信自动回复管道;Android 容器支持单账号多社媒多开挂机。
  - 主导 Snapchat 接入方案。
- **业务价值 · 量化**:【填:覆盖账号数 / 日均动作量 / 人工替代率 / 获客转化↑%】

### 三、Minerva · 运营后台
- **业务**:SP 与陪聊运营的内部 admin —— 设备管理、脚本监控、实时 / 历史看板,支撑运营决策。
- **前端产出（核心）**
  - 基于 Umi / React + echarts 构建运营看板:SP 设备管理、脚本错误日志流式导出、实时在线统计看板(数据可视化)。
- **后端产出（全栈支撑）**
  - Fastify + 裸 SQL 分层后端:当前在线读 Redis、历史曲线基于 Postgres 去重合并在线区间;定位并修复线上「当前在线恒 0」问题(绕开基础设施限制,产品级换源)。
- **业务价值 · 量化**:【填:看板服务运营人数 / 数据延迟 X→Y / 问题定位效率↑】
