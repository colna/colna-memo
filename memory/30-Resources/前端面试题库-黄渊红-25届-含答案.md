> 岗位基准：杭州 15–20K 前端。简历标「25 年应届生」，但按时间线实际已有约 1.5 年经历（腾讯 6 个月 + 知乎 10 个月），**先确认按应届还是社招标准面**。
> 建议 65–75 分钟：业务 10 / 腾讯 12 / 知乎 15 / DevRelay 12 / 基础 12 / 手写 8 / 反问 5。标 **必问** 的优先。

## 一、基本情况与动机（10 分钟）

### 1. **必问** 时间线与身份

> 2025.06 毕业，但 2025.04 就进了腾讯：当时是实习还是正式？为什么 2025.09 离开、直到 2026.01 才入职知乎？这 4 个月在做什么？

- 期待：实习/正式说清楚；离开腾讯有具体原因（业务调整、转正/方向、地域、学业）；空档有学习/项目/求职安排；时间线自洽。
- 警惕：把实习包装成正式；6 个月离职原因含糊；空档说不清；与背调冲突。

### 2. **必问** 知乎岗位性质与边界

> 知乎这份是正式、外包还是实习？团队几人？你负责的模块边界在哪？上游是谁、下游是谁？向谁汇报？

- 期待：用工性质明确；能说清自己负责的前端/全栈范围；知道上下游；不把团队产出全说成个人。
- 警惕：回避用工性质；「整个平台都是我做的」但说不清团队；汇报关系模糊。

### 3. **必问** 15–20K 的动机与档位

> 你实际约 1.5 年经验，杭州 15–20K 对这个年限偏高。你觉得自己匹配哪一档？如果给 15K 你来吗？如果给 20K，你能立刻独立扛什么？

- 期待：对市场有认知；能给出与档位匹配的证据（独立模块、线上结果、可复用产出）；薪资预期真实。
- 警惕：只说「我能学」；对 15K 明显不接受却继续面；把「参与」当「独立扛」。

### 4. **必问** 前端还是 AI 全栈？

> 简历标题是「AI 全栈工程师」，这个岗位是前端。你更想做哪个？如果每天写 React/小程序、偶尔碰 AI，你能接受吗？你的前端深度到什么程度？

- 期待：明确偏好但接受岗位；能说出前端最强的一项（小程序/React/性能）；不把 AI 当唯一卖点。
- 警惕：只想做 AI/Agent，前端只是跳板；对前端基础不自信也不愿补。

### 5. 最近一年写得最多的代码

> 前端还是 Python？占多少比例？给我一个你亲手写的 PR/模块，文件路径、多少行、解决什么问题。

- 期待：具体到项目/文件/技术点；能讲一次自己调试或上线的过程。
- 警惕：只讲平台/架构；代码都是同事/团队写的；说不清自己改了什么。

### 6. 项目归属与时间冲突

> DevRelay 是个人、开源还是公司项目？2026.07 开始，和知乎全职时间重叠，你怎么安排？Liszt 是知乎的公司项目，为什么放在「项目经历」而不是工作经历？两边代码/数据有混用吗？

- 期待：归属清晰；个人项目用业余时间；不涉及公司代码/数据；能说清知识产权边界。
- 警惕：把公司项目包装成个人项目；个人项目占用工作时间；说不清代码来源。

## 二、腾讯地图 / 小程序（12 分钟）

### 7. 业务与职责

> 腾讯出行小程序打车、境外出行：完整业务链路是什么？你负责哪几块？技术栈是原生小程序、Taro 还是 uni-app？

- 期待：打车链路（定位 → 起终点 → 车型/价格 → 下单 → 支付 → 行程 → 客服）；境外差异；自己负责的页面/模块；技术栈明确。
- 警惕：只讲「做打车」；说不清自己写哪部分。

### 8. 小程序机制

> 小程序双线程模型？`setData` 为什么贵？分包/主包体积？原生组件（map/video）有哪些坑？登录、支付、定位权限怎么走？

- 期待：逻辑层/视图层、`setData` 跨线程通信与数据量、diff、分包（主包 2MB）、原生组件层级/覆盖、`cover-view`、登录 `code` 换 session、支付签名、定位授权与拒绝兜底。
- 追问：「首页一次 setData 传 1MB 会怎样？」「map 组件上盖弹窗怎么做？」

### 9. **必问** GIF 首帧闪白

> 根因是什么？静态图占位、预加载、无缝切换具体怎么实现？怎么验证真的消除了闪白？低端机/弱网呢？

- 期待：GIF 解码/首帧延迟导致空白；静态 poster 占位 + `preload`/`downloadFile` + 加载完成后再替换；保持尺寸避免 layout shift；iOS/Android/微信差异；弱网兜底；真机对比。
- 追问：「预加载失败怎么办？」「多张 GIF 同时加载，内存怎么控？」

### 10. **必问** 「猜你想去」2811→1305ms

> 这个耗时从哪一刻到哪一刻？p50 还是 p90？A/B 怎么分流、样本多大、是否显著？具体改了哪些请求/资源时序？有没有负向指标？

- 期待：指标定义（页面开始/位置返回 → 模块可见）；A/B 分流、样本、置信；位置返回后先展示模块，其余数据/资源并行渐进；骨架/占位；负向（空白、错位、接口失败）。
- 追问：「位置授权拒绝/超时，模块还展示吗？」「并行请求打满带宽怎么办？」「2.8s 的基线为什么这么慢？」
- 警惕：拿实验室数据当线上；没有样本/显著性；把别的改动算进来。

### 11. 首页内容、营销与客服

> 首页内容展示、营销活动、客服承接分别怎么做？活动页是配置化还是写死？埋点、灰度、降级、兼容怎么处理？

- 期待：活动搭建/配置、资源位、跳转协议、埋点、灰度、静态兜底、客服入口与小程序跳转；兼容旧版本。
- 追问：「活动上线后发现配置错了，怎么快速回滚？」

### 12. 境外出行差异

> 境外出行和国内有什么不同？i18n、时区、货币、地图、网络、合规分别怎么处理？

- 期待：多语言/时区/货币、地图服务差异、弱网、隐私合规、支付方式；能说清自己碰过的部分。
- 警惕：只答「加了翻译」。

## 三、知乎 AI 平台（15 分钟）

### 13. **必问** 瑶光 AI 服务平台

> 平台解决什么问题？30+ AI 服务怎么管理？配置、调试、评测、发布链路是什么？你负责前端、BFF 还是全栈？

- 期待：服务注册/配置 schema、模型与 Prompt 版本、调试、评测、发布、权限、审计、灰度、回滚；自己负责的模块与代码。
- 追问：「一个 AI 服务上线要经过哪些步骤？」「配置错了怎么止损？」
- 警惕：只讲「做了个平台」；说不清服务模型；把团队产出说成个人。

### 14. Prompt 优化链路

> Prompt 怎么版本化？怎么评测？指标是什么？人工还是自动？怎么防止改一个 Prompt 把别的场景弄坏？

- 期待：Prompt 模板/变量/版本；测试集；指标（准确率、通过率、延迟、成本、人工评分）；回归门禁；A/B；bad case 回流。
- 追问：「评测集多大？谁标注？模型升级后怎么回归？」

### 15. 审核系统接入（Nezha / Tianji）

> 2 个审核系统怎么接入？协议、鉴权、灰度、失败降级？你做了哪部分？

- 期待：接入协议/适配层、鉴权、超时/重试、降级、灰度、监控；区分平台侧与业务侧。
- 追问：「审核服务挂了，内容还能发吗？」——降级策略与人工兜底。

### 16. **必问** Liszt Insight 模型

> 什么是 Insight？数据模型是什么？怎么生成、校验、失效、重建？Git Diff 怎么定位到引用它的 Insight？

- 期待：Insight = 带源码证据的知识条目（文件/行号/commit）；生成/校验/存储/检索；引用关系；Git Diff 命中引用证据；未命中只推进 checkpoint；CAS 状态机；幂等/去重；快照校验。
- 追问：「Repo HEAD 变了，但 Insight 没失效，为什么？」「过期快照覆盖最新知识怎么防？」

### 17. **必问** 指标口径

> 114 条 Insight、32 次 Sync、684 次检查、126 次重建、过滤率 81.6%、拦截 7 次：这些数字怎么统计？基线是什么？谁统计？「避免 558 个无效任务」怎么证明是避免的？

- 期待：统计口径、时间窗口、基线、对照组/反事实、日志来源；能承认估算与局限。
- 警惕：数字无法复现；把「没有发生」直接算成「避免」；只报喜不报忧。

### 18. **必问** CR Agent

> Review Plan 怎么生成？怎么约束只评论本次 Diff？证据怎么关联到行号？结果门禁校验什么？16 个 MR、48 条建议、27 条有效、19 条采纳怎么统计？误报/漏报怎么处理？

- 期待：按变更类型生成计划、限制范围；输出必须带 Diff 行/代码证据；门禁校验严重等级/结构/格式；人工确认有效/采纳；误报率、漏报抽样；不能自动发布。
- 追问：「Agent 说的问题不存在，怎么发现？」「和人类 Review 冲突怎么办？」

### 19. zjournal Skill

> 解决什么？怎么扫描对话？45+ 成员、每月 9 人时怎么算？隐私/权限怎么处理？为什么做成 Skill 而不是脚本/平台？

- 期待：输入/输出、扫描范围、脱敏、权限、统计口径；Skill 的分发/复用优势；人工确认环节。
- 警惕：把「工具」说成「体系」；无法说明数据来源与隐私边界。

### 20. MCP Tool

> 封装了哪些 MCP Tool？协议是什么？权限、超时、错误怎么处理？和 Function Calling 的区别？

- 期待：MCP 的 tools/resources/prompts、JSON Schema、调用链、鉴权、超时、错误回传；与模型侧 Function Calling 的职责差异。
- 追问：「Tool 返回 1MB 代码，怎么处理？」——截断/摘要/按需读取。

### 21. Liszt 前端实现

> React/TS 在 Liszt 里怎么组织？状态管理、SSE/流式、代码 Diff 展示、长列表、性能怎么处理？

- 期待：组件/状态划分、请求层、流式增量、Diff 渲染、虚拟化、错误边界；SSR 与否。
- 追问：「一个 Insight 关联 100 个文件，页面怎么不卡？」

## 四、DevRelay 多 Agent 平台（12 分钟）

### 22. **必问** 整体架构

> 从一条需求到 PR，完整流程是什么？LangGraph 有哪些节点、边、状态？人工审批、检查点、隔离工作区分别怎么实现？

- 期待：规划 → 检索 → 开发 → 测试 → 修复 → 审查 → PR；状态图/条件边；人工审批中断；checkpointer；git worktree/容器隔离；失败回退。
- 追问：「Agent 改错文件/删库，怎么防？」「任务跑到一半进程挂了，怎么恢复？」

### 23. 多 Agent 协作

> 规划、开发、审查 Agent 怎么分工？上下文怎么传递？失败怎么回退？怎么防止死循环、越权、重复劳动？

- 期待：角色/工具/输出契约；共享状态与消息；最大步数；失败分类；人工接管；权限白名单；幂等。
- 警惕：只是「串了三个 Prompt」；没有终止条件与权限边界。

### 24. **必问** 混合 RAG 与评测

> 词法、向量、依赖扩展、Rerank 各自解决什么？怎么融合？50 条基准怎么标？Recall@5/MRR 怎么算？77.07→90.53 可信吗？会不会过拟合？

- 期待：BM25/Embedding/依赖扩展/Rerank 的互补；RRF/加权融合；标注流程；Recall@5、MRR 定义；训练/测试划分；显著性；bad case；过拟合风险。
- 追问：「50 条够吗？」「换个仓库还成立吗？」「延迟/成本增加多少？」
- 警惕：只报指标不讲方法；拿训练集当测试集；没有基线。

### 25. 可靠任务执行

> Celery + Redis 怎么分队列？心跳租约怎么检测失联？5 类检查点是什么？恢复前怎么校验工作区一致？重复执行/幂等怎么保证？

- 期待：队列/优先级、`acks_late`、visibility timeout、心跳/租约、检查点（计划/文件/测试/审查/PR）、git status/diff hash 校验、幂等键、重试/死信。
- 追问：「Worker 假死但心跳还在，怎么办？」「恢复时发现文件被手工改了，怎么办？」

### 26. 上下文工程

> 批准文件优先、工具按需读取、任务摘要、最近 3 轮反馈、输入预算/输出容量：具体怎么实现？怎么防止上下文污染/超限？结构化输出重试为什么重复携带失败内容？

- 期待：上下文分层、token 预算、裁剪/摘要、工具结果截断、输出预留、重试时只带必要错误；可观测。
- 追问：「上下文超了，先删哪部分？」「摘要丢信息导致改错，怎么办？」

### 27. 可观测性

> Trace/Span 怎么建？怎么关联 Job、时间线、工具调用、Token、测试结果、Diff？一次失败怎么定位到文件/行号？

- 期待：trace_id/span、父子关系、事件、指标、日志；失败分类；回放；成本统计。
- 追问：「线上一次 Agent 失败，你怎么在 5 分钟内定位？」

### 28. 安全与成本

> 代码执行沙箱？仓库权限？Prompt 注入（仓库里恶意注释）？密钥？Token/模型成本怎么控？

- 期待：容器/最小权限、只读挂载、网络限制、密钥隔离、注入检测、工具白名单、预算/配额、模型路由、缓存。
- 警惕：「个人项目，没考虑安全」——至少要有边界意识。

## 五、前端基础（12 分钟）

### 29. JavaScript

### 39. **必问** 并发池

- 关注点：运行计数/队列、完成一个补一个、按索引回填、空数组/`limit<=0`、重试退避、错误聚合。
- 追问：「任务无限增加，怎么防止内存涨？」「某个任务卡死不返回，怎么办？」

### 40. 备选：数组/对象

> 实现 `flatten`、`deepClone`（循环引用/Map/Set）、数组去重、`groupBy`。

- 关注点：递归/显式栈、`WeakMap` 循环引用、类型判断、边界（`null`/函数/Date/RegExp）。

### 41. 备选：Hook

> 实现 `useRequest(fn, deps)`：返回 `data/loading/error`，支持取消、竞态处理、卸载不 setState。

- 关注点：`AbortController`、请求序号、`useEffect` 清理、依赖、错误处理。
- 追问：「快速切换筛选条件，旧请求晚到覆盖新结果，怎么防？」

### 42. 代码 review

给下面这段代码，问他有什么问题：

```js
function useSearch(keyword) {
  const [list, setList] = useState([])
  useEffect(() => {
    fetch(`/api/search?q=${keyword}`)
      .then((r) => r.json())
      .then((data) => setList(data))
  }, [])
  return list
}
```

**期望指出**

- 依赖数组为空，`keyword` 变化不重新请求。
- 没有清理/取消，竞态与卸载后 `setState`。
- 没处理 `res.ok`、网络错误、loading/empty。
- `keyword` 未编码，可能注入/特殊字符。
- 没有防抖，输入每个字符都请求。
- 返回结构不稳定，调用方无法区分 loading/error。

**观察**：能不能从「正确性 → 体验 → 安全 → 可维护性」分层说，而不是只挑一个。

## 九、评分与红线

### 档位（杭州，1.5 年经验）

| 档位 | 标准 |
|-|-|
| 12–14K | 基础尚可，能完成页面/小程序模块；项目多为参与；指标说不清；手写题需要提示。 |
| 15–17K | 基础扎实；独立负责过小程序/React 模块；性能优化有方法；能讲清一个 AI 项目的闭环；手写题基本完成。 |
| 18–20K | 主导过核心模块；指标有口径与归因；RAG/Agent/前端至少两项能讲到实现；有可复用产出；手写与排障都稳。 |
| 超配/谨慎 | 若前端基本功弱、主要靠 AI/团队，按 12–15K 或不适配；若前端+AI 双强，可给 18–20K，但需强证据。 |

### 红线

- **身份/经历包装**：实习写成正式、外包写成正式、6 个月离职与空档说不清。
- **项目归属不清**：把公司/团队项目说成个人；DevRelay 与知乎时间冲突解释不了。
- **指标无口径**：2811→1305、Recall@5、MRR、复用率、采纳率说不出样本/基线/统计方法。
- **只会调 AI API**：Agent/RAG 讲不清循环、检索、评测、失败处理；一追问就是「框架做的」。
- **前端基本功空**：事件循环、闭包、React hooks、CSS/网络/安全连续答错；手写题写不出。
- **AI 生成代码不理解**：能跑但讲不清为什么；不会调试；没有测试意识。
- **合规/安全无意识**：代码执行无沙箱、Prompt 注入无所谓、用户数据随意上传。

### 面试官提醒

- 这份简历对 1.5 年经验**非常漂亮**，要区分「平台/团队强」与「个人强」；每个项目至少追问三层「你具体改了什么」。
- 先定标准：按 25 届应届（12–15K）还是按 1.5 年社招（15–20K）？标准不同，结论会差很多。
- 让他**共享屏幕打开代码**：GitHub、DevRelay、Liszt 任选一个，现场找一个文件讲；比任何架构描述都有效。
- 手写题必须现场写；AI 项目再亮，前端基本功不能空。
- 指标统一追问：基线、样本、口径、谁统计、同期还有什么变化。
