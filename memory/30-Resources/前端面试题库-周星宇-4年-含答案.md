## 一、基本情况与动机（10 分钟）

### 1. **必问** 时间线与空档

> 数字马力 2 年 10 个月 → 2025.06 离职；空档 2 个月；甄汇 7 个月 → 2026.03 离职；到现在约 7 个月。每段为什么走？两段空档分别在做什么？

- 期待：每段有明确原因（业务调整、方向、家庭、base），空档有具体安排（求职/学习/项目），时间线自洽。
- 警惕：全部归因外部；7 个月空档说不清；与背调/社保冲突。

### 2. **必问** 甄汇为什么只待 7 个月？

> 7 个月做了智能客服和商旅 Agent 两个大项目，时间够吗？团队几人？你具体负责哪块？为什么离开？

- 期待：项目范围与团队配置合理；自己负责的模块清晰；离开原因具体（公司/业务/方向）。
- 警惕：两个项目都说「主导」但团队只有 2–3 人；7 个月做完整平台不合常理；离开原因含糊。

### 3. **必问** 15–20K 与前端意愿

> 你 4 年、AI 全栈，杭州 15–20K 对你偏低吗？如果每天写 React/Next 业务、偶尔做 AI，你能接受吗？base 在杭州有问题吗？

- 期待：薪资预期真实；接受前端为主；base/到岗明确；不把 AI 当唯一卖点。
- 警惕：明显屈就；只想做 AI/Agent；对纯前端排斥。

### 4. 当前状态

> 2026.03 到现在在做什么？有在看机会、做项目、学习吗？最快什么时候到岗？

- 期待：具体、可核实；有产出（开源/项目/学习）；到岗时间明确。
- 警惕：含糊；简历时间与实际情况不符。

### 5. 最近一年写得最多的代码

> 前端、Node 还是 AI 编排？各占多少？给我一个你亲手写的 PR/模块，文件路径、多少行、解决什么问题。

- 期待：比例真实；能讲一次自己调试/上线的过程；代码边界清楚。
- 警惕：只讲架构；代码都是团队写的；AI 生成但讲不清。

## 二、甄选智能客服（15 分钟）

### 6. **必问** 端到端链路

> 从文档上传到用户拿到答案，完整链路是什么？解析、切分、Embedding、存储、召回、重排、生成、引用、人工兜底，各环节谁做？你负责哪几段？

- 期待：链路完整；知道每段的输入/输出；自己负责前端 + 部分后端/编排；能画出数据流。
- 追问：「哪一段最容易出问题？你怎么发现？」
- 警惕：只讲「LangChain/LangGraph」；说不清检索与生成边界。

### 7. 文档解析与切分

> PDF/Word/Markdown 怎么解析？MinerU 解决什么？表格、图片、扫描件、页眉页脚怎么处理？切分策略是什么？metadata 存什么？

- 期待：解析器选型；MinerU 处理复杂版面/表格/图片；OCR 兜底；按标题/段落/语义切分；chunk size/overlap；metadata（租户、文档、页码、章节、版本）；引用可回溯。
- 追问：「扫描版 PDF 没有文字层怎么办？」「一个 200 页的文档怎么切？」「表格跨页怎么保证语义完整？」
- 警惕：固定 500 字切分；没有页码/章节；引用对不上原文。

### 8. **必问** RabbitMQ 异步链路

> 上传、解析、切分、Embedding、入库为什么用消息队列？怎么保证不丢、不重、可恢复？增量更新、删除文档怎么处理？

- 期待：削峰/解耦；手动 ack；重试 + 退避；DLQ；幂等（文档版本/消息 ID）；失败补偿；增量更新按文档版本；删除时同步删向量/索引；监控积压。
- 追问：「同一条消息消费两次会怎样？」「文档更新到一半失败，旧版本还能用吗？」「删除文档后，向量库残留怎么清？」
- 警惕：没有幂等；没有 DLQ；删除只删 Mongo 不删向量。

### 9. **必问** 混合检索

> BM25 + Milvus 双路召回怎么融合？为什么不用单路？Rerank 输入是什么？topK 怎么定？多租户过滤在哪一层？

- 期待：BM25 擅长关键词/专有名词，向量擅长语义；RRF/加权融合；Rerank 对候选重排；topK 召回 vs 延迟；tenant_id 过滤在检索层；权限过滤不能只在前端。
- 追问：「用户问一个表格里的数字，BM25 和向量谁更有效？」「Rerank 延迟多少？值得吗？」「没有召回结果怎么办？」
- 警惕：只做向量；没有 metadata 过滤；跨租户召回。

### 10. **必问** 效果评测

> 你怎么证明 RAG 效果好？检索和回答分别看什么指标？测试集怎么构建？有没有幻觉/引用准确率/人工评分？数字是多少？

- 期待：检索（Recall@K、MRR、命中率）、回答（准确率、groundedness、引用准确率、拒答率）、人工评分、bad case 回流、A/B；测试集来自真实问题/工单；标注规范。
- 追问：「100→60 是业务指标，怎么证明是模型变好，而不是用户少问了？」「模型升级后怎么回归？」
- 警惕：只有业务指标；没有测试集；「感觉变好了」。

### 11. LangGraph 编排

> 检索、重排、生成、人工兜底怎么编排？状态里有什么？条件边怎么走？为什么用 LangGraph 而不是普通链？

- 期待：状态机/图、节点职责、条件路由、人工中断、检查点、错误重试；LangGraph 适合有状态/多分支/可恢复流程。
- 追问：「生成节点失败怎么重试？」「人工兜底后怎么回到自动流程？」「怎么防止死循环？」
- 警惕：只是把 Prompt 串起来；没有状态/恢复。

### 12. 意图识别与路由

> 多级意图怎么分？用规则、分类模型还是 LLM？置信度阈值多少？分错了怎么办？简单/复杂问题怎么分流？

- 期待：规则 + 模型/LLM；层级（业务域/意图/槽位）；置信度阈值；低置信转人工/澄清；混淆矩阵；bad case；多意图处理。
- 追问：「用户中途换意图怎么办？」「一句话里两个需求怎么拆？」

### 13. **必问** 多租户与 RBAC

> 租户隔离怎么做？向量库、Mongo、对象存储、Prompt 各层怎么防越权？用户问别的租户的文档，怎么保证查不到？

- 期待：tenant_id 贯穿数据模型；检索时强制过滤；RBAC 角色/资源/操作；行级权限；Prompt 不拼接越权内容；审计；加密；测试用例。
- 追问：「前端把 tenant_id 改了会怎样？」「Prompt 注入让模型忽略权限，怎么办？」
- 警惕：只在前端过滤；向量库无 tenant 字段；权限靠 Prompt。

### 14. **必问** 100%→60% 介入率

> 「人工客服介入率」的定义是什么？分子分母各是什么？统计周期多长？样本多少？改造前真的是 100% 吗？同期还做了什么？

- 期待：明确定义（转人工会话/总会话，或人工处理消息占比）；基线；样本；时间窗口；AI 自助解决/转人工；用户满意度；负向（答错但没转人工）。
- 追问：「AI 答错了但用户没找人工，介入率也会好看，怎么发现？」「60% 里有多少是 AI 主动转人工？」
- 警惕：100% 基线不可信；只报下降不报质量；把业务自然波动算成 AI 效果。

## 三、商旅 AI Agent（12 分钟）

### 15. **必问** 整体架构

> 从用户说「下周去上海出差」到完成预订，Agent 的完整流程是什么？规划、推荐、工具调用、下单各节点怎么编排？你负责哪部分？

- 期待：意图/槽位 → 行程规划 → 航班/火车/酒店/天气工具 → 方案对比 → 用户确认 → 下单 → 提醒；LangGraph 状态；前后端边界。
- 追问：「用户信息不全，Agent 怎么追问？」「方案不满足差旅规则怎么办？」
- 警惕：只讲「Agent 自动规划」；没有确认与异常处理。

### 16. 长期记忆

> 用户偏好记忆存什么？怎么提取、更新、过期？隐私和租户隔离怎么做？用户能否查看/删除？

- 期待：偏好 schema（交通/舱位/酒店/时间/预算）、来源、置信度、更新时间；抽取/合并/衰减；用户可控；PII 最小化；租户隔离。
- 追问：「用户上次住五星，这次预算低，推荐什么？」「记忆错了怎么纠正？」
- 警惕：什么都存；没有过期/删除；跨租户共享。

### 17. Tool Calling

> 航班、火车、酒店、天气工具怎么定义 schema？鉴权、超时、重试、限流、错误回传怎么做？能并行调用吗？

- 期待：JSON Schema、工具注册、参数校验、鉴权、超时、重试、错误作为 observation 回传、并行调用、结果归一化、可观测。
- 追问：「工具返回价格过期怎么办？」「一个工具挂了，整个行程还能规划吗？」
- 警惕：没有 schema 校验；工具错误直接抛给用户。

### 18. **必问** 自动下单安全

> Agent 能自动下单/支付吗？用户确认在哪一步？怎么防重复下单、价格变动、库存不足、下错日期？退款/改签怎么处理？

- 期待：人工确认；幂等键；订单状态机；库存/价格二次校验；支付回调；补偿/退款；操作审计；限额。
- 追问：「Agent 把日期理解错了，已经付款，怎么办？」「用户说『就按这个订』，还需要确认吗？」
- 警惕：无确认自动支付；无幂等；出错无补偿——红线。

### 19. 主动服务

> 天气/交通/行程风险提示怎么触发？推送频率？误报怎么办？用户能关吗？

- 期待：事件/规则触发、个性化、opt-in、免打扰、退订、效果指标；避免骚扰。
- 追问：「暴雨预警但用户已经改签，怎么避免重复提醒？」

### 20. SSE 流式

> Agent 的流式输出怎么实现？SSE 格式、心跳、断线重连、代理缓冲、取消、半截 JSON 怎么处理？

- 期待：`text/event-stream`、`data:`、`[DONE]`、心跳、`Last-Event-ID`、retry、abort、Nginx `X-Accel-Buffering: no`、增量解析、工具调用状态展示。
- 追问：「客户端断开，服务端的工具调用要取消吗？」「流式中间报错怎么展示？」

### 21. Agent 评测

> 怎么衡量 Agent 成功？任务完成率、工具调用准确率、时延、成本、用户满意度？测试集怎么建？

- 期待：任务级评测、轨迹/工具序列、成功判定、人工评审、A/B、成本；离线用例 + 线上指标。
- 追问：「同一个需求有多种正确方案，怎么判成功？」

## 四、Whale FX 平台（10 分钟）

### 22. **必问** 0→1 架构

> Whale FX 从 0 到 1 的架构是什么？为什么同时用 Next.js 和 Umi？哪些页面 SSR/SSG/CSR？状态、路由、权限怎么组织？

- 期待：门户 SSG/SEO，交易平台 CSR，按页面分类；Next.js 与 Umi 的边界（门户 vs 应用）；路由/权限/状态；组件库；构建部署。
- 追问：「为什么门户不用 Umi？」「交易页为什么不做 SSR？」
- 警惕：技术栈堆砌；说不清选型理由。

### 23. 组件库与工程化

> 组件库怎么设计 API、文档、版本、破坏性变更？npm CLI 解决什么？20 个项目怎么升级？

- 期待：AntD 二次封装、设计 token、文档/demo、semver、changelog、codemod、迁移指南、接入率；CLI 脚手架/规范。
- 追问：「一个组件 API 要 breaking change，怎么推？」「组件库和业务组件边界在哪？」

### 24. Tailwind

> 为什么用 Tailwind？和 AntD/CSS-in-JS 怎么共存？purge 怎么做？动态类名有什么坑？

- 期待：原子化、设计约束、产物体积、content 配置、动态类名 safelist、与 AntD 样式隔离；团队接受度。
- 追问：「设计稿任意值很多，Tailwind 还合适吗？」

### 25. Next.js SSG 与 SEO

> 门户为什么用 SSG？构建、增量更新、i18n、sitemap、metadata 怎么做？1 万个页面构建慢怎么办？

- 期待：`getStaticProps`/ISR、CDN、增量静态再生成、sitemap、hreflang、metadata、构建拆分；内容更新流程。
- 追问：「价格/汇率是动态的，SSG 怎么保证不展示旧数据？」

### 26. AI 生成文案/图表/配置

> 自然语言生成业务文案、图表、批量配置：prompt 怎么设计？结构化输出怎么校验？生成错了怎么防？

- 期待：JSON Schema/工具调用、校验、预览、确认、撤销、权限、限流、成本；生成失败兜底。
- 追问：「模型生成了一个非法配置，直接生效会怎样？」「怎么评测生成质量？」

### 27. **必问** NestJS 网关

> HTTP/SSE 与 gRPC 怎么转换？流式响应怎么透传？客户端断开、gRPC 超时、错误码怎么处理？鉴权在哪层？

- 期待：协议适配、流式转发、背压/取消、metadata、错误映射、超时、重试/熔断、鉴权、trace。
- 追问：「gRPC stream 背压怎么处理？」「SSE 连接断了，gRPC 调用怎么取消？」
- 警惕：只做简单转发；没有取消/错误映射。

### 28. React 升级

> 从哪个版本升到哪个？breaking changes 怎么处理？class 组件、旧依赖、测试怎么迁移？怎么保证不回归？

- 期待：React 17→18（`createRoot`、自动批处理、StrictMode、并发）或更早；codemod；测试/视觉回归；灰度；回滚；团队培训。

### 47. 代码 review

给下面这段代码，问他有什么问题：

```js
function useChat(url) {
  const [text, setText] = useState('')
  useEffect(() => {
    const es = new EventSource(url)
    es.onmessage = (e) => setText((t) => t + e.data)
    return () => es.close()
  }, [])
  return text
}
```

**期望指出**

- `url` 变化不重连；依赖数组为空。
- 没有处理 `error`/重连/`[DONE]`；EventSource 不能自定义 header/POST。
- 分片/多行 `data:` 直接拼接可能破坏 JSON/Markdown。
- 没有 loading/error/abort；组件卸载/路由切换的竞态。
- 没有鉴权；URL 带 token 泄露。
- 长文本每次 `setText` 触发整页渲染，性能差。

**观察**：能否从「正确性 → 流式协议 → 安全 → 性能」分层说。

## 九、评分与红线

### 档位（杭州，4 年经验）

| 档位 | 标准 |
|-|-|
| 13–15K | 前端基础尚可；AI 项目多为参与；RAG/Agent 讲不清闭环；手写需要提示。 |
| 15–17K | 前端能独立扛 React/Next 业务；AI 项目能讲清一条链路；指标有基本口径；手写基本完成。 |
| 18–20K | 主导过核心模块；RAG/Agent/网关至少两项能到实现与失败模式；有评测/权限/安全设计；前端深度稳；手写与排障都行。 |
| 超配/谨慎 | 若前端基本功弱、主要靠 AI 工具/团队，按 13–15K 或不适配；若 AI+前端双强，可给 18–20K，但要解释 7 个月空档与短经历。 |

### 红线

- **稳定性存疑**：甄汇 7 个月 + 当前 7 个月空档说不清；每段都怪公司。
- **项目归属不清**：两个 AI 项目同期，追问三层说不清自己写了什么。
- **指标无口径**：100%→60% 定义/样本/归因说不清；检索/回答没有评测。
- **只会调框架**：LangGraph/LangChain 讲不清状态、检索、失败处理；一追问就是「框架做的」。
- **AI 安全无意识**：自动下单无确认/幂等；多租户只在前端过滤；Prompt 注入无所谓。
- **前端基本功空**：React hooks、TS、CSS、网络、性能连续答错；手写写不出。
- **AI 生成代码不理解**：能跑但讲不清；不 review；没有测试。

### 面试官提醒

- 先问稳定性：7 个月短经历 + 7 个月空档，是这个候选人最大的非技术风险。
- AI 项目很亮，但**岗位是前端**：React/TS/CSS/性能/手写必须单独验证，不能被 RAG/Agent 带偏。
- 两个 AI 项目同期，务必区分「平台/团队」与「个人」；让他打开代码/PR 讲。
- 100→60 是业务指标，不是模型指标；追问「答错但没转人工」怎么发现。
- AntD PR 是很好的验真点：让他讲 PR 的 diff、测试、Review，讲不清就是包装。
