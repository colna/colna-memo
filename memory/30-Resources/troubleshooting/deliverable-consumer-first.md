# 先问消费方，再问格式

2026-09-08 在同一份产物（Poo 的 43 屏 UI prompt）上返工三次，**根因是我从没问过目标工具是什么**：

1. 第一版：7 份按 Tab 分，每份 ≤5000 字
2. 第二版：用户要「一页一个 prompt」→ 拆成 43 屏
3. 第三版：用户说「这个 prompt 是给 Figma Make 的」→ **前两版都是按出图工具写的**
   （满篇 `Draw…`、`flat screen only, no bezel, no hand`、`render at 3x`）

**第三次不是措辞问题，是内容缺了一半。** Figma Make 产出的是可交互 React 原型，它需要
而出图工具完全不需要的三段，前两版一段都没有：

| 段 | 缺了会怎样 |
| --- | --- |
| Interaction（点什么发生什么、什么会动、什么锁住） | 它自己编交互逻辑 |
| Data（几条、叫什么、什么状态） | 它自己造假数据或 lorem ipsum |
| TARGET / VIEWPORT（一屏 iOS 原型、不要设备边框） | 它可能给你做个落地页 |

补完后每份 3900–5300 字符，比只有 Layout 时长约 1000 —— **长出来的正是能用的那部分**。

## 教训

我问了拆分粒度、问了字数上限，**唯独没问最能决定内容形态的那一条**。粒度和字数是可以
事后调的，消费方定的是内容骨架，事后只能重写。

> **动作**：产出物有明确下游消费方（某个 AI 工具、某个脚本、某个人的既定流程）时，
> **第一个问题就是「这给谁用 / 用什么工具吃」**，排在拆分方式、字数、格式之前。
> 判据：如果换一个消费方会让内容重写而不只是重排，那它就是必须先问的那一条。
