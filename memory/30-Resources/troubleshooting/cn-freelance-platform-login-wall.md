# 中文接单平台取证：登录墙判定与证据留痕

## 症状

要判断「中文接单平台（实现网 / 程序员客栈 / 猪八戒）能不能公开取到报价与投标数」，常见的两种坏结果：

1. **把「我打不开」写成「平台不可取数」**——上一轮就因此得出一句错误结论「只有 Freelancer.com 在未登录公开面拿得到带预算的需求」，而实际实现网列表页未登录即给出 `budget_text` 60/60 + `bid_count` 60/60（依据：`shared/cash7d/requirements_shixian.tsv` 60 行）。
2. **把「登录墙的描述」当事实转述**——上游一句话里混了四条：`302`、`robots Disallow /wd/*`、「短信」、「滑块」。磁盘上只有一条有证据。

## 根因

- **「取不到」混了三种情况**：URL 真的 404 / 列表页能读但详情跳登录 / 整站要登录。三种对该不该继续投入的判断完全不同。
- **状态码与最终 URL 被混为一谈**：headless 抓取只存了「落地后的 URL」（`/user/notlogin?next=/wd/list`），没有存中间的 3xx 记录，事后却按「302」写进结论。
- **反爬声明（robots）与图形验证码从来没人真去取**：写的人凭印象，读的人当既有事实。

## 判据（可照做）

1. **先分三层，分别记**：
   - **L1 列表页可读**：DOM 正文里有没有价格 / 投标数 / 发布时间 → 有，就说明**这家平台公开面可取证**，能进样本表。
   - **L2 详情页要登录**：列表页可读、详情 302/落地到 `/user/notlogin` → 样本只能到列表字段，**详情字段一律标缺**，不许用别的平台补。
   - **L3 整站要登录**：连列表都落在 `notlogin` → 判「机器不可过」，**需要用户本人一次登录**，这不是分析问题，是 30 秒的人手动作。
2. **状态码与落地 URL 分开记**：只有拿到响应头/抓取日志的 3xx 才能写「302」；只看到落地 URL 时写「**最终落点为 X（未见 3xx 记录）**」。
3. **没存档的事实，一律写成「未验证」**：`robots.txt` 没抓过 → 不写「robots Disallow /wd/*」；注册页 DOM 正文只有 `手机号` + `验证码` 字样、没有滑块文字 → 不写「滑块」（图形验证码可能只是 canvas/图片元素，正文无痕）。
4. **登录墙也要留三件套**：PNG + 渲染后 `.txt` + `.html`。否则事后无法区分「被墙挡住」和「没抓到」。

## 本轮的具体证据账（2026-11-04，程序员客栈）

| 说法 | 证据状态 |
|---|---|
| `/wd/list` 存在登录墙，需开发者登录 | **有证据**：`manifest.tsv` 的 `p2_01`（`page_type=proginn_login_wall_for_wd_list`）+ DOM 正文「您还没有登录呢」 |
| 落地 URL 是 `/user/notlogin?next=%2Fwd%2Flist` | **有证据**（同一份 manifest 的 url 列） |
| 「302 跳转」 | **无证据**：`fetch_log.jsonl` 里没有 `/wd/list` 的状态记录，只有 200 `/`、404 `/projects`、404 `/wanted` |
| 「robots Disallow `/wd/*`」 | **无证据**：库里 `find -iname "*robot*"` 0 命中 |
| 「短信 + 滑块」 | **半有**：注册页正文含 `手机号` / `验证码`；**「滑块」无文字证据** |
| 登录后预算栏是否可见 | **从未验证**（任何一方都没有登录态样本） |

## 修法（回灌到流程）

1. **抓取器必须落 `fetch_log.jsonl` 一行一请求**：`url / status / bytes / sha256 / ts_utc / path / error`。只要 3xx 没进日志，结论里就不许出现 3xx。
2. **报告里每个「不可得」都绑定一条证据**（截图名或 DOM 行），没绑定就降级为「未验证」。
3. **`remote_ok` 这类「筛选页自带条件」要单独标注恒真**：样本取自远程筛选页时，60/60 全「是」并不构成筛选力，否则会把「三条件交集」说成「四条件交集」。

## 可迁移的两条

- **「取不到数」是一个需要举证的结论**，和「数字算错」同级；写成「未验证 / 需用户登录」比写成「平台不给」诚实得多，也不至于让后续派单整个绕开一家其实能取数的平台。
- **登录墙是产品的窗口，不是分析的黑洞**：判到 L3 就停下，把它变成「用户 30 秒动作 + 之后 10 分钟填表」，而不是反复换 UA / 试接口（那既慢又越界）。

## 补记（16:38 终态）：闲鱼为什么判「不可评估」而不是「出局」

**症状**：抓取方遇闲鱼登录墙即停，一支线交回 0 张截图。报告框架里只有「成立 / 窄门 / 出局」三档时，0 样本很容易被顺手写成「出局」——那就把一个**取证失败**写成了**市场判断**。

**根因**：
1. **零样本 ∈ 不可评估，不属于任何结论档**。判据文件（`prereg.json`）的 `falsifier` 原文已写好：「N=0 或想要数不可见 → 判不成立/**不可评估**，不得用其他平台数据替代」。框架里没这一档，人就会往「出局」上凑。
2. **合成的测试 fixture 会污染「零样本」判定**：库内唯一带 `xianyu` 的文件是 `fixtures/xianyu_测试_数据采集.png` 与 `selftest/fixtures/` 同名自造图。按文件名 grep 统计，会把合成件当成「有闲鱼样本」。
3. **「想要数」的口径含平台差异**：闲鱼是「想要数」，实现网是「投标数」，两列名字相近、含义不同，混列相加就等于跨平台比较。

**修法**：
1. 判据里**显式写第四档「不可评估」**，并要求报告附「分母 = 0」+ 停手原因（登录墙）+ 未用他源顶替的声明（本轮交付的自检项 D1b 即查这一条，实测 PASS）。
2. 统计样本前先排除 `fixtures/`、`selftest/`、`testdata/`；**文件名里的平台名不算样本证据**，样本只认 `capture/` 下真渲染的三件套。
3. 「想要数 / 投标数」按平台分列，禁止合并成单一「竞争度」列。
4. 结论里「不可评估」必须与「需用户 30 秒登录」成对出现，否则下一个人只会读到「平台不行」。
