# 前端面试题库（陈濛 · 10年 · 杭州 15-20K · 含参考答案）

> 依据简历定制：10 年（邦盛 → 网易 → 有赞 → 字节 TikTok 广告 → 同花顺 → 个人全栈 → 泉缘），主线是广告/营销前端 + 跨端 + 音视频 + AI 全栈。
> 建议 75-90 分钟：业务 20 / 技术 55 / 反问 10；**必问** 标在题前。简历原文：`~/Downloads/【前端开发工程师_杭州+15-20K】陈先生+10年.pdf`。
> 出题原则：卖点是字节 3 年（Lynx / SSR 流式 / converter）、AI Agent 全栈、Taro 小程序；风险是近三段偏短、个人项目与 AI 提效数字需核实。题目可按时间取舍，标 **必问** 的优先。

## 一、业务与动机（20 分钟）

### A. 经历与稳定性（8 分钟）

1. **必问** 按时间线过一遍：邦盛 2 年 3 个月 → 网易 8 个月 → 有赞 2 年 → 字节 3 年 → 同花顺 5 个月 → 个人全栈 1 年 2 个月 → 泉缘 6 个月。字节之后为什么去同花顺、只待 5 个月？为什么又从个人开发回到公司？泉缘 6 个月为什么离开？
   - 期待：每段有明确的「要什么 / 得到什么 / 为什么走」，能承认判断失误；短期经历有可核实原因（业务调整 / 团队解散 / 方向不符 / 家庭）。
   - 警惕：全部归因外部；对「稳定性」毫无自觉；说法与背调/社保记录冲突。
2. **必问** 2024.02–2024.06、2026.07 至今两段空档具体在做什么？有收入、项目或学习产出吗？
   - 期待：自然、具体、可核实；空档有产出（产品迭代 / 开源 / 系统学习）；不回避。
   - 警惕：含糊其辞；把空档包装成「全职做产品」但拿不出任何证据。
3. 15-20K 在杭州、以你字节 3 年 + 全栈背景，为什么接受这个区间？是过渡还是长期？如果同时拿到更高薪的 offer 怎么选？
   - 期待：真实动机（稳定 / 方向 / 家庭 / WLB / 看好业务），对职级与薪资有合理认知。
   - 警惕：明显「屈就」心态；只说来过渡；对薪资无判断。
4. 你如何定义自己当前职级（初中高 / 专家）？对标市场什么水平？
   - 期待：客观自评 + 证据（复杂项目 / 深度方向 / 带人 / 跨端）；不虚高也不过度贬低。

### B. 项目与业务结果（12 分钟）

5. stockpractice.top：为什么做？现在还在运行吗？用户量 / 付费 / 成本（服务器、模型 token）？为什么停止？技术上最难的一点？
   - 期待：真实数据（哪怕是 0）、成本意识、持续维护情况；能讲一个具体难点（Agent 工具调用 / SSE 流式 / 画线工具 / 部署）。
   - 加分：能说清「哪个功能没人用、为什么」；对产品有复盘。
   - 警惕：只讲技术栈不讲用户；数据全靠猜；项目已停但包装成「成功产品」。
6. 泉缘「建立 AI 驱动开发范式，显著提升交付效率」：具体改了哪些环节？提升多少？怎么度量？翻车案例？
   - 期待：环节具体（需求拆解 / 脚手架 / 代码生成 / CR / 测试 / 发布）、度量口径（周期 / 返工率 / 缺陷率 / 人力）、可复现流程（rules / 模板 / skill）；坦承幻觉、越权改动、返工。
   - 警惕：只会说「用 Claude Code 很快」；无度量；把工具使用当方法论。
7. TikTok 广告贴纸 / 落地页：前端改动如何影响 CTR / CVR / 加载时长？举一个你做的优化与数据结果。
   - 期待：指标口径、A/B 或灰度、性能与转化的关系、广告审核/合规约束；区分「我做的」与「团队做的」。
8. 有赞做前端 PM：带几人？怎么拆任务 / 排期 / 暴露风险？举一次延期或冲突。
   - 期待：拆解与依赖、buffer、风险升级、砍范围；冲突用数据/方案解决；有复盘。
9. 小程序组件库 / 业务组件跨团队推广：多少业务方接入？定制诉求怎么处理？破坏性升级怎么办？
   - 期待：接入成本、文档/demo、版本策略、deprecate、维护归属；「组件不是越多越好」。
   - 警惕：只讲「我建了组件库」，讲不出接入方与维护成本。
10. 10 年经验，如果团队只需要一个能独立扛业务的前端，你的差异化是什么？举两个只有你能做的证据。
    - 期待：业务理解 + 跨端 + 性能/工程化 + AI 全栈的组合；有具体产出与影响。
    - 警惕：泛泛而谈「学习能力强 / 能加班」。
11. 反问与落地：期望的工作内容、团队规模、技术栈？能否接受加班/出差/驻场？到岗时间？

## 二、字节经历深挖（15 分钟）

### C. Lynx 与跨端（5 分钟）

12. **必问** Lynx 是什么？渲染链路是怎样的？和 RN / Flutter / Hippy 的差异？字节为什么自研？
    - 期待：JS 逻辑与 UI 渲染分离、原生渲染而非 WebView、CSS 子集/布局、模板/DSL、首屏与跨端一致性；能对比 RN（JS bridge/JSI + 原生组件）、Flutter（自绘）、Hippy（复用 Web 生态）。
    - 加分：说清自己负责哪一层（业务 / 组件 / 构建 / 发布），以及一次具体的性能或兼容问题。
    - 警惕：只会说「跨端框架」；把 Lynx 说成 WebView；讲不清自己做了什么。
13. 广告贴纸样式：用 Lynx 怎么实现？动效/手势/多端适配怎么做？性能怎么保证？和客户端原生能力的边界在哪？
    - 期待：布局与动画方案、资源加载、埋点、降级、审核；首屏/滚动性能；与 native 通信与兜底。

### D. SSR 与广告落地页（5 分钟）

14. **必问** React SSR + 流式渲染：为什么用？`renderToPipeableStream` 的 Suspense/错误处理？TTFB/FCP 收益？hydration 坑？
    - 期待：流式 shell + 分块、Suspense 边界、`onShellReady/onAllReady`、错误边界、选择性 hydration、hydration mismatch（时间/随机/环境差异）、Node 超时与 CSR 降级。
    - 加分：流式与 CDN 缓存的矛盾、AB 实验、线上监控。
    - 警惕：只答「SEO 好 / 首屏快」；说不出流式与普通 SSR 的区别。
15. 广告落地页性能：LCP / INP / CLS 怎么优化？弱网 / 低端机怎么办？第三方脚本（广告/统计）怎么管？
    - 期待：资源优先级/预加载、图片格式与尺寸、字体、代码分割、SSR/边缘缓存、第三方脚本延迟/沙箱、RUM 采集与告警；弱网降级。
    - 加分：能给出真实指标与优化前后对比。
16. 性能与报错看板：采集哪些指标？怎么上报（采样 / 批量 / Beacon）？sourcemap 怎么关联？告警怎么定？
    - 期待：Web Vitals、错误分类、采样与去重、离线补偿、sourcemap 上传与隐私、阈值与告警收敛。

### E. Converter 项目（5 分钟）

17. **必问** converter：Chromium 打开页面，DFS 提取元素 → 约定化 JSON。完整设计？怎么保证结果稳定、可复现？
    - 期待：遍历策略（DOM 树 / 可见性 / 计算样式）、文本合并规则、图片/背景图/链接、相对 URL 归一化、去重、输出 schema 版本、顺序稳定、超时/重试、并发与隔离。
    - 加分：Playwright/CDP、请求拦截、快照对比、抽样人工校验、失败分类。
    - 警惕：只讲「深度优先遍历」；对脏数据/稳定性没有概念。
18. 边界场景：懒加载、无限滚动、Canvas 渲染、iframe、Shadow DOM、登录墙、反爬，分别怎么处理？
    - 期待：滚动触发 + 等待稳定、iframe 递归/跨域限制、shadow root 遍历、Canvas 截图/OCR 兜底、cookie/UA/限速；Shopify/Amazon 特化的维护成本。
    - 加分：能讲「哪些场景直接放弃，为什么」。
19. 抓取耗时看板：怎么定位瓶颈？优化前后量级？并发模型？
    - 期待：分段计时（导航/等待/遍历/序列化/上传）、P50/P95、并发池、浏览器复用、请求拦截、缓存；用数据说话。

## 三、React 与前端原理（10 分钟）

20. **必问** React 渲染机制：render 与 commit 阶段？Fiber 解决什么？Concurrent 下一次更新的完整链路？
    - 期待：双缓存树、可中断 render、优先级/lanes、commit 不可中断、effect 时机；并发 = 时间切片 + 优先级调度。
    - 警惕：只会背「虚拟 DOM 很快」；把 Fiber 与 diff 混为一谈。
21. React 18 自动批处理的边界？流式高频更新为什么卡？怎么解？
    - 期待：事件/异步中的 batching、`flushSync` 例外；高频 setState 导致重复 render；方案：外部 store + `useSyncExternalStore`、rAF/节流、transition、memo/拆分、虚拟化。
    - 加分：能说清「状态更新频率」与「渲染成本」分别怎么降。
22. `useMemo/useCallback/memo` 什么时候真正有用？过度使用的代价？
23. 受控/非受控、合成事件、事件委托？React 17 事件挂载变化？
24. 错误边界能捕获什么、不能捕获什么？SSR/流式下怎么处理？
25. hydration mismatch 的常见原因与排查？
26. Vue 与 React 响应式差异？如果团队是 Vue 项目，你如何接手/迁移/共存？
    - 期待：依赖追踪 vs 不可变 + 调度；不轻易重写；路由级/组件级共存；风险与回滚。
    - 警惕：把 Vue 说成「只会用 API」；对迁移成本无概念。

## 四、AI Agent 与流式（12 分钟）

27. **必问** 你的 Agent 循环怎么实现？Function Calling 的消息协议、工具 schema、终止条件、错误回传？
    - 期待：system/user/assistant/tool 消息、`tool_calls`、并行调用、max steps、工具错误作为 observation 回传、超时/重试、幂等、trace。
    - 警惕：只会说「调 OpenAI 接口」；讲不清一轮工具调用怎么闭环。
28. 流式工具调用：arguments 是分片 JSON，怎么拼？半截 JSON 怎么处理？前端怎么展示？
    - 期待：按 index 累积 delta、完成后 parse、失败兜底；前端展示「正在调用工具」而非解析半截参数。
29. **必问** HITL 中断/恢复：用户暂停修改后，如何保证上下文、已生成内容、工具状态一致？协议怎么设计？
    - 期待：事件类型（token / tool_call / tool_result / interrupt / resume / done / error）、seq/消息 ID、服务端快照、幂等恢复、前端状态机、取消信号；不能只靠前端 abort。
    - 加分：能画出「暂停—编辑—恢复」的时序图，并说清哪些状态必须服务端持有。
30. SSE：`EventSource` vs `fetch` 流？重连 / `Last-Event-ID` / 心跳 / 代理缓冲 / 背压？
    - 期待：自定义 header 与 POST 需 fetch；自动重连局限；`retry`/id；Nginx `X-Accel-Buffering: no`、超时；abort；服务端事件缓冲。
31. 流式 Markdown：chunk 边界怎么处理？代码高亮/滚动跟随/5 万字长文怎么不卡？
    - 期待：增量解析、未闭合语法缓冲、rAF/节流、按块 memo、虚拟化/折叠、高亮降级/Worker、仅接近底部才跟随。
32. 上下文管理：超长对话怎么压缩？token 预算谁控？工具结果太大怎么办？
    - 期待：滑动窗口 + 摘要、system 固定、检索、工具结果截断/摘要、token 计数、后端控预算；前端展示用量。
33. 评测：Trajectory 评测怎么做的？指标？怎么防回归？
    - 期待：用例集、工具调用序列/参数正确性、最终答案、人工标注、A/B、回归门禁；不能只看「感觉」。
34. 安全：prompt 注入、工具越权、用户数据、模型输出 XSS？前端/后端各做什么？
    - 期待：工具白名单/权限校验走用户身份、输入过滤、输出转义/沙箱、脱敏、审计；前端不能兜底权限。
35. 为什么选 DeepSeek？OpenAI 兼容层？多模型切换/降级？成本？
36. Chart.js 二次开发：画线工具的坐标转换、命中测试、拖拽、缩放、持久化？1000 根 K 线怎么不卡？
    - 期待：`getPixelForValue`/反向转换、DPR、独立 overlay canvas、命中阈值、事件坐标、节流、降采样；插件生命周期/销毁。
    - 警惕：只会调 Chart.js API；讲不清 canvas 重绘与交互。
37. 全栈部署：Docker Compose + Nginx + JWT + Celery/Redis 的职责？JWT 存哪？刷新/注销？SSE 在 Nginx 下怎么配？
    - 期待：access/refresh、httpOnly cookie vs localStorage 的 XSS/CSRF 权衡、短过期/黑名单、SSE buffering、异步任务、健康检查、日志。

## 五、小程序与跨端（8 分钟）

38. **必问** Taro 编译/运行时原理？和原生小程序、uni-app 的差异？踩过最大的坑？

39. 开门寻宝：回收/商城/社区/会员的核心流程？小程序性能怎么优化？

40. 后台管理 React+TS：权限 / 表单 / 数据看板怎么设计？和 C 端如何共享类型？
    - 期待：RBAC、路由/按钮权限、schema 表单、图表、OpenAPI/生成类型、包共享。
41. 跨端一致性：同一套代码如何保证微信 / iOS / Android / H5 表现一致？怎么测试？
    - 期待：差异清单、降级、真机测试、视觉回归、埋点对比。

## 八、评分与红线

**业务面**

- 通过：短期经历能给出自洽且可核实的解释；15-20K 动机真实；solo 项目有真实数据与复盘；AI 效率有口径。
- 不通过：每段都怪公司；对稳定性无自觉；项目数据全靠猜；把「用过工具」说成「建立范式」。

**技术面**

- 15-18K：React/Vue 至少一个能讲到原理；字节经历能落到实现细节；SSE/Agent 能讲清基本闭环；小程序或 WebRTC 有一个能深挖。
- 18-20K：在上述基础上，能设计协议/状态机；有性能或工程化的可复用产出；能独立扛一个业务方向。
- 加分：Lynx / SSR / converter 三者中至少一个能给出量级、坑与取舍；AI 项目有评测与安全设计。

**红线**

- 简历包装：把「参与」写成「负责」，追问三层就露馅。
- 数字无口径：性能提升、AI 提效、业务增长都说不出来源。
- 只会用库：React 原理、Canvas、SSR、WebRTC 任一方向只停留在 API 层。
- 对短期经历与空窗回避、前后矛盾。
- AI 安全无意识：工具越权、prompt 注入、数据外发都觉得「不是前端的事」。
