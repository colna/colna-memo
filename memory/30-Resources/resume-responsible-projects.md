  - **聊天与消息**：针对套壳 WebView 的性能与兼容瓶颈，主导聊天主链路与多模态消息优化，女方端崩溃率【填:↓X%】、消息渲染延迟【填:↓Y%】。
  - **音视频通话与计费**：为解决 web / native 双通话栈规则不一致，主导通话模块解耦重构，统一两端体验与业务规则（规则单点维护）；落地按分钟计费与通话违规检测扣款，通话计费准确率【填:X%】、通话相关缺陷【填:↓Y%】。
  - **实名探真**：为满足实名合规，搭建自拍 / 语音实名验证流程（录制 → 送审 → 通过 / 失败），实现 UI 与后端审核解耦、可复用；探真通过率【填:X%】。

### 二、SP · Social-Proxy 社媒代理自动化
- **情境 / 任务（S / T）**：人工社媒运营无法规模化，需把加好友、回关、私信、主页同步等获客动作自动化，并覆盖 IG / Snapchat 双平台与多设备矩阵。
- **行动 / 结果（A / R）**：
  - **获客动作自动化（浏览器端核心）**：针对多平台页面结构与多语言差异，设计注入式浏览器自动化框架，驱动真实 DOM 完成关注 / 私信 / 拉消息 / 切换专业账号等动作，支持断点续跑；自动化成功率【填:X%】、单账号日均动作【填:N】。
  - **自动化决策管线（后端）**：为解耦决策与执行，设计 Signal（事实）→ Todo（决策）→ Behavior（执行）三层管线，打通「交换 → 回关 → 静音 → 开场私信」动作链与私信自动回复；人工替代率【填:X%】。
  - **多平台接入与设备矩阵**：主导 Instagram 和 Snapchat 接入，建设设备连接管理与实时在线（NestJS + WebSocket + Redis），Android 容器支持单账号多平台多开挂机；覆盖账号【填:N】、获客转化【填:↑X%】。

### 三、Minerva · 运营后台（技术重构方向）
- **情境 / 任务（S / T）**：运营后台承担设备管理、脚本监控与实时 / 历史看板；重构前存在构建慢（单次约 6 分钟）、类型错误静默上线、统计口径失真等问题。
- **行动 / 结果（A / R）**：
  - **构建与交付链路**：针对 CI 构建慢与双重构建，修复 turbo 缓存并收窄构建范围，以 `pnpm deploy` 精简镜像替代整库 node_modules —— 镜像导出 110s→13s（约 8×）、依赖拷贝 52s→1.4s（约 37×）、单次构建整体提速约 40%。
  - **类型安全治理**：针对类型错误被 `tsc || true` 吞掉带病上线，移除静默兜底并消除生成物类型歧义 —— 类型错误在 CI 暴露并当场清零，杜绝静默上线。
  - **前端架构收敛与瘦身**：针对旧页冗余与重复实现，下线策略引擎旧页及配套 API（净删约 3400 行），将 Actions 页 V2→V3 重构并合并进统一「Action 控制台」，API wrapper 与信号类型枚举收敛为单一实现。
  - **数据统计层重构**：针对多设备并发重复计时与跨服务数据源不一致，重做在线统计口径（gaps-and-islands 区间并集去重、明细防扇出、分时段日均口径、导出截断显式化）；根修线上「当前在线恒 0」，实时源与 Action 控制台同源。
  - **BFF 流式架构**：针对大体量导出内存峰值，将 minerva-server 作为 BFF 流式透传 social-proxy（不缓冲），配合前端流式写盘，导出全程浏览器内存恒定；数据边界归位（导出落在数据所在服务）。
