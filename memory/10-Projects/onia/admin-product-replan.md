# Onia 后台全面重规划产品文档

> 版本：评审稿 v1；日期：2026-11-20（北京时间 / Asia/Shanghai）。
> 交付：完整产品规划与验收口径；不开发、不变更任务、不修改技术架构、不写飞书。
> 定位：**社媒代理 + 可控的账号日常运营**。用户所说的「养号」在本文指有授权、可审核、有节奏、能暂停的日常运营，不是刷量、规避平台检测、保证增粉或免封。

## 1. 结论：需要重规划，但不是推翻管线重做

当前后台的主要问题不是动作数量不够，而是**工程对象成为用户入口，同一运营目标被分散到多个页面**。用户要表达的是「哪个账号、对谁、做什么、何时做、是否重复」，目前却需要理解发令、Signal 定义、发送 Signal、追踪、Todo、Behavior 与设备的关系。按最新知识库，这种对象和入口分裂有事实依据；但本轮未完成登录后逐页操作，不能把具体交互难用或某个按钮失效写成实测结论。

建议以一个产品主线收敛：

**账号 → 创建任务（单动作 / 串行工作流）→ 选择立即 / 定时 / 周期 → 预览与授权 → 按账号运行 → 查结果与内容数据。**

- 单动作不是另一套系统，而是只有一个步骤的任务。
- 工作流模板负责「做什么」，计划负责「何时、由哪些账号做」，运行负责「本次实际发生了什么」。
- 所有入口最终共用预检、审批、调度、账号/设备互斥、失败处理、监控与审计。
- 保留社媒代理的「收到事件 → 草稿 → 审核/策略发送」，但放在代理收件箱，不要求用户伪造 Signal。
- 最终目标包含关注、发消息、评论、点赞、发帖、发 Story、可复制、多账号、全部调度方式、内容数据和账号状态。分期只是交付顺序，不删减目标。
- 不改既有 `Signal → Policy → Todo → Scheduler → Behavior` 分层；工程对象退到高级诊断，不再占普通用户主导航。

## 4. 产品定位、用户与范围

### 4.1 卖什么

Onia 帮用户把自己有权运营的 Instagram 账号，变成**可计划、可编排、可审核、可观测**的运营对象：主动安排互动与内容发布；被动接收消息后让 Agent 生成草稿；管理日常节奏与账号恢复；用执行事实和可合法取得的数据复盘。

目标用户假设：个人账号运营者；经营多个品牌/业务账号的小团队；需要审核与留痕的社媒代理运营者。首期沿用现有用户归属，不因「代理」自动允许跨客户账号静默操作。团队席位、客户空间属于后续独立权限产品。

### 4.2 目标与非目标

目标：一次创建单动作；可复用串行链；六种主动动作均能选择三类时间；一次选择多个有权限账号；随时定位每个账号的每一步；复制不误发；看到账号真实状态；内容发布结果和内容指标可以关联。

非目标：批量陌生私信获客、协同灌赞/刷评论、虚假人设互动网络；绕过验证/封禁、代理 IP/指纹反检测；承诺增长或平台合规背书；全量抓取平台数据；现在扩展第二社媒平台；本轮重新设计套餐或支付。账号日常运营不是「执行越多健康分越高」。

成功先用可重复验收定义，不编用量/收入目标：六动作的可用性表达真实；任务按时或有明确跳过原因；多账号不串号；外部结果未知不重复发送；每条指标可追溯来源。

## 5. 统一对象：让产品语言稳定

| 对象 | 用户含义 | 关键规则 |
|---|---|---|
| 动作定义 | 关注/发消息等可用能力与参数规范 | 共享动作目录；中文名 + 已登记 snake_case；不是新接口名称 |
| 单动作任务 | 只有一步的运营任务 | 与工作流共用创建、调度、审批、运行与复制 |
| 工作流模板及版本 | 有序步骤和参数占位的可复用方案 | 发布版本不可变；修改生成新版本；不保存密码、会话或授权凭证 |
| 计划 | 模板/步骤快照 + 账号 + 时间规则 + 授权范围 | 一次性或周期；启停独立；编辑影响未来，不改历史 |
| 多账号批次 | 一次触发选定账号集合的父记录 | 固化账号目标与内容版本；展示逐账号预检/审批/结果 |
| 每账号运行实例 | 某计划某次触发在某账号上的执行 | 独立结果、重试判断与取消；不是所有账号一个笼统成功 |
| 步骤实例 | 该账号运行中的一次动作/等待 | 输入、引用解析、审批、执行与凭证可追溯 |
| 审批记录 | 谁批准什么内容/目标/时间与范围 | 有效期和配置哈希；重大变化失效，不等于无限发送许可 |
| 执行日志 | 用户时间线与底层追踪关联 | 脱敏；包含等待/风险/取消及外部结果未知 |
| 内容对象与数据快照 | 素材、发布版本、平台结果和指标 | 内容版本与发布实例分开；不把平台未确认当已发布 |

这些是产品对象，不强制数据库新增同名表或协议改名。内部 Signal 是事实、Todo 是决策、Behavior 是执行尝试；一个产品运行可关联多个内部对象。不得绕开 Policy / Scheduler 直派执行。自动代理和主动任务共享执行治理，但保留事件锚点和 `send_reply` 语义；不把自动回复伪装成用户主动 `send_message`。

## 6. 信息架构与页面要求

主导航收敛为七项：**总览、账号、任务与计划、工作流模板、内容、代理收件箱、数据中心**；设置置底。日历是任务列表切换视图，不再独立一级菜单；素材库/发布排程是内容次级页，排程仍指向同一个计划。

| 页面 | 首屏要回答的问题 | 核心操作与显示 |
|---|---|---|
| 总览 | 今天需要我处理什么 | 待审、账号异常、待核对、今日计划、失败；一键停机；创建任务 |
| 账号 | 哪些账号可做哪些事 | 账号组/标签、六维状态、能力矩阵、当前任务、恢复入口；设备是次级页 |
| 任务与计划 | 要做什么、何时做、正在如何 | 全部/草稿/待审/已计划/运行/异常；列表和日历；计划与运行分栏；复制/暂停/取消 |
| 工作流模板 | 哪些日常工作可复用 | 单链编辑、参数表、版本、引用校验、示例运行；默认列表编辑，复杂时可切画布 |
| 内容 | 素材是什么、哪些发出、哪些待发 | 素材、帖子/Story 草稿、发布台账、排程；按账号预览；跳转内容效果 |
| 代理收件箱 | 谁发来消息、AI 写了什么、谁来发 | 会话、草稿、待审、人工接管、代理规则；联系人资料收进次级页 |
| 数据中心 | 内容表现和执行是否正常 | 内容/账号/执行三个视图；范围、账号、来源、数据时效、导出 |
| 设置 | 权限、套餐、审计和诊断 | 用户归属、通知、套餐；高级诊断/OTA 仅有权角色可见 |

跨页统一：当前账号/账号组范围常驻；跨账号时明确数量与账号清单；状态有文字不只颜色；创建表单支持保存草稿和键盘调序；错误保留已填参数。站内登录不等于 Instagram 登录，官网仍只介绍/下载，不成为另一个发任务入口。

## 7. 创建任务：一个向导，多个快捷入口

流程固定为：**选账号 → 选单动作或模板/编排 → 配参数/内容 → 设时间 → 预检与预览 → 审批/确认 → 保存计划或运行。** 账号详情、内容发布、模板「使用」按钮只是预填该向导，不能拥有各自的提交语义。

1. 账号选择先限定用户归属，再显示按动作可用性；不可用账号可留在草稿，但不能偷偷排入可运行批次。
2. 单动作只展示一张参数卡；「继续添加动作」立即变为同一份串行流程，不强制跳另一个编辑器。
3. 模板参数区分公共值和逐账号覆盖；预览展示最终解析值，不让用户审一个变量名却发出另一个内容。
4. 时间面板三选一；周期计划必须有结束条件、授权有效期与可检查的后续触发预览。
5. 预检把账号/会话、设备/能力、素材、目标、计划冲突、审批和套餐分别列出；不以一次总检查掩盖部分失败。
6. 多账号默认所有阻塞项处理完再提交；也可显式选择「仅提交通过的账号」，再次确认清单，被排除账号记录原因。
7. 确认后直接打开批次/运行详情，不只给一个 Signal ID。保存草稿不执行，模板保存不执行。

## 8. 六种主动动作的产品契约

本节字段是产品表单要求，不声明均为现有 API 字段；落地时从既有契约生成并核对。已登记动作名来自 S6，不新造接口。六动作始终可被规划为立即/定时/周期；**能选择时间不代表未完成的执行适配器可被启用**，执行前仍受成熟度与权限门禁。

| 动作与对象 | 必填/可选参数和预览 | 前置条件 | 成功凭证 / 明确失败或未知 |
|---|---|---|---|
| 关注 `follow_user`；目标账号 | 目标用户名（既有 `target_handle`）；预览我方/目标身份和授权理由 | 我方身份匹配、目标可访问、设备有关注能力；不提供任意账号池轮流关注 | 真实关系变化或平台已接受关注请求；「已关注」「请求待批准」单独标记，不当新关注；账号不可访问/受限为失败；无确认则待核对 |
| 发消息 `send_message`；明确收件人/会话 | 目标用户名或已知会话（既有 `thread_id`）、文本列表（既有 `texts`）；逐条顺序与收件人完整预览 | 有权联系且满足平台限制；会话与身份可确认；文本能力可用 | 平台真实消息 ID/会话及时间或等价正向证据；禁止生成假 ID；请求可能已发但断线为待核对，不换路径重发 |
| 评论 `comment_post`；明确帖子 | 目标帖链接/媒体引用、评论正文；展示目标缩略信息与最终正文 | 帖子可评论、账号身份与能力正确、内容审核通过 | 真实评论 ID/可定位结果；评论关闭/删除/平台拒绝为失败；只有点击记录不足以判成功 |
| 点赞 `like_post`；明确帖子 | 目标帖链接/媒体引用；显示账号与帖目标 | 目标可见、能力支持；语义是「确保已点赞」不是切换开关 | 确认已点赞；原已赞记幂等未变更，不能又点一次取消；响应不明为待核对 |
| 发帖 `create_post`；自己的内容 | 媒体、顺序、正文；按支持类型校验；逐账号覆盖与最终预览 | 合法素材、可访问的自有素材地址、可用上传能力；该格式已端到端验收 | 平台媒体 ID、可用时的链接、发布时间；素材已上传不等于已发布；转码中继续等待；无确认不报成功 |
| 发 Story `create_story`；自己的内容 | 图片/视频、顺序/文案（仅已支持项）；竖版预览并提示可能裁剪；不支持的贴纸等不能静默忽略 | 与发帖同样校验；账号/格式/客户端版本通过验收 | 每条 Story 的真实媒体 ID与发布时刻；有链接才显示；多条部分成功保留逐条结果，不重发成功条 |

统一：目标发布产物若来自前一步，必须是相同账号下已验证的对象引用。生成文案/媒体调整在审批前完成；审批后修改正文、媒体、收件人、账号或时间范围必须重新审核。隐私/风险提示不是用一次总勾选替代授权。

### 8.1 现有成熟度与上线门禁

| 能力 | 本次证据判断 | 本轮规划要求 |
|---|---|---|
| 关注 | 已登记且既有回关/动作统计有成功口径 [S3、S4、S6]；任意目标与各设备路径未在本轮复测 | 复用能力但逐账号预检；补真实关系状态验收，不能以回关统计证明所有场景可用 |
| 发消息 | 主动发送已接入；Mock 自动回复有真机对端确认 [S3、S4]；两者不是同一动作 | 单独验收主动发送、无会话、结果未知；`send_greet` 留作明确的历史/高级动作，不与 `send_reply` 合并 |
| 点赞/评论 | 动作登记与方案明确 [S5、S6]；本轮未取得最新逐项真实执行凭证 | 标「待复验」，不写成生产全量可用；未通过门禁不能执行 |
| 发帖 | 已有表单/编排/计划；未见 live 上传打通证据 [S2–S4] | 保留目标能力和草稿；打通真实上传、媒体结果与失败恢复后才开放可执行 |

| 内容数据 `get_media_insights` | 有动作名/cap 登记 [S6]，缺少可售卖全量看板证据 | 登记不等于数据覆盖；先做台账与已证实字段，官方增强另有资格门禁 |

动作目录应显示「已验证 / 待验证 / 未就绪 / 不支持」，并记录验证适用的版本、平台、账号类型和媒体类型。设备自报 cap 只是候选，不等于真实发布验收通过；Mock 成功永不升级 live 能力。

## 9. 工作流：同账号串行，跨账号受控并行

### 9.1 执行语义

- 一个账号运行内严格按序；上一步确认成功（含定义允许的幂等未变更）才能开始下一步。默认失败停后续，不允许跳过失败步假装完成。
- 不同账号可以并行推进，但共享物理设备/单 WebView 会话时互斥；同账号的手动、周期、代理发送共用执行锁和容量约束。选多个账号不保证同刻执行，也不承诺一台设备同时保持多个登录态。
- 调度时再次核对当前绑定账号与快照；发生切号则等待重新确认，不能将 A 的任务发给 B。具体多账号容器能力留架构确认。
- 模板编辑与历史运行隔离；计划固定模板版本和内容版本。发布新版本不会自动影响已批准的计划，提供差异后由用户显式升级并重审。
- 示例：测试账号发布已批准帖子 → 获取真实发布结果 → 记录到台账。后续步骤可引用前一步媒体结果；不能拿 A 账号发布结果套给 B。不存在结果就阻断，不以空字符串或演示 ID 继续。

### 9.2 引用与时间条件

引用是类型化的产品能力：例如「本账号步骤 1 的媒体结果」供后续采集数据，创建时检查步骤在前、类型匹配、账号范围和输出是否保证存在。不是让运营手填任意 JSON 路径，更不是立即修改既有协议；旧方案尚未支持步骤变量，本次列为 P1。

「计划触发时间」决定整次运行何时产生；「等待 15 分钟」或「等到指定时间」只限制下一步何时可开始（15 分钟仅为示例参数，不是承诺/建议频率）。等待不长期占设备锁，但保留流程顺序，恢复前重检账号和授权。晚于计划截止/内容有效期就过期停止。活跃时段外不得执行，即使等候已结束。

MVP 只做动作单链和整计划时间；P1 做显式等待/时间条件与前序引用；P2 才评估条件分支、有限循环及并行节点。周期计划不是流程内循环；不做任意脚本、无限循环或随机延迟「模拟真人」。

## 10. 调度、审批与不可逆操作

### 10.1 所有动作共用的时间规则

| 维度 | 产品规则（新默认建议，历史差异见 §18） |
|---|---|
| 立即 | 授权/审批通过后进入调度，不等于立刻在设备执行；排队原因可见 |
| 一次性定时 | 指定绝对日期时间、计划时区；展示用户当地与计划时区，不允许含混的「明天」持久化 |
| 周期 | 支持按天/周及指定时间、固定间隔两类明确模式；给下一批触发预览、起止范围、授权到期；不向普通用户直接暴露 cron |
| 时区 | 保存 IANA 时区（默认 Asia/Shanghai），可按账号覆盖；夏令时不存在的本地时刻跳过，重复时刻只运行一次并记偏移；更改时区重审未来触发 |
| 开始/截止/活跃时段 | 三者都要解释；任务/内容/授权截止取最早者；未配置活跃时段表示没有额外时段约束，不暗示平台允许随时执行 |
| 错过执行 | 默认跳过错过的触发，不在重启/上线时集中补发；记录 skipped 及原因；手动补做必须新建本次确认 |
| 重叠 | 同账号同计划上轮未终态时，本轮记「重叠跳过」；不堆多个周期副本；不同计划仍共用账号/设备互斥 |
| 离线 | 新产生的运行在明确、有限的等待截止前排队；无截止不允许启用；到期过期，不永久等待；这与历史无限冲突等待不同 |
| 周期内容 | 每轮是独立运行；指定「重复同一内容」必须明确确认，默认不反复发布同一帖子/Story/私信；内容池默认已用不复用、用尽暂停待补 |
| 套餐/权限变化 | 执行前再次检查；到期或能力被撤销则阻断/暂停，不能因已排程绕过限制；不静默降级成另一通道 |

默认不给离线等待、日限额或活跃时段编一个「平台安全值」。启用时必须有用户看得见的有限等待/授权截止配置；推荐值须经真实场景验证后另定，本文不伪造平台标准。频控仅代表 Onia 自身记录，不代表账号在其他端的全部行为。

### 10.2 审批与授权

单次确认至少绑定：操作者、所属账号、目标/目标范围、动作、最终文案/素材版本、执行时窗、可重复次数/周期与结束条件。周期可复用的是这些明确边界内的审批，不是无限发送权。目标或内容超出范围、版本变化、授权到期、风险提示出现，均转待审或暂停；新的收件人和内容不能靠旧批准覆盖。

默认人工审核对外动作；低风险已授权日常计划可以显式批准范围后运行，先提供 review，不把现有账号默认改为 auto。自动代理继续保留 review/auto/suggest、会话人工接管和入站锚点；新消息可能使旧草稿失效，不和定时发消息共用一个无限授权开关。平台允许的会话窗口与权限也必须在实际执行时重检。

### 10.3 幂等、重试、暂停、取消

- 产品幂等身份必须覆盖计划、原定触发时刻、目标账号、步骤和内容/目标版本；同一调度重复扫描不重复建运行，重复结果回写不重复记功。具体键格式交架构设计。
- 只对确定未产生外部副作用且允许恢复的失败重试；不要对关注、私信、评论、发布做通用「失败重试全部」。系统重连恢复既有执行，不应当作新任务发出。
- 请求可能已送达但结果丢失，进入**待核对**：保留原请求/时间/凭证、阻断后续写动作、提供人工核对平台结果。没有已成功证据不等于未发出；不要自动改用另一路径发送。
- 暂停计划只阻止未来触发，不默认取消已经启动的运行；页面明确列出仍在进行的账号。暂停运行停止下一步派发；正在执行的外部请求无法保证撤回。
- 取消运行阻止未执行步骤。已发帖子/消息不会自动删除，已关注不会自动取关。对正在执行的步骤显示「取消已请求，等待结果」；之后如收到真实成功仍记成功，同时记取消时点，不能伪造已撤销。
- 全局停机阻止所有新派发，自动代理也在内；正在飞行的请求仍可能完成。恢复必须显式选择计划，错过运行不补洪峰。

## 11. 多账号、批次与复制

批次创建时固化账号快照、归属、模板版本、公共参数及逐账号覆盖；有标签也只解析当时账号集合，后来加入标签的账号不自动继承外发授权。未来若做动态账号组需独立授权机制。

每个账号可覆盖：目标、正文/语言、媒体、时间/时区；预览支持逐账号展开。缺素材、无权目标、不支持格式的账号不能借用另一账号的参数静默通过。账户组用于管理授权账号，不提供陌生对象名单批量轰炸器。

批次详情显示：总数、待审、等待、执行中、成功、失败、待核对、过期/取消/跳过数量；可下钻每账号及步骤。一个账号失败默认不阻断其他账号，风险可能跨账号影响共享设备时暂停该设备相关队列，并解释影响范围。提供「停止剩余账号」但不默认回滚已成功账号。

复制规则统一适用于任务、运行配置、模板和计划：

1. 只复制配置、内容引用及可见参数；从运行复制保留「来源运行」但不复制它的成功结果、步骤输出或执行状态。
2. 新建对象必为**草稿/停用**，不触发任何请求；旧的一次性时间不原样启用，提醒重新选时间；周期也要重新启用确认。
3. 账号可预选但必须重验归属、能力、绑定、目标和审批；不得复制 OAuth/token/session、授权凭证或他人的数据。原审批不沿用。
4. 从工作流中复制含结果引用的步骤时保持引用关系并重校验，不能把历史媒体 ID 当本次新产物；引用的素材已删除/无权则提示修复。
5. 「重试失败步骤」不是「复制整任务」：前者沿原运行语义、先判断副作用；后者是新执行，必须提醒可能重复外发。

## 12. 账号状态：维度分开，不造健康分

账号列表用一个「需要处理」聚合提示辅助排序，但必须可展开真实来源，不给没有依据的健康分/安全等级。**未知 ≠ 正常；在线 ≠ 已登录；已登录 ≠ 能发帖；设备离线 ≠ 账号被封。**

| 维度 | 状态示例（产品建议，非现有协议枚举） | 证据与处理 |
|---|---|---|
| 平台可见状态 | 正常可访问、受限/挑战、已停用、未知 | 只展示平台明确反馈和观察时间；验证/挑战由用户完成，禁止自动绕过 |
| 登录会话 | 有效、失效、待确认、未知 | 设备本机最近验证；不能仅心跳当登录成功；提供到原设备恢复登录指引 |
| 设备连接/执行能力 | 在线/离线、忙碌、能力缺失、脚本版本待更新 | 分开连接与执行锁；显示哪些动作可用、阻塞原因及影响中的运行 |
| 官方授权 | 未接入/不可用、缺权限、过期、已撤销、授权有效 | 当前 main 不提供该通道；没有就标未接入，不填绿色；未来只显示非敏感权限/到期 |
| 同步时效 | 已同步、陈旧、同步中、失败、从未同步 | 来源、最近成功时间与失败时间分开；展示账号资料/消息/内容分别的水位 |
| 任务健康/风险事件 | 待审、积压、结果未知、失败/平台风险 | 仅基于本系统事件；显示数量、时间和处理入口，不反推平台完整风控画像 |

账号详情应包含：头像/handle 与稳定账号标识、所属人、绑定设备、能力矩阵、回复模式、最近同步、最近运行、风险时间线与恢复操作。handle 变化不能新建一个不相干账号；解绑不删除历史，但立即停用绑定计划并请求确认。普通用户不能从列表、导出、图表或 URL 猜出别人的账号信息。

账号 × 动作能力表至少列出六动作、数据读取和代理能力，并给出设备/官方路径、验证范围、所需权限、阻塞原因。多设备对同一账号的选择与故障切换不可静默发生；切换执行设备需重新核对会话身份与授权。

## 13. 数据中心与内容台账

### 13.1 四层数据，不混为一张「增长成绩单」

| 层 | 必备内容 | 边界 |
|---|---|---|
| 发布台账（MVP） | 我方账号、帖子/Story 类型、内容版本、计划/运行/步骤、平台媒体 ID、可用时链接、发布时间、来源和确认状态 | Onia 生成的草稿、已排程、已下发、已发布分别计数；手工导入内容标「外部导入」，不冒充 Onia 发出 |
| 内容效果 | 按单帖/Story 展示实际取得的观看/播放、触达、点赞、评论、分享、收藏、回复等支持子集与趋势 | 这是目标字段族，不承诺每个媒体、账号类型和接口都有；每项独立能力判断，不支持就不出数字 |
| 账号趋势 | 已同步的粉丝/关注/内容数、可用的账号级指标；标采样来源与时刻 | 历史快照差值只在同口径相邻快照可比时显示；不是 Onia 带来增粉的归因证明 |
| 执行效果 | 运行/步骤成功、失败、等待、待核对、跳过、审批、设备阻塞、按动作耗时分布 | 复用现有统计但标分母/去重；动作数不是消息条数，也不是实际曝光 |

每条指标存/展示：账号、媒体标识、指标名/定义版本、值或不可用原因、时间范围、来源、采样时间/最近成功时间、权限/支持状态。0 只有在真实返回零时才是零；未授权、不支持、过期、尚未采集、采集失败和未知必须区分。若采样失败可保留上次值，但显著标「截至某时」，不能让旧数看起来实时。

### 13.2 当前可做与官方增强的界线

当前 main 为设备脚本方案，**不能宣称已具备官方 Insights 看板**。既有 `get_media_insights` 登记不证明其所有指标/账号类型可用。首期先交付发布台账、运行数据与已有可靠快照，内容效果按实际验证字段逐项开放；无合法来源的指标明确不可用，而不是绕路补抓。

官方 Insights 是候选增强：memo 的审核指南以 Instagram 专业号（商业号/创作者号）、相应授权/审核为前提，并将 `instagram_business_manage_insights` 列为可选权限；它不是当前 main 的承诺。若未来启用，须先确认具体 Login 路径、API 版本、账号/媒体资格、权限范围、审核、授权到期和历史覆盖，再形成字段支持表并获批。本文未另行实证 Meta 当前全部字段，不固定权限名为最终接口契约，不假定个人号可用全部 Insights。

禁止为了补全图表复制登录 cookie/session，或由服务端调用私有 GraphQL、Direct、CDN；也不设计设备私有面批量抓取作为 Insights 替代。自有素材地址与平台私有媒体地址分开，不因数据中心需要而突破现有硬约束。不能静默恢复官方分支或共用冲突数据库迁移。

### 13.3 看板页面与数据口径

- 内容列表：账号、类型、缩略图、发布时间、发布确认、可用指标、采样时间；点击详情看发布/采集时间线和数据缺口；支持同类型同口径排序。
- Story 单独展示有效期和可见状态；过期/删除/未知分开。保留已合法采集的历史快照不等于 Story 仍在线，也不保证过期后能继续补采。
- 账号页小型摘要跳数据中心；任务页侧重执行，发布成功后链接内容效果。总览只放需要处理和少量摘要，不同时堆所有图。
- 触达等非可加总指标不能直接跨帖相加声称去重人数；没有分母不算互动率；如有比率，显示确切分子/分母与支持范围。
- 自然发生的数据与 Onia 发出的内容/互动分开。可展示「Onia 发布的内容在平台上的表现」，不声称这些全部由 Onia 增长能力造成。
- 不虚构 CTR、成交转化、收益、ROAS；无点击或交易归因链就不出这些卡片。频控与工作量仅代表本系统，不宣称覆盖用户所有端行为。
- 导出沿用归属和套餐限制，附指标定义、数据来源、时间和缺失原因；列表筛选与导出范围一致，避免多账号泄露。

## 14. 可控日常运营（「养号」）的正确产品化

提供「日常计划」作为模板集合，而不是另造一个自动刷量模块：内容节奏、授权会话维护、已确认目标的关系维护、账号检查/同步、人工复核与恢复提醒。模板介绍写清目的与副作用，用户选择账号、内容与时段后才能启用；不附赠陌生用户爬取名单，不引导无差别关注和冷私信。

建议增强：

1. **运行前试算**：不调用平台写接口，展开未来触发、每账号动作及内容预览、共享设备冲突、授权覆盖与预计阻塞；不伪造执行耗时。
2. **一键停机与恢复清单**：按账号组或全局暂停，明确在途动作可能完成；恢复时逐项检查会话/内容/授权，不补发过期任务。
3. **异常收件箱**：将结果未知、需要重新登录、内容不支持、审批过期集中到总览，提供明确下一步，而不是只能看原始日志。
4. **内容用尽保护**：周期内容池默认不重复，用尽暂停；避免把「每天发帖」变成每天重复同一媒体。
5. **操作预算**：用户可设置本系统每账号每日/周期上限和安静时段；它是运营控制，不是平台安全阈值，不因达标就标账号健康。
6. **变更影响预览**：编辑模板或暂停设备前列出受影响计划；复制、升级版本、换账号/设备都展示差异，减少误操作。

风险事件（平台挑战、限制、身份不匹配等）应阻断相应写动作并通知用户。恢复依靠用户正常登录/验证与明确复核，不通过随机延迟、IP/指纹或设备伪装绕过检测。真实用户授权的互动可规划，但不将多账号能力包装成协同点赞/评论放大器。

## 15. 关键流程与用户故事

### 15.1 五条主流程

**A. 单账号单动作**：账号详情点创建 → 选发消息 → 明确目标和逐条文本 → 立即/一次/周期 → 检查会话与授权 → 确认 → 进入运行 → 平台凭证/失败/待核对。不能只返回「已受理」就显示已发送。

**B. 多账号内容排程**：内容草稿选账号集合 → 逐账号媒体和文案覆盖 → 支持性检查 → 指定时区与时间 → 预览最终账号快照 → 审批 → 每账号排队 → 真实发布结果入台账 → 可用指标后续采样。某账号无能力时必须明确排除或修复，不能静默替换素材/格式。

**C. 串行流程**：选模板版本 → 配参数 → 检查前序引用 → 选择账号与计划 → 每账号独立串行 → 某步失败停止该账号后续 → 判断是否可安全重试 → 其他账号按策略继续；下一步不得因前一步「待核对」而启动。

**D. 日常周期计划**：从模板建草稿 → 选择明确目标/内容池/活跃时段/截止/操作预算 → 预览后续触发 → 审批覆盖范围 → 每次独立运行 → 重叠/错过标跳过 → 内容用尽/风险/授权到期暂停 → 用户复核后恢复。

**E. 代理回复**：新入站事实 → 会话视图 → Agent 草稿 → review 审核/策略 → 与手动任务共用账号/设备锁 → 发送前重新验证锚点 → 结果回写。人工接管即停该会话自动发送；不把会话变成无限周期消息计划。

### 15.2 用户故事与可验收结果

| 用户故事 | 可重复验收 |
|---|---|
| 我只想关注一个已确认目标，不想理解 Signal | 单动作向导可完成；展示账号/目标/时间与成功凭证，原始 ID 仅详情折叠 |
| 我想把重复日常步骤存下来 | 保存模板版本，重新使用不带入旧执行状态；版本升级不改变已有批准计划 |
| 我想每周在多个账号发不同内容 | 每账号覆盖可预览，产生独立运行；共设备不并发写；媒体能力不足账号被明确阻断 |
| 我想复制昨天任务稍作修改 | 副本是草稿停用，旧时间/授权/平台结果不复用；无外部请求，重新确认才能执行 |

## 16. 状态机与边界验收

### 16.1 面向用户的状态（建议语义，不强制重命名现有枚举）

- 模板：草稿 → 已发布版本 → 已归档；归档不删除历史快照。
- 计划：草稿 → 待审批 → 待启用/已启用 → 暂停/到期/取消；修改待审字段后回到待审批，不修改已运行实例。
- 每次触发记录：到期 → 已建批次；或跳过（错过/重叠/未在时段），保留原因。跳过不是执行失败。
- 账号运行：待审批 → 已计划/等待 → 执行中 → 成功 / 失败 / 已取消 / 已过期 / 待核对；待核对可经凭证核实为成功或确定失败，人工确认不冒充平台自动确认。
- 步骤：等待前序 / 等设备 / 等能力 / 等时间 / 执行中 / 等外部处理 / 成功 / 失败 / 待核对 / 已取消。动作内部 pending 仍属执行中，不是成功。
- 批次：待审/已计划/进行中/需处理/全部成功/部分成功/全部失败/已取消；各账号结果数量是最终依据，不能用父级一个状态遮住未决项。

### 16.2 发布前必须重复执行的验收集

| 编号 | 测试条件与操作 | 通过标准 |
|---|---|---|
| A01 | 对六种动作分别新建单步立即、一次、周期任务 | 三种时间共用规则；未就绪动作只能草稿或显式阻断，不能演示成功 |
| A02 | 单动作添加第二步，再改回一步 | 仍是同一任务/审批/监控体系，不丢参数，不生成额外计划 |
| A03 | 同账号三步，第二步确定失败 | 第三步不执行；取消原因可见；不以父任务「已发送」当整体成功 |
| A04 | 两账号用两设备，再让两账号共享一设备 | 前者可受控并行，后者严格设备互斥；开始执行前身份重新验证，绝不串号 |
| A05 | 批次中一账号无能力/素材失效 | 默认提交被阻断；显式只提交通过账号后，清单和排除原因留痕 |
| A06 | 周期扫描重复、重启跨过多个触发时刻 | 同触发每账号只建一运行；错过时刻跳过，无集中补发 |
| A07 | 上轮运行未结束又到下一周期 | 本轮重叠跳过，原运行不被取消，也不堆叠多个写操作 |
| A08 | 设备离线超过有限等待截止再上线 | 原运行过期不再执行；恢复无突发补发；离线时能看具体等待原因 |
| A09 | 在发送请求后模拟断线丢响应 | 标待核对，后续写步骤停止，无 DOM/其他通道盲回退；人工核实可附凭证 |
| A10 | 暂停计划、暂停运行、取消运行、全局停机各测一次 | 各自影响范围清楚；未派发停止，在途结果如实记录，不声称撤回已发内容 |
| A11 | 复制已成功任务/周期计划/含引用模板 | 副本草稿停用，无平台请求；旧授权/结果不复制；重选时间并重审 |
| A12 | 批准后修改收件人/文案/媒体/账号/授权时窗 | 原审批失效，未重审不执行；原运行快照和历史不被改写 |
| A13 | 帖子/Story 上传成功但平台配置发布失败 | 不入已发布数，能定位失败阶段；Story 多条部分成功不整体重发 |
| A14 | 指标缺权限、过期、未采集、真实为零各构造一条 | 四者不混；显示来源/时刻；Story 过期保留快照但不标仍在线 |
| A15 | 普通用户修改 URL/账号参数或导出范围访问他人数据 | 服务端拒绝且不泄露计数/内容；超管操作保留操作者与归属 |
| A16 | 账号切号、解绑、平台挑战、权限撤回 | 相关新写动作阻断，计划停用/暂停可解释；不自动切其他账号或设备续发 |
| A17 | 修改模板并发布新版本 | 历史与已批准计划不变；显式升级需差异确认与重审 |
| A18 | 非北京时间计划遇夏令时切换和跨日 | 下一触发预览与实际一致；缺失时刻跳过、重复时刻一次；日期归属清晰 |
| A19 | 同一消息事件到达两次，或审批旧草稿前有新入站 | 不重复回复；旧锚点草稿按既有策略作废/重审；人工接管有效 |
| A20 | 旧入口重定向、迁移旧定时定义 | 深链接可追历史、账号归属不扩大、迁移不触发发送、旧实例不重播 |

集成和 Mock 测试只能证明产品管线；六个真实写动作的端到端验证必须用用户明确授权的测试账号/目标，由独立验收操作确认。本文不执行测试关注/私信/评论/发帖/Story，也不以文档授权代替真实外发授权。

## 17. 分期：全目标保留，按依赖交付

### MVP：统一运营底座与可控闭环

交付统一创建向导、单动作/已有单链模板、三类时间、多账号快照与逐账号运行、设备互斥、任务/计划复制、明确审批、有限等待/幂等/待核对、运行详情、账号六维状态、发布台账、现有执行统计整合、全局停机。六动作目录全覆盖，逐动作有真实成熟度门禁，不把未完成动作藏起来也不误开放。

先复用已有多动作和 cron 能力，完善产品模型与风险边界；不要求先造复杂画布。**六动作可执行验收是最终核心闭环的硬门槛**：帖子上传和 Story 真发布验证是发布子阶段的显式依赖。若底座先交付，只能称「运营底座阶段」，不得称六动作已全可用或项目完成。关注/消息/点赞/评论也须补本轮授权场景复验。

MVP 内容数据至少提供可信发布台账和执行看板；对无法合法取得的指标显示限制，不伪造。若用户将完整内容效果看板设为首发硬门槛，必须先解决数据源/资格决策，不能通过砍掉需求或私有抓取假装完成。

### P1：内容运营与工作流增强

交付帖子/Story 可用指标支持表和来源明细、已验证的数据采样/历史快照、内容池不重复与用尽暂停、类型化前序产物引用、等待/指定时间节点、运行前试算、变更影响分析、账号组与安全的批次操作。依赖 MVP 发布结果 ID 稳定、能力验证与数据保留策略明确；不把「官方 Insights」绑定成唯一承诺，也不为无来源指标填数。

若重新考虑官方数据能力，先独立决策官方分支/授权/审核与迁移方案，再实施适配；没有这项决策，当前脚本 main 的 MVP 不偷带官方通道。

### P2：代理协同与复杂流程（独立评审）

评估有限分支/循环、团队/客户工作区及审批角色、代理事件触发与任务模板更深整合、多平台和有资格的官方能力。任何批量外发、跨客户代操作、触发式营销都需独立边界与平台规则审查；不随工作流引擎顺带开放。

依赖顺序：账号身份/能力与权限 → 统一运行治理 → 多账号与调度 → 发布闭环/台账 → 数据来源验证 → 高级编排。内容看板不能先于可靠媒体结果与合法数据源；自动化不能先于停机、审批和未知结果处理。

## 18. 迁移方案与既有决策差异

### 18.1 不丢历史、不重放、不越权

1. 先盘点旧页/角色/定义/计划与实际部署版本，记录数量和映射关系；只读验证不执行历史任务。
2. 旧 Signal 定义映射模板版本；带 schedule/target 的定义拆出计划快照；旧单动作发令映射一步运行。内部 ID 和 Signal/Todo/Behavior 链接保留。
3. **迁移本身不触发任何运行，也不新增重发。** 历史实例只读；运行中实例仍由原执行链收尾，新页面聚合观察，不能同时由新旧调度双写。
4. 旧已启用计划先做权限、时区、截止与授权覆盖审计；无法满足新规则则标「待迁移确认」且不生成未来新运行。已核实无需语义变化的计划是否无缝接续，由架构给出切换水位与幂等验证后再批，不静默套默认。
5. 旧入口过渡期只读或引导到新创建向导；旧深链接继续到对应历史详情。新版稳定后隐藏普通用户工程菜单，高级诊断仍可查原记录。
6. 归档模板不删除历史；暂停/取消和迁移操作都记审计。回滚只回展示/入口与受控调度开关，不重放过去触发。
7. 官方分支与 main 数据库迁移差异单独处理；本次不运行迁移、不恢复被删除表、不要求共享同库切分支。[S2]

### 18.2 建议覆盖点与必须保持点

| 原决策/边界 | 本轮建议 | 是否已落实 |
|---|---|---|

## 19. 给架构与设计的评审输入、待确认项

本文已经给出可继续评审的默认，不以追问阻塞文档：

1. **产品范围**：按「社媒代理 + 可控日常运营」扩容，内容库/排程/看板进入正式目标；不是转向刷量。需确认产品真源同步范围。
2. **设备模型**：当前多账号实际容器/登录态是否支持、每设备容量与锁边界，须只读核对后形成能力表；不能从多账号需求反推已有多开。
3. **发布验收**：帖子上传补齐、Story 真发布验证分别排交付门禁，确认首发是否必须六动作全部可执行；无论怎么分批，最终目标不变。
4. **数据资格**：当前 main 不恢复官方功能；内容深度指标需要明确合法数据源。如果要官方 Insights，先单独批准分支/资格/权限/审核与数据库迁移路线。
5. **授权默认**：建议默认 review、周期有授权截止和有限等待，复制一律停用草稿；自动代理原 review/auto/suggest 保留，需确认既有用户过渡政策。
6. **角色/保留策略**：首期沿用用户归属与 super_admin，不新增代理客户空间；内容、会话、运行与指标历史保留/删除策略需结合隐私条款和套餐另定，不编期限。

后续只读 UI 补证清单：按普通用户和超管分别记录菜单/页面截图；对照旧→新矩阵确认实际入口；查看空态、能力警告、计划状态、账号状态和统计定义；不新建/改动任务，不发送任何互动或内容。补证可能调整「现状」表，不改变本轮用户要的最终产品目标。
