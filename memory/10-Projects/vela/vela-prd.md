# Vela 产品文档（MVP）

本文是给评审用的产品成稿，只覆盖 **Vela**（AI 语音助播），不涉及 Onia / Verlume。对照 2026-11-11 播搭子逆向报告、2026-11-11 Daily 摘要、2026-11-19 Daily 中的 VoiceStudio 评估与项目命名决策写成。

**完整逆向报告已于 2026-11-19 由用户提供**，用于补全能力对照与分期命名。撰写时仍遵守：不编造用量、转化、市场规模、首包延迟、RTF、并发路数或备案/售价承诺；不把竞品接口字段、协议、密钥、视觉或文案写成 Vela 的实现。竞品商户配置中的价格、备案号等只属于对方站点，不写入本产品口径。

立场：clean-room 做同能力新品牌，不复用竞品视觉、品牌、文案、密钥、接口或协议实现。本阶段先出文档与技术方案，**不开发**；实现方案交技术架构师另出。

**相对 18:21 初稿的主要修订**：七种模式现已按报告命名并写入分期；模式 3「助播」不再写成「点选一条话术入队」，而纠正为「主讲解由真人承担，AI 负责欢迎 / 报时 / 互动回复，本阶段用 Mock 事件 + 手动插话验证」；明确竞品隐藏「唠星人」模式本产品不做；音色「训练微调」因候选引擎不覆盖，放入后续而非 MVP。

## 1. 产品定义：卖什么、不卖什么

### 卖什么（本阶段要立住的叙事）

**Vela** 是面向直播运营的 **AI 语音助播 Web 产品**：运营在后台准备音色与话术，选择一种直播模式后，系统把文本转成语音并**边生成边播放**，用于辅助现场口播，或按稿逐句播报。

本阶段交付面是：**Web 官网 + 后台 + 服务端**（可选独立 Agent 项目做话术类能力的预留边界）。直播平台侧使用 **Mock 适配器**，在受控环境里验证「文本 → TTS → 播放队列 → 出声」，以及助播所需的 Mock 互动事件。播放发生在后台浏览器页内，开播页需保持前台。

### 不卖什么（写进对外口径时禁止声称）

- **不是**「已接入抖音 / 快手等真实直播平台的无人值守直播工具」。本阶段不接真实抖音或其他真实直播开放平台。
- **不是**完整复刻播搭子全部 7 种模式，以及货盘 / 卡密 / 白牌多租户的 SaaS。本阶段只落地模式 2、模式 3 及相关语音链路。
- **不是** App / Flutter 客户端，也不能承诺锁屏或切后台持续出声（那是后续 App / 原生容器能力）。
- **不是**「已商用清关的 VoiceStudio 一体方案」。VoiceStudio 只覆盖音色克隆 + TTS 层，且存在 AGPL 与模型商用许可约束（见第 10 节）；TTS 必须以可替换 adapter 接入，不得绑死。

### 其他能力面（产品层摘要）

- **音库**：竞品有「训练」（长音频微调）、「克隆」（短参考音频）、「随机」三种创建方式。VoiceStudio 覆盖零样本克隆与 voice design / 随机音色，**不覆盖训练微调**。Vela MVP 只做克隆 + 随机/系统音色；训练放入后续。
- **话术**：竞品有流式生成、过滤、整段改写，以及模板变量。Vela MVP 只做人工维护的话术本 / 模板；AI 生成与改写放后续 Agent。
- **互动**：欢迎、回复提问、报时、手动插话、忽略昵称、模板随机。真实弹幕依赖直播间分享链接与平台接入，本阶段不做；MVP 助播用 Mock 事件模拟「进入 / 提问 / 报时」。
- **直播位与配置、算力与卡密、货盘、白牌多租户、App 伴随端（后台播放 / 悬浮窗）**：竞品有完整体系。Vela 本阶段不做支付卡密、货盘、白牌与 App；「场次 / 配置」只保留开播所需的最小概念。
- **播放约束**：竞品也是浏览器承担播放引擎。纯 Web 无法在锁屏或切后台保证不断播；Vela MVP 接受「开播页保持前台」。

### VoiceStudio 覆盖关系（2026-11-19 Daily 评估）

上游参考：`https://github.com/colna/VoiceStudio`（fork 自 debpalash/VoiceStudio，AGPL-3.0）。覆盖关系以当日评估与用户说明为准。

| 能力 | VoiceStudio | Vela 本阶段 |
|------|-------------|-------------|
| 声音克隆（上传参考音频，零样本，非训练微调） | 支持 | **MVP 要做**（经 TTS adapter） |
| 文本转语音 / voice design 随机音色 | 支持，多引擎、中文可用 | **MVP 要做** |
| 直播中边生成边播（流式） | 有 `/ws/tts` 流式接口，自带 ttfa/rtf 指标 | **MVP 要做**（产品侧建播放队列） |
| 模式 2 逐句读、模式 3 助播 | 能支撑语音链路（编排需自建） | **MVP 要做**（业务编排自建） |
| 碎片音频切段、主辅插播 | 不支持 | **后续**（ffmpeg + 队列自建） |
| 二创（音频重组 / 变声） | 不支持 | **后续** |
| 7 种模式编排、弹幕、话术改写 | 不支持 | **后续**（业务层自建；Agent 预留） |
| 长音频训练微调 | 不支持 | **后续**（需换引擎或自建，不进 MVP） |

结论：VoiceStudio **不能单独构成产品**；它只是 TTS / 克隆层的候选实现。产品主体是后台编排、播放队列、模式状态机与 Mock 直播适配。

## 3. 目标用户与核心场景（假设）

以下用户画像为产品假设，未经独立用研验证。

| 角色 | 诉求 | 本阶段是否服务 |
|------|------|----------------|
| 直播运营 / 助播 | 用克隆音色按稿逐句播报，或在真人讲解时由 AI 做欢迎、报时和互动回复 | 是 |
| 商家主播本人 | 想「无人值守挂机直播」并对接真实抖音 | **否**（本阶段不做真实平台接入） |
| 白牌代理商 / 多商户运营 | 卡密、多租户、货盘分销 | **否**（首期不做完整多租户；见第 9 节假设） |

核心场景（MVP）：

1. **模式 2 · 逐句读**：运营准备一份有序参考话术（每条一句或一小段，可含随机选词），选定音色后「开播」（Mock）。系统按顺序：取下一句 → 展开变量 → TTS（流式）→ 进入播放队列 → 播完再取下一句。可暂停 / 继续 / 跳过当前句 / 停止。不改写原文。
2. **模式 3 · 助播**：主讲解仍由真人承担，系统不自动朗读参考话术。运营填写本场商品/场次说明，配置欢迎 / 报时 / 回复模板与音色后进入 Mock 直播。系统根据 Mock 事件（进入、提问、到点报时）或运营手动插话，生成并播放对应语音。本阶段不做主辅轨混音，多条音频按队列先后播放。
3. **音色准备**：上传参考音频做零样本克隆，或选用系统 / voice design 生成的音色，写入音库后供上述模式选用。

## 4. 目标与成功标准

### 目标

在 Web 后台跑通「音库 + 话术/模板 + 模式 2/3 + 流式 TTS + 播放队列 + Mock 开播（含助播 Mock 事件）」闭环，形成可评审、可交给架构师落地的产品口径；官网只做介绍，不发任务。

### 成功标准（不看用量 / 转化）

- 运营能在后台完成：登录（最小）→ 建音色 → 建话术或助播模板 → 选模式 2 或 3 → Mock 开播 → 听到边生成边播的语音。
- 模式 2 严格按序、不改写；失败句可重试或跳过，不静默丢队。
- 模式 3 在无真实弹幕的前提下，用 Mock 事件与手动插话即可演示欢迎、报时、回复、插话四类出声，且界面不声称已连接真实平台。
- TTS 经 adapter，可在不改业务编排的前提下替换引擎（文档与验收能说清边界）。
- 明确写出本阶段不做真实抖音、不做 App、不做其余模式与二创等，验收时不被扩大范围。

本阶段**不要求** App / Flutter 客户端。播放在后台开播页内完成。

建议的后台信息结构（不复用竞品导航文案与视觉）：

- 音库
- 话术（逐句读稿本；助播用的欢迎 / 报时 / 回复模板可同属「话术 / 模板」）
- 开播控制台（选模式、音色、稿本或场次说明、Mock 开停播、队列与当前句、Mock 事件与插话）
- 我的（最小账号与退出）

「直播位 / 多套配置 / 货盘 / 充值」不做完整产品化；若实现需要一次开播会话的名称，用「场次」即可。

## 6. MVP 范围与分期

### 6.1 MVP（本阶段文档对应的实现目标；仍先出方案再开发）

1. **模式 2 逐句读**：有序话术队列、可选随机选词（如 `{早上好|大家好}` 取其一）、自动推进、暂停/继续/跳过/停止。开播前参考话术与主播音色必填。
2. **模式 3 助播**：场次/商品说明必填；主播音色必填，助播音色可选。欢迎 / 报时 / 回复可开关；用 Mock 事件触发，并支持手动插话。不自动念参考话术，不做主辅轨混音。
3. **声音克隆**：上传参考音频 → 零样本克隆 → 写入音库（需权利人授权声明，见第 10 节）。
4. **TTS**：文本 → 语音；支持选用音库音色；可走 voice design / 随机音色作辅助（若 adapter 支持）。
5. **流式边生成边播**：消费 TTS 流式输出，进入播放队列，在后台浏览器连续播放。
6. **基础音库 / 话术与模板 / 播放队列**：CRUD、绑定到一次 Mock 开播会话、队列状态可见。
7. **Mock 直播适配器**：模拟「直播中」状态与开停播；可注入进入、提问、报时等假事件。不接真实抖音 SDK / 开放平台。
8. **官网 + 后台 + server** 三件套边界清晰；TTS adapter 可替换。

### 6.2 后续分期（必须写清，避免漏项）

默认顺序参考竞品实现难度，评审可改，不作为工期承诺。

| 分期 | 内容 | 依赖 / 说明 |
|------|------|-------------|
| P1 | Mock 弹幕源可配置化、互动频控与忽略昵称的完整策略（若 MVP 只做最小触发，此处补齐） | 仍不接真实平台 |
| P1 | 碎片化音频（模式 4）：切段、主/辅按比例插播、段长与切换频率 | 需自建 ffmpeg + 更完整的音频队列；非 VoiceStudio 能力 |
| P2 | 全自由（模式 0）、半自由（模式 1） | 依赖话术改写 / 分段；建议与 Agent 同期 |
| P2 | 全拟人（模式 5） | 在 0/1 之后；改写更重，需单独验收生成质量，不编造指标 |

## 7. 关键用户流程

### 7.1 准备音色

1. 登录后台。
2. 进入音库 → 新建音色 → 上传参考音频（格式/时长上限由实现方案定，产品要求：失败有明确原因，不静默成功）。
3. 勾选权利人授权声明后发起克隆（零样本）→ 状态：处理中 / 成功 / 失败。
4. 成功后可试听短句，再用于模式 2/3。也可选用系统音色或（若 adapter 支持）生成随机音色。

### 7.2 准备话术与模板

1. **逐句读**：新建有序话术列表；每条为人工维护的纯文本，可使用随机选词语法；本阶段不做改写 Agent。
2. **助播**：维护欢迎、报时、回复三类模板（可先用简单文本 + 可选占位，如观众称呼、当前时间）；另准备本场商品/场次说明，供回复时作为上下文（本阶段不要求模型自动改写说明本身）。
3. 可预览「用某音色合成」短句，但不强制预合成整表（流式开播时再生成亦可；缓存策略交架构师）。

### 7.3 模式 2 · 逐句读开播（Mock）

1. 选择主播音色、有序话术列表、Mock 场次。
2. 点击开播 → 会话进入「直播中」（文案不得写成已连接抖音）。
3. 系统按序取句 → 展开随机选词 → TTS 流式 → 入队 → 播放；界面显示当前句、队列剩余、播放状态。
4. 运营可暂停、继续、跳过当前句、停止（停播）。
5. 某句 TTS 失败：该句标记失败，默认停在该句供重试或跳过；不自动吞掉后续整表（默认假设，见第 11 节）。

### 7.4 模式 3 · 助播（Mock）

1. 填写本场商品/场次说明，选择主播音色（助播音色可选），配置欢迎 / 报时 / 回复开关与模板。
2. 进入 Mock 直播中。系统**不**自动按参考话术逐句朗读。
3. 运营在控制台注入 Mock 事件，或到点自动报时：进入 → 播放欢迎；提问 → 播放回复；报时 → 播放报时。
4. 运营可随时手动插话：输入一句，生成后插入播放队列。
5. 多条音频按队列先后播放；本阶段不提供「主轨真人 + 辅轨 AI」的自动闪避/混音。

### 7.5 官网

访客浏览介绍与能力边界说明，进入后台登录入口。官网不创建音色、不开发播。须写明本阶段为 Mock、未接真实直播平台。

## 8. 用户故事与验收标准

### 用户故事（MVP）

1. 作为运营，我上传一段参考音频，以便得到可用于播报的克隆音色。
2. 作为运营，我维护一份有序话术，以便模式 2 按原文顺序播报。
3. 作为运营，我在 Mock 环境下开模式 2，以便听到话术被边生成边播放。
4. 作为运营，我在 Mock 环境下开模式 3，以便在不接真实平台时，用假事件和插话验证欢迎、报时、回复和手动插话。
5. 作为运营，我能看到队列与当前句状态，以便暂停、跳过或停止。
6. 作为访客，我在官网理解 Vela 是什么、本阶段不接真实抖音，以免预期错误。

### 验收标准（可重复验证；不把压测数字写死）

1. 后台可创建音色：上传参考音频并确认授权 → 克隆成功后音库可见且可试听；失败有错误提示。
2. 后台可创建有序话术列表，条目可增删改排序；含随机选词的条目在播放时只出其中一种展开结果。
3. 模式 2：Mock 开播后，按话术顺序、不改写地播放；未播完上一句不得自动开播下一句。
4. 模式 2：暂停后不继续出声；继续后从暂停点或当前句策略恢复（恢复粒度由实现方案定，产品要求行为可说明、可测）。
5. 模式 2：跳过当前句后进入下一句；停止后会话结束，队列清空或归档可见。
6. 模式 3：不自动朗读参考话术；缺场次说明或主播音色时不能开播。
7. 模式 3：注入「进入 / 提问 / 报时」Mock 事件后，对应模板语音进入队列并播放；手动插话同样入队播放，不丢请求。
8. 流式：播放过程允许「边生成边播」，不得要求整段 TTS 全部完成才开始出声（若引擎降级为非流式，须在 UI 标明，不得假装流式）。
9. Mock 场次可开可停；界面不得出现「已连接抖音」等真实平台文案。
10. 官网无登录业务操作；能力说明中写明本阶段 Mock、未接真实抖音。
11. TTS 调用经统一 adapter 边界（架构验收）：替换引擎不需要改模式 2/3 的产品流程定义。
12. 不出现竞品品牌名作为自己的产品名；不使用竞品密钥、接口路径或协议实现作为依赖。
13. 本阶段后台导航不出现：真实平台授权、其余模式（0/1/4/5/7）的完整编排入口、二创工作台、卡密发售、训练微调工作台（若仅占位，须标「未开放」）。

压测与性能：**必须自测**首包延迟、RTF、数小时稳定性与克隆主观相似度后再写入方案；本文不给承诺数字。公开 benchmarks 当时为空。

## 9. 本阶段明确不做 & 首期最小假设

### 明确不做

- 真实抖音 / 其他真实直播平台接入与真实弹幕。
- App / Flutter 客户端，以及锁屏 / 切后台持续出声。
- 碎片切段、主辅插播、二创变声 / 重组。
- 全自由、半自由、全拟人的完整产品化。
- 隐藏的唠星人模式。
- 长音频训练微调音色。
- 话术生成 / 改写 Agent 上线（可留 monorepo 空项目边界，但不做功能验收）。
- 货盘、卡密发售、真实支付、白牌多商户后台。
- 复用竞品前端、协议、密钥、备案号或品牌资产。
- 把 VoiceStudio 绑死为唯一引擎，或把 AGPL / 非商用模型写成「已可商用上线」。

### 首期最小假设（实现前可改，需明示）

1. **登录**：后台需要登录。默认做最小邮箱/密码账号即可；不做第三方一键登录矩阵。是否与 Onia 同一套账号见第 11 节待确认。
2. **计费 / 卡密 / 算力币**：首期**不做真实支付与卡密**。若联调需要「额度」概念，可用本地配额开关或无限额度开发模式，并在界面标明非计费。
3. **多租户**：首期默认**单租户**（个人/单团队）。白牌多商户是后续；数据模型可预留租户字段但不做商户后台。
4. **播放端**：首期以**后台页内 Web Audio / 浏览器播放**验证闭环；开播页需保持前台。是否要独立「播放器页」或本地小工具交架构师，但不做 App。
5. **并发**：评估口径曾写单卡 GPU workers 约 1–4 路、多商户可能要多卡——**标为假设**，不是承诺。首期产品按「单运营、少量并开会话」设计即可。
6. **助播回复质量**：MVP 可用模板播报（必要时把提问原文插入模板），不要求上线自动改写/大模型临场发挥；临场发挥随 P2 话术能力再做。

## 10. 合规与授权风险（必须写进方案评审）

1. **应用许可**：VoiceStudio 应用为 AGPL-3.0。作为商用 SaaS 使用需购买 Pro 商业授权或完成合规评估；不得在未评估时默认「开源可直接商用」。
2. **模型许可**：当日官方模型许可清单未见 `commercial_use: true`；默认 OmniVoice / OmniVoice-GGUF 为非商用。商用前必须换可商用引擎或取得模型授权。
3. **音色权利**：上传参考音频做克隆，必须由运营确认拥有权利人或已获授权；产品需有确认勾选与违规处理入口（文案级即可，法务细节另议）。禁止引导克隆公众人物或无授权声音。
4. **深度合成与标识**：若对外提供克隆与 TTS，需按深度合成 / 生成式人工智能相关规定考虑权利人同意、显著 AI 标识、日志留存等；具体合规清单由法务另评，产品在文档阶段先留出标识与日志位置，不写成已清关。
5. **竞品**：不使用竞品硬编码密钥、不抄其协议实现；真实平台接入单独合规评估。第三方非官方签名服务不构成平台授权。
6. **话术与广告**：后续若上线 AI 写话术，需考虑广告法与违禁词审核；本阶段人工话术同样应有基础违禁处理入口的预留，但完整审核策略可后置。
7. **安全对标**：竞品存在全站 HTTP、token 入 query、WS `eval` 等；Vela 默认假设使用 HTTPS、token 不进 query、不 `eval` 远端脚本（具体由架构师落地）。

以上风险在文档阶段标为**未清关**，不要写成已经可以对外售卖。
