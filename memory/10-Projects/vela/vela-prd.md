立场：clean-room 做同能力新品牌，不复用竞品视觉、品牌、文案、密钥、接口或协议实现。本阶段先出文档与技术方案，**不开发**；实现方案交技术架构师另出。

## 1. 产品定义：卖什么、不卖什么

### 卖什么（本阶段要立住的叙事）

**Vela** 是面向直播运营的 **AI 语音助播 Web 产品**：运营在后台准备音色与话术，选择一种直播模式后，系统把话术转成语音并**边生成边播放**，用于辅助或替代现场口播。

本阶段交付面是：**Web 官网 + 后台 + 服务端**（可选独立 Agent 项目做话术类能力的预留边界）。直播平台侧使用 **Mock 适配器**，在受控环境里验证「话术 → TTS → 播放队列 → 出声」闭环。

### 不卖什么（写进对外口径时禁止声称）

- **不是**「已接入抖音 / 快手等真实直播平台的无人值守直播工具」。本阶段不接真实抖音或其他真实直播开放平台。
- **不是**完整复刻播搭子全部 7 种模式与货盘 / 卡密体系的白牌 SaaS。竞品能力面里，本阶段只落地模式 2、模式 3 及相关语音链路。
- **不是** App / Flutter 客户端产品。本阶段不做移动端。
- **不是**「已商用清关的 VoiceStudio 一体方案」。VoiceStudio 只覆盖音色克隆 + TTS 层，且存在 AGPL 与模型商用许可约束（见第 10 节）；TTS 必须以可替换 adapter 接入，不得绑死。

## 3. 目标用户与核心场景（假设）

以下用户画像为产品假设，未经独立用研验证。

| 角色 | 诉求 | 本阶段是否服务 |
|------|------|----------------|
| 直播运营 / 助播 | 用克隆音色或指定音色，按话术逐句或助播方式出声，减少长时间真人念稿 | 是 |
| 商家主播本人 | 想「无人值守挂机直播」并对接真实抖音 | **否**（本阶段不做真实平台接入） |
| 白牌代理商 / 多商户运营 | 卡密、多租户、货盘分销 | **否**（首期不做完整多租户；见第 9 节假设） |

核心场景（MVP）：

1. **模式 2 · 逐句读**：运营准备一份有序话术列表（每条一句或一小段），选定音色后「开播」（Mock）。系统按顺序：取下一句 → TTS（流式）→ 进入播放队列 → 播完再取下一句。可暂停 / 继续 / 跳过当前句 / 停止。
2. **模式 3 · 助播**：在「主播仍可能真人出声」的设定下，运营点选或触发一条助播话术，系统生成并播放该条；支持插入下一条，但不在本阶段做复杂的主辅轨混音插播（那是后续「主辅插播」）。
3. **音色准备**：上传参考音频做零样本克隆，或选用系统 / voice design 生成的音色，写入音库后供上述模式选用。

## 4. 目标与成功标准

### 目标

在 Web 后台跑通「音库 + 话术 + 模式 2/3 + 流式 TTS + 播放队列 + Mock 开播」闭环，形成可评审、可交给架构师落地的产品口径；官网只做介绍，不发任务。

### 成功标准（不看用量 / 转化）

- 运营能在后台完成：登录（最小）→ 建音色 → 建话术 → 选模式 2 或 3 → Mock 开播 → 听到边生成边播的语音。
- 模式 2 严格按序；失败句可重试或跳过，不静默丢队。
- TTS 经 adapter，可在不改业务编排的前提下替换引擎（文档与验收能说清边界）。
- 明确写出本阶段不做真实抖音、不做 App、不做其余模式与二创等，验收时不被扩大范围。

## 6. MVP 范围与分期

### 6.1 MVP（本阶段文档对应的实现目标；仍先出方案再开发）

1. **模式 2 逐句读**：有序话术队列、自动推进、暂停/继续/跳过/停止。
2. **模式 3 助播**：点选/触发单条话术生成并播放；简单「下一条」插入；不做主辅轨混音。
3. **声音克隆**：上传参考音频 → 零样本克隆 → 写入音库（需权利人授权声明，见第 10 节）。
4. **TTS**：文本 → 语音；支持选用音库音色；可走 voice design / 随机音色作辅助（若 adapter 支持）。
5. **流式边生成边播**：消费 TTS 流式输出，进入播放队列，浏览器或受控播放端连续播放。
6. **基础音库 / 话术 / 播放队列**：CRUD、绑定到一次 Mock 开播会话、队列状态可见。
7. **Mock 直播适配器**：模拟「直播中」状态与开停播；不接真实抖音 SDK / 开放平台。
8. **官网 + 后台 + server** 三件套边界清晰；TTS adapter 可替换。

### 6.2 后续分期（必须写清，避免漏项）

| 分期 | 内容 | 依赖 / 说明 |
|------|------|-------------|
| P1 | 碎片音频切段；主辅插播（主轨 + 辅轨） | 需自建 ffmpeg + 更完整的音频队列；非 VoiceStudio 能力 |
| P1 | 弹幕驱动触发（仍可先 Mock 弹幕源） | 业务编排；真实平台弹幕随平台接入 |
| P2 | 其余直播模式编排（竞品称共 7 种；**另 5 种名称以完整报告为准，本版不编造**） | 模式状态机扩展 |
| P2 | 话术改写（Agent） | 独立 agent 项目；需提示词、安全审核与人工确认策略 |
| P2 | 二创：音频重组 / 变声 | 自建音频处理 |
| P3 | 真实抖音或其他直播平台接入 | **单独合规评估**；本阶段明确不做 |
| P3 | App / 移动端 | 本阶段不做 |
| 待定 | 完整多租户、卡密、货盘、算力账单 | 见第 9 节；首期默认最小化 |

## 7. 关键用户流程

### 7.1 准备音色

1. 登录后台。
2. 进入音库 → 新建音色 → 上传参考音频（格式/时长上限由实现方案定，产品要求：失败有明确原因，不静默成功）。
3. 发起克隆（零样本）→ 状态：处理中 / 成功 / 失败。
4. 成功后可试听短句，再用于模式 2/3。

### 7.2 准备话术

1. 新建话术本或话术列表；模式 2 需要**有序**条目。
2. 每条为纯文本；本阶段不做改写 Agent。
3. 可预览「用某音色合成」但不强制预合成全部（流式开播时再生成亦可；具体缓存策略交架构师）。

### 7.3 模式 2 · 逐句读开播（Mock）

1. 选择音色、话术列表、Mock 直播位。
2. 点击开播 → 会话进入「直播中」。
3. 系统按序取句 → TTS 流式 → 入队 → 播放；界面显示当前句、队列剩余、播放状态。
4. 运营可暂停、继续、跳过当前句、停止（停播）。
5. 某句 TTS 失败：该句标记失败，默认停在该句供重试或跳过；不自动吞掉后续整表（默认假设，见第 11 节）。

### 7.4 模式 3 · 助播（Mock）

1. 选择音色与助播话术集，进入 Mock 直播中。
2. 运营点选一条 → 生成并播放；播放中可再选下一条进入队列。
3. 本阶段不提供「主轨真人 + 辅轨 AI」的自动闪避/混音；若需插播感，仅以队列先后播放满足最低助播。

### 7.5 官网

访客浏览介绍与能力边界说明，进入后台登录入口。官网不创建音色、不开发播。

## 8. 用户故事与验收标准

### 用户故事（MVP）

1. 作为运营，我上传一段参考音频，以便得到可用于播报的克隆音色。
2. 作为运营，我维护一份有序话术，以便模式 2 按顺序播报。
3. 作为运营，我在 Mock 环境下开模式 2，以便听到话术被边生成边播放。
4. 作为运营，我在 Mock 环境下用模式 3 点选助播句，以便插入一条 AI 口播。
5. 作为运营，我能看到队列与当前句状态，以便暂停、跳过或停止。
6. 作为访客，我在官网理解 Vela 是什么、本阶段不接真实抖音，以免预期错误。

### 验收标准（可重复验证；不把压测数字写死）

1. 后台可创建音色：上传参考音频 → 克隆成功后音库可见且可试听；失败有错误提示。
2. 后台可创建有序话术列表，条目可增删改排序。
3. 模式 2：Mock 开播后，按话术顺序播放；未播完上一句不得自动开播下一句。
4. 模式 2：暂停后不继续出声；继续后从暂停点或当前句策略恢复（恢复粒度由实现方案定，产品要求行为可说明、可测）。
5. 模式 2：跳过当前句后进入下一句；停止后会话结束，队列清空或归档可见。
6. 模式 3：点选一条后进入队列并播放；多条依次播放，不丢请求。
7. 流式：播放过程允许「边生成边播」，不得要求整段 TTS 全部完成才开始出声（若引擎降级为非流式，须在 UI 标明，不得假装流式）。
8. Mock 直播位可开可停；界面不得出现「已连接抖音」等真实平台文案。
9. 官网无登录业务操作；能力说明中写明本阶段 Mock、未接真实抖音。
10. TTS 调用经统一 adapter 边界（架构验收）：替换引擎不需要改模式 2/3 的产品流程定义。
11. 不出现竞品品牌名作为自己的产品名；不使用竞品密钥、接口路径或协议实现作为依赖。
12. 本阶段后台导航不出现：真实平台授权、其余未命名模式的完整编排入口、二创工作台、卡密发售（若仅占位，须标「未开放」）。

压测与性能：**必须自测**首包延迟、RTF、数小时稳定性与克隆主观相似度后再写入方案；本文不给承诺数字。公开 benchmarks 当时为空。

## 9. 本阶段明确不做 & 首期最小假设

### 明确不做

- 真实抖音 / 其他真实直播平台接入与真实弹幕。
- App / Flutter 客户端。
- 碎片切段、主辅插播、二创变声 / 重组。
- 其余 5 种模式的完整产品化（名称待报告）。
- 话术改写 Agent 上线（可留 monorepo 空项目边界，但不做功能验收）。
- 复用竞品前端、协议、密钥、备案号或品牌资产。
- 把 VoiceStudio 绑死为唯一引擎，或把 AGPL / 非商用模型写成「已可商用上线」。

### 首期最小假设（实现前可改，需明示）

1. **登录**：后台需要登录。默认做最小邮箱/密码或与 Onia 类似的账号体系即可；不做第三方一键登录矩阵。
2. **计费 / 卡密 / 算力币**：首期**不做真实支付与卡密**。若联调需要「额度」概念，可用本地配额开关或无限额度开发模式，并在界面标明非计费。
3. **多租户**：首期默认**单租户**（个人/单团队）。白牌多商户是后续；数据模型可预留 `tenant_id` 但不做商户后台。
4. **播放端**：首期以**后台页内 Web Audio / 浏览器播放**验证闭环；是否要独立「播放器页」或本地小工具交架构师，但不做 App。
5. **并发**：评估口径曾写单卡 GPU workers 约 1–4 路、多商户可能要多卡——**标为假设**，不是承诺。首期产品按「单运营、少量并开会话」设计即可。

## 10. 合规与授权风险（必须写进方案评审）

1. **应用许可**：VoiceStudio 应用为 AGPL-3.0。作为商用 SaaS 使用需购买 Pro 商业授权或完成合规评估；不得在未评估时默认「开源可直接商用」。
2. **模型许可**：当日官方模型许可清单未见 `commercial_use: true`；默认 OmniVoice / OmniVoice-GGUF 为非商用。商用前必须换可商用引擎或取得模型授权。
3. **音色权利**：上传参考音频做克隆，必须由运营确认拥有权利人或已获授权；产品需有确认勾选与违规处理入口（文案级即可，法务细节另议）。
4. **竞品**：不使用竞品硬编码密钥、不抄其协议实现；真实平台接入单独合规评估。
5. **安全对标**：竞品存在全站 HTTP、token 入 query、WS `eval` 等；Vela 默认假设使用 HTTPS、token 不进 query、不 `eval` 远端脚本（具体由架构师落地）。

以上风险在文档阶段标为**未清关**，不要写成已经可以对外售卖。
