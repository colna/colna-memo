## 工作日志 — 现在 评估 InputBar 能否复用 PR #723 的 KeyboardLiftFooter

**做了什么**:拉 `feature/sitin4.0` 最新代码(前进 54 commits),对比 PR #723 分支上的 `KEYBOARD_LIFT_FULL_STYLE` / `KeyboardLiftFooter`,与 `feature/sitin4.0` 主线上 InputBar 现用的 `KEYBOARD_LIFT_STYLE` 做适用性分析。

**为什么**:用户想知道 chat InputBar 能否统一切换到新组件。

**结论**:**不能替换**。核心分歧在 translateY 公式:

| | `KEYBOARD_LIFT_STYLE`(InputBar 在用) | `KEYBOARD_LIFT_FULL_STYLE`(#723 新) |
|---|---|---|
| translateY | `-max(0, --kb-height − --nav-height)` | `-var(--kb-height)`(不扣 nav) |
| 适用 | 下方**有** nav / KeyboardAwareTabBar | 底部按钮**直接贴屏幕底**、无 nav |

- Chat 页 `pages/Chat/index.tsx:1361/1377/1385` — 聊天区、提示条、InputBar 三块共用**同一** `KEYBOARD_LIFT_STYLE`,精准落到键盘上沿。
- 换成 `KEYBOARD_LIFT_FULL_STYLE` → 多抬一个 nav-height,输入区会飘到键盘上方留出与 nav 等高的空。
- `KeyboardLiftFooter` 本质是 `<div style={KEYBOARD_LIFT_FULL_STYLE}>{children}</div>`,替换还会打破「三块共用同一 transform 表达式」的同步位移设计。

**关键命令**:
- `git switch feature/sitin4.0 && git pull --ff-only` (前进 54 commits)
- `git show origin/personal/zz/pwa-login-kb-lift:packages/app-pwa/src/components/KeyboardLiftFooter.tsx`
- `git diff origin/feature/sitin4.0..origin/personal/zz/pwa-login-kb-lift -- packages/app-pwa/src/utils/keyboardLift.ts`

**沉淀 / 建议**:
- InputBar 继续用 `KEYBOARD_LIFT_STYLE`,不换。
- 若求命名统一,可把 #723 的常量重命名区分意图(如 `KEYBOARD_LIFT_ABOVE_NAV_STYLE` vs `KEYBOARD_LIFT_TO_KEYBOARD_STYLE`),行为不动。
- 新事实:PR #723 **已合入** `feature/sitin4.0`(merge commit `2de987f15`),`KeyboardLiftFooter.tsx` / `KEYBOARD_LIFT_FULL_STYLE` 现已在主线可用。
