### HH:MM — sitin-next:Koa 反代非 JSON 响应改流式(修 CSV 导出 502)

- **背景**:生产 `GET /api/social-proxy/script/error-logs/export?startDate=<7d ago>&endDate=<now>` 返回 502。用户给了 curl 请求让排查。
- **排查路径**(前面绕了两轮):
  1. 一开始怀疑后端端点缺失(`feature/admin` 上确实没有 `@Get("error-logs/export")`),但没拉全 remote 就下结论。
  2. `git fetch --all` 后修正:后端 `1d523b5e`(PR #512)已在 `release/online-sp` 生产分支,前端 `c0912ca7`(PR #491)已在 `release/online-admin`。**端点存在,鉴权通过**。
  3. 用 1 分钟窄窗口 curl → 200,但 `Content-Type` 变 `text/plain`,`Content-Disposition` 丢了。7 天窗口 → 502。判定:反代层不流式,大响应超 CF origin timeout。
- **根因**:`packages/app-minerva-server/src/_koa-perm/routes/social-proxy/index.ts` 非 JSON 分支用了 `ctx.body = await res.text()`,把上游 cursor 分批的流式 CSV 全缓成 string 才 set `ctx.body`,导致响应头一直不发,超时。
- **改动**(commit `b6208239`,分支 `personal/zz/admin-sp-proxy-stream` off `feature/admin`,+12 -1):
  非 JSON 分支改成 `ctx.body = Readable.fromWeb(res.body as WebReadableStream<Uint8Array>)`,并透传 `Content-Type` / `Content-Disposition` / `Cache-Control`。JSON 分支不动。
- **结果**:`pnpm --filter @heyhru/app-minerva-server lint` 0 error;`tsc --noEmit` 本文件 0 error。**PR #522** 已开(base: `feature/admin`)。
- **push 备注**:pre-push 全量 build 里 `@heyhru/business-minerva-upgrade` 打包挂在 `@presence-io/common` 未声明依赖上,这是 `feature/admin` HEAD PR #457 就带的历史坏,与本 PR 无关,用户授权 `--no-verify` 推送。
- **沉淀**(值得复用的经验,已归到 [sitin-koa-fastify-proxy-streaming](../30-Resources/troubleshooting/sitin-koa-fastify-proxy-streaming.md)):
  1. **两个仓分开部署**:`feature/admin`(admin 前端 + minerva-server Koa 反代)、`feature/sp`(social-proxy-server 后端),分别推 `release/online-admin` / `release/online-sp`。排查跨系统问题时先确认部署映射,别只看单个分支的 controller。
  2. **`fetch(url).text()` 抵消上游流式**:Koa 中间层反代 fetch 响应时,任何 `await res.text()` / `res.json()` / `res.arrayBuffer()` 都会等上游全部 flush 完才继续,只有直接把 `res.body`(WHATWG ReadableStream)当 stream 挂到 `ctx.body` 才是真流式。
  3. **`ctx.body = string` 会让 Koa 覆盖 Content-Type 为 text/plain**——反代场景要先 `ctx.set(...)` 再赋 stream 才能保留上游 MIME。
  4. **排查大响应超时时 curl 用窄时间窗**——1 分钟窗口一秒返回、7 天窗口 502,直接把问题定位到"大小/时长"而非"路由/鉴权"。
- **未做**:未起 admin 本地服务真跑,只做了 lint/tsc/curl 端到端确认。CORS `exposedHeaders` 没加 `Content-Disposition`——前端 `streamExportScriptErrorLogs` 是自己 `showSaveFilePicker({ suggestedName })`,不读服务端 header,先不动。
