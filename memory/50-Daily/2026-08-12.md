# 2026-08-12

## 工作日志 — 13:54(sitin-next2 Snapchat:NEW_MESSAGE 事件 data 改为 object)

**做了什么**:`packages/app-ins-scripts/src/snapchat/actions/startDMListener.js` 的 `reportNewMessage` 上报 NEW_MESSAGE 时,去掉外层 `JSON.stringify`,直接把 payload 对象传给 `bridge.emitScriptEvent({...})`。

**为什么**:`emitScriptEvent(data)` 内部会 `JSON.stringify({success,data,interaction,timestamp})`。原来调用方又先 `JSON.stringify(payload)` 一次 → 事件里 `data` 变成**字符串**(后端要双重 parse)。后端需要 `data` 是 **object**。IG 版 `instagram/actions/startDMListener.js:132` 本就是传对象,Snapchat 改成一致。

**结果**:`node scripts/build.mjs` 通过(snapchat 3 bundle/31 脚本);产物 `dist/snapchat/automation.js` 已是 `emitScriptEvent({platform,type:"NEW_MESSAGE",source,threads})`。事件形如 `{"success":true,"data":{...对象...},"interaction":true,"timestamp":...}`。未提交(规范模式,待用户批准)。

**遗留观察(未改,待用户决定是否统一)**:同仓另有两处仍 `JSON.stringify` 后传 emitScriptEvent —— `snapchat/methods/getChatMessages.js:838`、`instagram/methods/getChatMessages.js:942`。属另一类事件消费方,本次只按用户要求改了 NEW_MESSAGE。
