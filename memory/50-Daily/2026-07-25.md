## 工作日志 — 22:5x sitin-next 登录/onboarding 底部按钮随软键盘上移(PR #723)

**做了什么**:修 APK 下登录/注册流程「键盘弹起遮挡底部提交按钮」。基于 `feature/sitin4.0` 切 `personal/zz/pwa-login-kb-lift`。

- `packages/app-pwa/src/utils/keyboardLift.ts`:新增导出 `KEYBOARD_LIFT_FULL_STYLE` —— 纯 transform 上移**整个** `--kb-height`(不扣 `--nav-height`,因这些页无 `KeyboardAwareTabBar`、按钮贴屏幕底),复用与 `KEYBOARD_LIFT_STYLE` 同一 transition。
- 新增 `components/KeyboardLiftFooter.tsx`:wrapper 组件包裹底部按钮。
- 5 页把 `<Button>` 套进 `<KeyboardLiftFooter>`:`Onboarding/{Username,Age,Phone}`、`PhoneLogin/{PhoneStep,OtpStep}`。

**为什么这么修**:复用聊天输入栏(ChatInputBar)同一套 `keyboardLift` 机制 —— APK 靠 native `notifyKeyboardChanged` bridge 写入 `--kb-height`,web 端恒 0。根因见 `troubleshooting/mobile-keyboard-and-viewport.md` §5:APK 键盘 overlay WebView、`visualViewport` 不 resize,`h-full` 容器不缩,贴底按钮被盖。web 端本就无此 bug(resizes-content 自然缩容器),transform=0 无副作用。

**遇到的问题 → 怎么解决**:
- inputbar 用的 `KEYBOARD_LIFT_STYLE` 上移量是 `max(0, kb − nav)`(聊天页底部有 TabBar 占位)。登录页无 nav、按钮贴屏幕底 → 该上移**全高**;且 `--nav-height` 是全局变量、可能残留别页的值。→ 新建不扣 nav 的 `KEYBOARD_LIFT_FULL_STYLE`,语义清晰又避开残留风险。
- 图4/5「Your Phone Number」+「Next」一开始误认为是 `PhoneLogin/PhoneStep`,实为 `Onboarding/Phone`(PhoneStep 文案是 "What's your phone number?" + "Send code")。→ 逐页核对文案后定位准确。
- pre-commit 全库 `pnpm lint` 挂在 legacy 包 `business-minerva-users`(`no-useless-assignment`,本次 pull 带入、与改动无关),死锁提交。→ `turbo run lint --filter=@heyhru/app-pwa` 单独验证我的包通过后 `--no-verify`(符合 troubleshooting §7 既定实践)。

**结果**:app-pwa lint 通过、改动文件 tsc 0 报错(`ChatFooter.tsx critHit` 是 base 既有待生成 proto 问题)。PR #723 → `feature/sitin4.0`。
