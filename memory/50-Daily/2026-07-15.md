## 工作日志 — 键盘上抬纯 CSS 驱动版(PR #615)

- **接续**:上版「snap 到历史高度 + 0.2s CSS 过渡」(commit `e482ac120`)真机反馈**下落又不跟手**。根因:native 收起时先逐帧发 `show=true` 且高度骤降(非立刻 `show=false`),snap 逻辑 hold 在完整高度直到最后 `show=false` 才落 → 下落滞后。
- **改法(用户要「上升下落都改 CSS、不再依赖 native 逐帧回调」)**:handler 每状态只写一次 `--kb-height`(开→`lastKbFullHeight-GAP`、关→0),升降全交 CSS transition;新增**收起检测**——`show=true` 但 `height < kbPrevHeight - KB_RETRACT_DELTA(60)` 判定键盘在收 → 目标设 0 及时下滑。阈值 60 高于「回前台少报工具栏 ~30px」跌幅,回前台不误判成收起。commit `0b065b8ff`。
- **调试设施**:按用户要求先把 debug 加回本分支(`kbDebugLog` 浮层 + 首页 debug 按钮),日志加了 `ret=`/`-> target` 便于调阈值。

## 工作日志 — 键盘上抬:纯 CSS 驱动定稿 + 重构出 keyboardLift 模块(PR #615)

- **多轮真机迭代(靠页面日志浮层)最终定稿逻辑**(全在 `app-pwa`):
  - **上升**:`--kb-height` 一次性写目标(不逐帧追 native),CSS transform `0.2s cubic-bezier(0.2,0,0,1)` 缓动;完整高度**持久化 localStorage**,冷启动首次即一步到位(否则逐帧累积会被 CSS 拖慢)。
  - **下降(跟手)**:native 收起是逐帧 `show=true` 高度平滑降到 0、末段抖动(h 0/1/2),最后才 `show=false`。用**收起锁存**:高度从近满峰值回落 > `KB_RETRACT_DELTA(45)` 即 latch `closing`→target 0,**保持到 show=false**,末段抖动不再翻转(修「落到底又弹一次」)。
  - **缓存防污染**:按屏幕方向分 key(`kb_full_height_px_portrait/_landscape`,旋转时切换+重置)、只缓存落在 viewport `20%~70%` 的高度(挡表情面板/异常值/回前台中间值)。
