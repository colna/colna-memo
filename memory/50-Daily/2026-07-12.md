## 工作日志 — PWA 主叫补发 CallOrder TIM 自定义消息

- **背景**:承接 sitin-next PR #591(女方 PWA 主叫改为自己 HTTP `createCallOrder` 拿 orderId)。对齐安卓 `TUICallKitImpl.goStartVideo2`,安卓建单成功后会调 `sendOrderIdToServer` 用 TIM 把 orderId 推给对端;PWA 主叫此前只填了自己 `connectSession.orderId`,**没通知对端**。用户要求 PWA 也补上这条 TIM 消息。
- **改动文件**:`packages/app-pwa/src/hooks/useWebCall.tsx`
  - 新增 import:`IMManager`(`@/services/IMManager` 默认导出单例)、`CustomDescription`(`@/types/chatMessage`)。
  - 新增模块级 helper `sendCallOrderToPeer(targetUserId, orderId)`:发 `description="CallOrder"` 的 C2C 自定义消息,**wire 格式与安卓完全对齐** —— `payload.data` = `{businessID:"custom_create_video_order", orderId, text}`(orderId 为字符串),`cloudCustomData` = `{orderId}`。对端 IM 监听读 `payload.data.orderId`(`webCallManager.tsx:192` / `nativeCallManager.tsx:156`)。
  - `placeOutgoingOrder` 拿到 orderId 后 fire-and-forget 调 `sendCallOrderToPeer`,失败只 log 不阻塞拨号。**native 与 web 两分支共用**(都走 placeOutgoingOrder),与安卓「建单成功即推送」一致。
- **关键点**:
  - CallOrder 不在 `descriptionMessageTypeMap`(IMManager.ts:38),故不生成 offlinePushInfo → 是静默控制消息,符合安卓 `isExcludedFromUnreadCount/LastMessage` 意图。
  - orderId 发字符串而非数字,匹配安卓现有格式,保证互通(PWA 侧现在就在收安卓推来的字符串)。
- **验证**:`tsc --noEmit` 通过;`eslint src/hooks/useWebCall.tsx` 通过。真机未验证。
