## 工作日志 — 16:35 media-chunk 改为 Range 透传 OSS（服务端，客户端无感）

- **做了什么**：改 `packages/app-social-proxy-server/src/script/media-chunk.service.ts` 的 `getChunk(url,...)`：不再 `fetch` 整个文件 + 3 条内存缓存，改为向上游发 `Range: bytes=off-end` 透传，从 `Content-Range` 解析 total，返回结构仍是 `{offset,size,total,chunk}`；`getChunkByKey`（story bake 本地文件）保持不变。
- **关键坑**：OSS 在 Range 末尾超过文件大小时会返回 **200 + 整个文件**（实测 `bytes=23592960-23855103` → 200/23.8MB）。所以新增 `totals` Map 记住每个 url 的总大小（最多 1000 条 LRU），拿到 total 后把末片 end 截到 `total-1`；否则最后一个分片会退化成整文件下载。offset 越界时直接返回空片，不再发请求。
- **验证**：`npx jest media-chunk.service.spec.ts` 8/8 通过；`tsc -p tsconfig.build.json` 通过；eslint 0 error。真实 OSS 验证：4.9MB/23.8MB 两素材首片/中片/末片均 206；末片 clamp 后长度分别 187478/230477 字节，未 clamp 则 200 全文件。
- **兼容性**：接口契约不变，JSSDK 脚本与 APK 均无需改动；上游 200（不支持 Range 或末片未 clamp 的极少场景）仍保留本地切片兜底。
