## 工作日志 — 15:19 定位 SUBMIT_STORY「烧录任务查询失败 HTTP 502」

- **现象**：`SUBMIT_STORY@1` 报 `STORY_PUBLISH_FAILED: 烧录任务查询失败：HTTP 502 error code: 502`；`dom_snapshot` 停在 IG inbox，说明还没进发布。
- **定位**：
  - 该文案只在 `createStory.js`（`callBakeApi` 轮询分支）抛出：`GET /script/bake-story-video/:jobId` 返回非 success；报错 body `error code: 502` 是 Cloudflare 纯文本错误页，不是 Nest JSON → 请求没到应用或应用不可用。
  - 不是烧录任务本身 failed（那会带 `job.error`）。
  - 现场实测 `https://social-proxy-api-dev.sitin.ai/script/bake-story-video/<uuid>`：能返回 `404 {"message":"bake job not found"}`，但极不稳定——6 次里 3 次连接超时，成功耗时 1–5.6s；根路径 `/` 连续超时。判断 dev origin 间歇性不可用/过载（Cloudflare 转发失败 → 502）。
- **代码层放大因素**：
  - 轮询对任何非 success 立即 throw，无 5xx/超时重试，一次抖动就整条 Story 失败。
  - bake job 存在进程内 `Map`，重启或多副本会丢 job（随后 404）。
- **待办**：① 查 dev pod 重启/CPU/内存（ffmpeg 烧录时是否 OOM）；② 给轮询加 3–5 次 5xx/网络重试；③ 若 dev 多副本，job 状态需落 Redis。

## 工作日志 — 15:27 修正：本机对 sitin.ai(CF LAX) 的测量不可用于判断服务器负载

- **仍然成立的部分**：
  - 设备侧报的是 Cloudflare 502（`error code: 502` 纯文本），502 语义是**边缘到 origin 失败**，与客户端网络无关，所以那次确实是 origin/回源层问题（重启、OOM、回源异常都可能，尚未定因）。
  - 轮询无重试、job 存内存这两个放大器问题不变。
- **prod 现状**：`/script/media-chunk?key=<不存在>` 返回 `404 {"message":"media key not found or expired"}`（不是 401）→ prod 已部署去鉴权版本；代码路径与 dev 相同，同样的 502 失败模式对 prod 同样存在，只是容量/监控更好。
- **怎么判 prod**：看 Cloudflare 面板按 origin 5xx/502 率与回源耗时；查 prod pod restart/OOM；从设备或稳定网络侧采样。不要用本机 curl 结论。

## 工作日志 — 23:25 验证 IG 帖子是否私密：未登录外部探测不可行

- **问题**：想统计评论任务涉及的 8 个 shortCode 里有多少是私密帖子。
- **日志侧结论**：无法统计，且没有一条证据指向私密。54 条 404 的 title 全是 `Page not found • Instagram`；8 个帖子里只有 `De3KFI1uc3a`、`De3KG4qzZu0`、`De3Kn3WvjBv` 被真正打开过并 404，其余 5 个从头到尾没被访问（全被前置检查拦掉）。
- **IG 语义**：私密内容对未登录是登录墙、对未关注是 `This account is private` / `This content isn't available`；`Page not found` 对应的是不存在/已删除/账号改名封禁。所以「404」更可能是删除或脏数据，不是私密。
- **外部验证全部失败**（代理 7897，试过香港/日本节点）：
  - `/p/{code}/` → 200 登录墙（~505KB）
  - `/p/{code}/?__a=1&__d=dis` → 404，但对随机编造的 shortCode（`AAAAAAAAAAA`）返回**完全相同**的 404（20942 字节）→ 端点已废弃，不能用于存在性判断
  - `/api/v1/oembed/` → `404 No Media Match`，真实与随机一致
  - `i.instagram.com api/v1/users/web_profile_info` → 401 `require_login`（换节点也无效）
  - embed / Googlebot / facebookexternalhit UA 均返回登录墙
  - 镜像站（imginn/picuki/dumpor）、RSSHub 被 Cloudflare 403
- **可行验证**：用执行评论的已登录设备逐个打开 8 个链接看文案；或服务端用已登录 session 调 `api/v1/media/{media_id}/info/`；或查 signal payload 的 socialId 看作者 `is_private`。
- **踩坑**：不要用 `?__a=1` 的 404 来判断 IG 帖子是否存在，必须先用随机短码做对照。
