### 关键教训

- **我编了一个原型里不存在的状态。** 自作主张加了 voice 的 `recorded` 态(校验前试听)+ 两句原型没有的文案(`Listen back...` / `Send voice`)。用户截图一问「html 中有这个状态吗」当场戳破。**枚举原型状态要用 JS 里的 `shBody.textContent =` / `ctaBtn.textContent =` 赋值点全集,而不是凭 UI 想象补齐。**
- **原型 voice 的真实时序**(与旧实现相反):`Stop` 即送审(**不是点 Send 才审**),通过后才出现 Play/Re-record + `Send — ¢0.80 earned!`;失败直接 `startRecording()` 重录,不回 idle。两处 Re-record 都是直接重录。
- **`onSent` 应在 CTA 点击时触发,不是审核通过时**。两份原型里真正把媒体塞进 chat 的都是那一下点击(`goStep4`)。photo 一并对齐。
- **通过态要停表**:片子已过审,何时发由她定,不该被倒计时收走(`terminal` 包含 `verified`)。
- **`@media (prefers-reduced-motion:reduce)` 里那堆 `animation:none` 是无障碍降级,不是「原型没动效」**。差点看漏。
- **原型的全屏相机是纯模拟**(无 `getUserMedia`/`<video>`),app 的原生 `capture="user"` 才是真的,不去造假相机。
- **`.pill-row{nowrap}` 在真机上会破版**。原型 384px 画布刚好放得下,实测:320px 溢出 31px、360px 溢出 11px、375px(SE) 溢出 4px、≥390px 才 OK。改 `flex-wrap`,≥390 与原型一致。**教训:原型的固定画布会掩盖窄屏溢出,涉及 `nowrap` 的行必须按真机宽度实测。**

- **各元素在审核态的行为**(逐条查证,不靠猜):
  | | recording | reviewing |
  |---|---|---|
  | 录音块 `shRec` | 显示 | **显示** |
  | 光晕 `rec-pulse` | 有 | **无**(`active` 移除) |
  | 波形条 `rec-bar` | 动 | **继续动**(原型该动画是**无条件 CSS**,没有 `.active` 门) |
  | 计时 | 实时 | **停在最后读数**(`clearInterval` 后数字不动 → 用 `recorded.durationMs` 而非 `recorder.durationMs`) |
  | CTA | 红 Stop | 琥珀禁用 `Checking content...` |
- `setRecorded(rec)` 在 `setPhase("reviewing")` **之前**(同一批更新),所以审核态拿得到时长,不会闪 `0:00`。
- **教训(与上一条同源)**:**「某个态显示什么」要逐个元素查它的 show/hide 赋值点**,不能只看 `.classList.add('show')` 的那一处就以为其余都隐藏了。我连续两次在同一份原型上想当然。

## 工作日志 — 底栏语音改回按住式 + 上滑取消(commit bd4050f8d,并入 PR #568)

- **交互模型回退(重要)**:PR #559 里用户明确要求「不再有手势上滑,使用点击式」,我删掉了整套 pointer 手势。新原型 `sitin40-inputbar.html` 绑的是 `mousedown/touchstart → mousemove/touchmove → mouseup/touchend`,**按下即录、松手即发**。用户确认回退。**教训:交互模型会来回改,别把「上次删掉的东西」当作永久决定;每次拿到新原型先读它绑了哪些事件。**
- **原型不在仓库里,是别人推到我 PR 分支上的**。`git ls-tree` 遍历所有远端分支都没有,最后发现远端 tip 是 `deec25fd8 feat: docs`(别人推的),不是我的 `03e80708`。**共享分支:动手前先 `git fetch` 比对 tip。**
- **取消判定是「接近」不是「滑动距离」**:
  ```js
  isOnTarget(x,y) → Math.hypot(x-cx, y-cy) < 40   // 垃圾桶圆心 40px 半径
  ```
  进入即 armed,移出即解除,**松手前可反复进出**。垃圾桶浮在药丸正上方 4px(`positionTarget()`,每次录音重测,因为底栏随键盘升降)。
- **层级**(照原型):蒙层 z-34、垃圾桶 z-36、输入栏 `.picker` z-43 → **底栏不被蒙灰**(聊天区暗、底栏亮)。
- **三个视觉态**:`.rec` 蓝;`.rec.cancel` → `--red-dim` 底 + 波形/chevron/文字全红 + 文案 `Release to cancel`,垃圾桶 `.hot` = `scale(1.3)` 红底 + `0 0 0 8px` 光晕。
- **与原型的有意差异**:①用 `setPointerCapture` 而非原型的 `document` 监听(手指拖出药丸仍收事件,且不干扰页面其它 pointermove);②垃圾桶+蒙层 `createPortal` 到 `body`(绕开祖先 `overflow` 裁剪);③保留 `MIN_DURATION_MS=1000`(原型 `Math.max(recSecs,4)` 照发不误)。
- **顺带修掉一个死锁(自己发现)**:按下后 **getUserMedia 还在授权中就松手**,旧写法 `if (startingRef.current) return` 把这次松手直接丢掉 → 录音永久停在进行中,没有任何事件能结束它。改为记 `pendingUpRef`,`start()` settle 后补发。
- **验证方法**:①把 `targetCentre` 的推导与真实 `getBoundingClientRect` 对拍 → 偏差 `0.0px`,垃圾桶底距药丸顶正好 4px;②把手势状态机搬进浏览器跑四个场景(正常/上滑取消/进出可逆/授权中松手)全部正确。**教训继续成立:几何和状态机都要实测,不要靠推导。**
- **顺带发现**:垃圾桶圆心到药丸顶只有 28px,所以手指刚离开药丸(d≈23)就已进入 40px 取消区。这是原型固有行为,非 bug。
