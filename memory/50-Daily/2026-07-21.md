### 02:xx browser-replay 修「无标识元素导致回放中断」（commit `8971db5`）

**现象**（用户实测）：回放停在第 2 步，`等待超时（10000ms）：focus #root > div:nth-of-type(1) > div:nth-of-type(2) > nav > … > div`。

**根因是三个缺陷叠加，不是一个 bug**：

1. **录了无意义的聚焦** —— SPA 常给布局容器挂 `tabindex`，点击时它真的拿到焦点，于是每次点击都多出一个 focus 步骤。而这类元素没有任何稳定标识，只能退到 8 层结构路径，**是整条脚本里最先失效的部分**。修法：只录输入类元素（input / textarea / select / contenteditable）的聚焦 —— 按钮的焦点由 click 自带，布局容器的焦点不影响任何状态。
2. **失败即停** —— 一个可有可无的 focus 挂掉，后面几十步真正有用的操作全被拦下。修法：focus / blur / scroll 失败跳过继续（等待上限 10s → 2s），关键步骤失败才中断。另外这三类步骤**不再要求元素「可交互」**：布局容器塌陷成 0 尺寸很常见，但 `el.focus()` 照样有效，硬套可交互判定只会让它们永远等不到。
3. **报错说不清原因** —— 「等待超时」分不清是「页面上没这个元素」还是「找到了但不可交互」。修法：区分两者，并列出尝试过的每个选择器**各匹配到几个元素**。

**顺带修掉同源的第四个问题**：结构路径从 `html > body` 一路铺下来。改为从最近的锚点或 `nav` / `main` / `form` 等**地标标签**起算，并把**文本线索提到结构路径之前**尝试（6 层路径插进一个包装层就全废，按钮上的文字改版后通常还在）。

**沉淀（⭐ 复用价值高）**

1. **「顺带发生的事件」不等于「用户的动作」。** focus 是点击的副产物，录进脚本就成了一个必须成功、却最容易失败的步骤。录制类工具要先分清「用户意图」和「浏览器的连带反应」，后者只在它本身改变状态时才值得记。
2. **失败处理要按「这步失败会不会让后面变得没意义」分级**，而不是一刀切。focus 失败后面照跑不误，click 失败后面全是噪声 —— 同一个 `if (!ok) return` 对两者都不对。
3. **超时报错必须带上「我试了什么、各匹配到几个」**。「等待超时」这四个字让用户完全无从下手；「`#x` → 0 个匹配」直接就能判断是页面改版还是选择器错了。
4. **兜底顺序要按可靠性排，不能按生成顺序排。** 原来 resolve 是「先试完所有 CSS 候选、再用文本兜底」，等于让最脆的 6 层结构路径优先于最稳的文本。改成按 score 分段：语义候选 → 文本 → 结构路径。

**测试**：选择器单测 9 → 11 项，端到端 16 → 24 项，新增「布局容器的聚焦未被录制」「失效的聚焦跳过而关键步骤中断」「结构路径失效后靠文本兜底」「结构路径从地标起算」。全绿。

### 02:xx（续）点击上溯到可交互祖先（commit `e910997`）

**用户追问**：`nav > div:nth-of-type(2) > … > span:nth-of-type(1) > span > span`（11 层）这种查找方式精准吗？

**回答要分两层**：录制那一刻它精准（生成时验证过唯一命中），但**下次几乎必然失效**（任何一层多个包装 div 就全废）。用户真正该关心的是后者。

**但根本问题是这条路径不该长成这样**：`span > span > span` 说明录制器记的是**事件的 `target`** —— 点一个按钮时 target 往往是按钮里的 `<span><span>文字</span></span>`，这些包裹层没有任何标识；而外面那个按钮多半带着 `aria-label` 或 `data-testid`。

**修法**：目标自身只能退到结构路径时（score < 60），向上找最近的**可交互元素**（button / a[href] / [role=button] / 表单元素），且**必须确实更好认才换** —— 择优不是无脑上溯。只上溯到可交互元素而不是布局容器：回放点击取元素中心点，容器太大时中心可能落在别的子元素上。

实测由 `span > span > span` 变成 `button[aria-label="收藏此项"]`。

**顺带**：步骤页对 score < 60 的步骤标「⚠ 易失效」，让用户自己能看出哪几步是靠结构路径吊着的。

**沉淀（⭐）**

1. **事件的 `target` ≠ 用户的意图对象。** 用户点的是"按钮"，DOM 给你的是按钮里最深的那个文字节点。任何基于 DOM 事件做录制/埋点/热图的工具都要处理这层落差，否则记下来的全是无标识的包裹层。
2. **"精准"和"稳定"是两个问题，别混答。** 一个 11 层路径可以做到 100% 唯一命中（精准），同时 100% 活不过下次改版（不稳定）。用户问"精准吗"时，通常真正想知道的是后者。
3. **择优上溯 > 无脑上溯。** 只在自身不好认时才向上找，且新目标必须评分更高。一刀切上溯会把"点列表第 3 项"变成"点整个列表"。
4. **脆弱性要在 UI 上可见。** 分值藏在 JSON 里等于没有；标在步骤页上，用户才知道该给哪几个元素加 `data-testid`——那才是治本的动作。
