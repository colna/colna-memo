### 01:xx browser-replay：浏览器操作录制/回放 Chrome 扩展（新项目）

**需求**：录制点击 / 输入 / 聚焦等浏览器事件 → 回放自动重做 → 导出 JSON 带 DOM 选择器，**禁止用 class 选择器**。目标仓库 `github.com/colna/browser-replay`（当时为空仓库）。

**做了什么**：新建 `/Users/max/Dev2/zhangzheng/browser-replay`，MV3 扩展，无构建、无 npm 运行时依赖。

| 文件 | 职责 |
|---|---|
| `src/lib/selector.js` | 选择器生成/解析（本项目最核心）。多候选 + 打分 + 当场验证唯一性 |
| `src/lib/waiter.js` | 等待策略：MutationObserver + 轮询、可交互判定、两帧稳定 |
| `src/lib/executor.js` | 动作执行：完整 pointer/mouse 序列、React 受控 native setter |
| `src/lib/export.js` | 导出格式（抽出来才能在 node 里断言） |
| `src/content.js` | 录制器 + 回放执行器，**不持有任何进度状态** |
| `src/background.js` | SW：录制会话 + 回放游标唯一权威，状态全落 `storage.session` |
| `src/popup/` | 列表 / 步骤查看 / 导出 / 导入 |

**「禁止 class 选择器」怎么落地**：优先级 `data-testid` → `id` → `name` → `aria-label` → 语义属性 → `tag:nth-of-type()` 结构路径。结构路径从最近的**有锚点的祖先**起，不从 body 一路 nth-child 到底。另外把 React `useId`（`^:r[0-9a-z]+:$`）、长 hex、纯数字开头、Radix/MUI/Ember 前缀的 id 一律判为不稳定，宁可降级到 name / 结构路径。

**验证（25 项断言全绿）**：
- `test/selector-test.html`（9 项）：真实 DOM 上验证全库无 class、动态 id 不采用、无标识节点退到 nth-of-type、候选唯一命中、shadow DOM 穿透
- `test/e2e.mjs`（16 项）：headless Chrome + CDP `Input` 真实鼠标键盘事件录制 → 回放 → **断言表单数据完全一致**

**遇到的问题 → 怎么解决**
1. **Chrome 150 禁用命令行 `--load-extension`**（flag 出现在 chrome://version 但扩展列表为空，无报错）。试过 `--disable-features=DisableLoadExtensionCommandLineSwitch`、`--remote-debugging-pipe`、预置 `developer_mode`、headful，**全部无效**。用 3 行的最小 MV3 扩展做对照，确认是浏览器限制而非自己 manifest 出错。改用 chrome API 桩把**未经改动的** content.js 装进普通页面跑。
2. **`npm i -D jsdom` 静默不装**（反复 `up to date` 但 node_modules 不存在）。放弃，改用 `chrome --dump-dom` 跑真 DOM 断言，零依赖。
3. **点 checkbox 被误录成一步「输入 yes」** —— checkbox 也会派发 `input` 事件，`el.value` 是 value 属性不是用户输入。这个 bug 是被 E2E 里「连续输入应合并成 2 步」这条**具体到值**的断言抓出来的，而「录到了 click / 有 input 类型」这类过程断言全绿。修法：`onInput` 排除 checkbox/radio/file。
4. **点提交按钮会同时录到 click + submit 两步**，回放时第一步点击已把页面带走，第二步找不到 form 必失败。修法：`onSubmit` 里若上一步是 200ms 内的 click 就丢弃。
