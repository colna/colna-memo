### 10:40 · sitin-rn：把 origin 从 GitHub SSH 改为 GitLab HTTPS

- **做了什么**：`git remote set-url origin https://gitlab.lumosolo.com/app-rn/sitin-rn`（原 `git@github.com:presence-io/sitin-rn.git`）；并在**仓库本地** config 加两条 rewrite 兜底，保证任何 SSH 写法都强制落回 HTTPS：`url."https://gitlab.lumosolo.com/".insteadOf = git@gitlab.lumosolo.com:` 与 `ssh://git@gitlab.lumosolo.com/`。
- **为什么**：用户要求仓库换到 GitLab，且**只准用 HTTPS 推拉**（不走 SSH）。
- **结果**：`git remote -v` 已指向 GitLab；`GIT_TERMINAL_PROMPT=0 git ls-remote origin` 报 `could not read Username` —— 远端是私有 GitLab，**本机还没有该站的凭据**。全局 `credential.helper = osxkeychain` 已在，第一次交互式 pull/push 输入用户名 + Personal Access Token 即会被钥匙串记住，之后免输。**未做**：没有嵌入 token，也没有改动任何全局 config（改动全在 `.git/config`，只影响本仓库）。
- **关键命令**：`git remote set-url origin https://…`；`git config --local --add url."https://gitlab.lumosolo.com/".insteadOf "git@gitlab.lumosolo.com:"`（两条 insteadOf 需用 `--add`，直接 `git config k v` 会覆盖前一条）
- **待办 / 提醒**：
  - 各 worktree 共用同一 `.git/config`，remote 变更对 `fix/luka-code-review` 等 worktree 一起生效；本地 `origin/feature/luka-ios` 等 remote-tracking ref 仍是 GitHub 那份，下次 `git fetch` 会连新站重取。
