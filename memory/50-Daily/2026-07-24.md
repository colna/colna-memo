## 工作日志 — 14:40 browser-replay 修「Instagram DM 录制回放失败」

用户拿一份 Instagram DM 的真实录制(10 步)报「输入步骤失败」,回放第 6 步报「页面上找不到该元素。已尝试：」(尝试列表为空)。查下来是**三个独立缺陷叠加**,已全部修掉并补回归测试。

**诊断**(先只读 JSON + 截图就定位到了)
1. 第 6 步 = `key` Enter,`selector: null`、`selectorFallbacks: []` —— 候选归零 → resolve 永远拿不到元素 → 等满 10s → `diagnose()` 遍历空数组,所以「已尝试：」后面是空的。
2. 根因:`push('structural', ...)` 默认走唯一性校验,Instagram 每层单子节点 → `nthOfType` 退化成裸 div → 12 层封顶后匹配上千个 → 被丢弃。注释写「一定能生成，作为保底」,与实现矛盾。
3. 更严重:整份录制**没有任何 input 步骤**,"hello" 没录进来。用户确认是**现场敲进去的** → 录制器漏录,不是操作问题。

**改动**(`browser-replay`)
- `selector.js`:新增 `nthChild()`;结构路径不唯一时退到逐层 `:nth-child`(封顶 12→30);两条都不唯一且别无候选时无条件塞一条(score 20);`push` 改为返回 boolean。
- `content.js`:新增 `editingHostOf()` 把待结算目标归一到 contenteditable 宿主(Lexical 重建内部节点导致旧节点脱离文档、读不到值);contenteditable 上打字时 keydown 也 `markPendingInput`;`key`/`keystroke` 定位不到**或只靠弱候选(score<55)命中**时退到 `document.activeElement`;零候选时超时从 10s 降到 2s。
- `executor.js`:`typeIntoEditable` 在合成 beforeinput 没人接管后,先逐键敲一遍再退到直写 textContent。

**验证**:`node test/run-all.mjs` 全绿(selector 16/16 + e2e 全过)。新增 harness fixture 复刻 Instagram 三重形态(14 层无标识 div 汤×2 条同构链 + window 捕获阶段吞掉输入事件 + 每次输入重建内部 `<p>`),e2e 断言:靠 keydown 录到输入、无零候选步骤、按键退到 activeElement、回放发出的不是空消息。selector 单测加「深层无标识节点不会候选归零」。

**踩坑**:第 2 条修复(非唯一保底)会**和第 3 条(activeElement 兜底)打架** —— 有候选就命中错元素,兜底反而不触发。所以规则定成「强候选才信任,弱命中让位焦点」。另:e2e fixture 里 contenteditable 默认高度 0 且在视口外,realClick 取中心点会点到别的元素,要给尺寸 + 先 scrollIntoView。

经验已沉淀到 `30-Resources/troubleshooting/ui-automation-selectors.md` 第四节。
