### 排查 — feature/pwa-ads:2000 状态 PENDING 但卡片不显示(诊断出 bug,改动已撤回)

- **现象**:`feature/pwa-ads` 上 `getCommonFinishedTasks`(实为 `ListUserCommonTaskResponse`,per-user 任务+status)返回 `taskId:2000 status:PENDING`,但 `PartnershipAdsCard` 不显示。用户问「是不是有缓存」。
- **结论:不是缓存**。`taskStore` 是纯内存 `create`(不 persist、无 localStorage),`refreshTasks` 每次重拉。
- **根因**:`hooks/useTask.ts` 的 `getFinishedTasks`(~231-238)把 `getCommonFinishedTasks` 返回的**每一条都当已完成**(历史:该接口原只返回 finished),`for (task of tasks) if (task.taskId) finishedTaskIds.push(...)` **不判 status**。后端现在连 PENDING 也返回 → 2000 被塞进 finished → `updateTasksStatus` 标 `TaskStatus.finish` → `PartnershipAdsCard` `visible=!!task && !isFinished` 判 `isFinished=true` → 隐藏。
- **类型**:`UserCommonTaskInfo.status` 是 `string`(值 `"FINISHED"`/`"PENDING"`,`user_api.ts:7568`);app-pwa 无共享 FINISHED 常量(cashout 里有独立的)。
- **拟修法(已写又撤回,未提交)**:`if (task.taskId && task.status === "FINISHED")` 过滤。用户让**撤回**,`git checkout` 还原,worktree 干净。→ **待用户定口径**(前端过滤 / 后端只返回 FINISHED / 其它)后再处理。
- ⚠️ 复用坑:`getCommonFinishedTasks` 语义已从「已完成列表」变成「用户任务+status 列表」,任何依赖它的地方都要按 status 过滤。
