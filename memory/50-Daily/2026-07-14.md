## 工作日志 — 08:43 排查「APK 从后台切回来输入框变低」+ 定方案(⏳明天做,可能换设备)

> **跨设备接手点。相关代码:前端 `sitin-next`、安卓 `GraceChat-Earn-Android`,均在 `/Users/max/Dev2/zhangzheng/` 下(换设备后路径可能是 `/Users/<user>/Dev2/zhangzheng/`)。**

- **状态前提**:安卓 ime 高度修复 PR [#84](https://github.com/presence-io/GraceChat-Earn-Android/pull/84) **已 merge** 进 `p/ljb/sitin4`(commit `ad63f9d9`,本地 base 已 ff 同步);前端 PR [#608](https://github.com/presence-io/sitin-next/pull/608)(分支 `personal/zz/pwa-apk-keyboard-navbar`)冲突已解决并推送。

- **新问题**:APK 键盘弹起状态下切后台 → 切回前台,输入框位置**变低**(被键盘工具栏盖住一截),不再贴键盘上沿。截图在飞书对话。

- **根因(已读代码定位)**:输入框上抬量 = `--kb-height − --nav-height`;变低 = `--kb-height` 变小。而 `--kb-height` 100% 来自安卓 `notifyKeyboardChanged` 上报的 `height`。安卓**只在「键盘动画回调」里 push 高度给 web**(`PWAWebViewFragment.kt:160-198`):
  - `onKeyboardAnimProgress` 逐帧上报 `min(typesInset.bottom, mStandardHeight)`
  - `onKeyboardAnimEnd` 上报 `getKeyboardHeight()` = **完整高度**(仅这一帧给完整值)
  - `onApplyWindowInsets`(`KeyboardHeightProvider.kt:287`)**不通知 web**,只更 `mStandardHeight` 就 `return CONSUMED`
  从后台恢复时,输入框仍 focus、系统直接把 insets 设成键盘终态、**不播放完整 IME 动画** → progress/end 正常序列没走完 → web `--kb-height` 停在偏小中间值(或旧值)。唯一必触发的 `onApplyWindowInsets` 又不 push web → **恢复路径缺一次「把完整键盘高度重推给 web」的动作**。

- **决定方案:纯前端 workaround(用户拍板——不想再发安卓版)**。前端没有独立键盘高度源(APK 里 visualViewport 不 resize),只能用 ①缓存的完整高度 ②输入框 focus 作「键盘是否弹着」代理。落点全在 `packages/app-pwa/src/utils/bridge.ts` 的 `notifyKeyboardChanged` handler(约 397 行)附近:
  1. handler 里累积 `lastKbFullHeight = Math.max(lastKbFullHeight, params.height)`(仅 `show` 时;用 max 防被恢复时的偏小中间值污染)。
  2. 加 `document.addEventListener("visibilitychange", ...)`:`visibilityState==='visible'` 时,若 `document.activeElement` 是 INPUT/TEXTAREA/contentEditable(键盘应弹着)→ 把 `--kb-height` 重设为 `Math.max(0, lastKbFullHeight - KEYBOARD_TOP_GAP)`;否则设 0。重设包一层 `requestAnimationFrame`。
  3. 时机若抖动,把重设改挂到 input 的 `focus` 事件 / 延后一帧,真机看效果再定。
  - **权衡**:纯前端优点 = 只发 PWA、快;缺点 = focus 是代理非权威,极端场景(切回来 focus 在但键盘没弹)会误抬。要 100% 稳才需安卓 `onResume`/`onWindowFocusChanged(true)` 里 `isKeyboardShow()` 为真时补推 `getKeyboardHeight()`——本次不走这条。

- **明天 TODO**:在现分支 `personal/zz/pwa-apk-keyboard-navbar`(或从最新 `feature/sitin4.0` 切)改 `bridge.ts` 实现上述方案 → `tsc`/`lint` → 真机验(切后台→回来输入框是否复位贴键盘;有无误抬)。`KEYBOARD_TOP_GAP=15` 常量已在 `bridge.ts:17`。

## 工作日志 — 10:11 语音消息跨端格式:app-pwa 优先录 AAC + webm 兜底转码

- **做了什么**:`sitin-next / app-pwa` 语音消息改为「优先录 AAC、录不出则发送前转码成 AAC」。新分支 `personal/zz/pwa-voice-aac-transcode`(从最新 `feature/sitin4.0` `f4224079b` 切)。**未 commit、未 push**。
- **根因**:语音格式没被前端固定——`MediaRecorder` 候选挑第一个支持的(原 `["audio/mp4","audio/webm;codecs=opus","audio/webm"]`)。iOS Safari / 新 Chrome / 新 Android WebView 录 `audio/mp4`(AAC),**老 Android WebView 落 webm/opus**。腾讯 IM `createAudioMessage` 不转码、不强制格式;官方文档(**IM 269/75316**)只对 **aac** 承诺「Android/iOS/小程序/Web 全平台互通」→ **webm 发给 iOS 原生端播不了**(iOS AVFoundation 不认 webm;iOS 15+ 的 WebKit `<audio>` 反而能播 webm,所以坑只在原生播放器侧)。
- **关键技术判断**:录不出 AAC 的设备 = 无硬件 AAC 编码器 → **WebCodecs `AudioEncoder` 同样编不出 AAC**(同一个 OS encoder)。唯一能覆盖的兜底是**软件编码的 ffmpeg.wasm**(自带 AAC 编码器,不依赖设备)。
- **改动(5 改 2 增)**:
  - `hooks/useVoiceRecorder.ts:8` 候选显式 AAC 优先(`audio/mp4;codecs=mp4a.40.2` 置顶)。
  - **新** `utils/audioToAac.ts`:懒加载 `@ffmpeg/ffmpeg`(dynamic import)+ 自托管单线程 core;`needsTranscodeToAac()` 正则判 + `transcodeToAac()` 用 `-c:a aac -b:a 64k` 转 m4a。
  - `pages/Chat/ChatFooter.tsx:138` voice `onSend` 改 async:非 aac/mp4 → `await transcodeToAac`,失败 `catch` 回退原 blob(不丢消息);`onSend` 本就 awaited(`ChatVoiceRecorder.tsx:256`)。
  - `vite.config.ts` VitePWA `globIgnores` 加 `**/ffmpeg/**` —— 否则 30MB wasm 被 SW 预缓存(maxFileSize 50MB),PWA 一装就下 30MB,毁掉懒加载。
  - **新** `scripts/copy-ffmpeg-core.mjs`:从 `node_modules/@ffmpeg/core/dist/umd` 拷 `ffmpeg-core.js/.wasm` 到 `public/ffmpeg/`;`package.json` dev/build/prod 全部串 `copy:ffmpeg-core`;`.gitignore` 排除 `public/ffmpeg/`(30MB 不入库);`@ffmpeg/core` 放 **dependencies**(非 devDep,Vercel `--prod` 也要拷)。
- **验证**:`lint` 0、`build:dev` exit 0;worker chunk 正常 emit(`dist/assets/worker-*.js`)、`dist/ffmpeg/` 到位、SW 预缓存**不含** wasm、`vite preview` curl `/ffmpeg/ffmpeg-core.{js,wasm}` = 200 + `application/wasm` 类型正确。
