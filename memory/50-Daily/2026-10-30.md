## 工作日志 — 12:24 SmartReply 点 IG Reconnect 闪退定位

- **现象**: SmartReply（smart-replay-android 1.1.3）PWA 登录完成后，点 Instagram 的 Reconnect 立刻闪退。
- **定位**: 连真机 `adb logcat -b crash` 拿到堆栈：`Process: smart.reply.android:socialweb` → `Unable to start activity ...SocialLoginActivity` → `IllegalStateException: You need to use a Theme.AppCompat theme (or descendant) with this activity.`，崩在 `SocialLoginActivity.onCreate` 的 `setContentView`。
- **根因**: `SocialLoginActivity` 继承 `AppCompatActivity`，但 `AndroidManifest.xml:122` 给它的是 `@style/Theme.SmartReply`（`android:Theme.Material.NoActionBar`，非 AppCompat）；AppCompat 在 `ensureSubDecor` 里直接抛异常，`:socialweb` 进程崩溃，用户看到的就是闪退。和 PWA 登录态无关，只要走到「打开登录 WebView」就崩。
- **修法**: 把该 Activity 的 theme 换成已有的 `@style/Theme.SP`（parent `Theme.AppCompat.NoActionBar`），或让 `Theme.SmartReply` 继承 AppCompat；最小改动是前者，未改代码待确认。
- **沉淀**: `30-Resources/troubleshooting/appcompat-activity-theme-crash.md`。

## 工作日志 — 14:13 SmartReply Quick Login 卡登录页 + develop 分支核对

- **develop 核对**: `git fetch` 后发现本地 develop 落后 2 个提交；`07513e9 fix(sociallogin): 修复社媒登录页 AppCompat 主题崩溃` 已把 `SocialLoginActivity` 主题改为 `@style/Theme.SP`。之前定位的 Reconnect 闪退在最新 develop 已修复；真机装的 1.1.3 是修复前构建，需要重装新包。`fba1ad4` 是 Quick Control 悬浮球，与 Quick Login 无关。
- **Quick Login 现象**: 真机 `app-test3` 上点 Quick Login，`FastLoginRequest` 返回 200、token 和 `userState=FullRegister` 都已写入，但页面停在 `/onboarding`。抓 React fiber 确认 `useUserStore.isReady=false`，`useAuthNavigation` 因此不跳转。
- **根因链**: 冷启动无 PWA token 时 `onRehydrateStorage` 走 `syncLoginFromNative()`，要等 `spBridge.getLoginInfo` 才置 `isReady`；但 SmartReply 的 `WebViewJavascriptBridge.js` 在 `onPageFinished` 才注入，`initBridge` 只监听一次 `PwaBridgeReady`，错过事件后 `init()` 永不执行，`spBridge.callHandler` 报 `Cannot set properties of undefined (setting 'src')` / native 报 `spBridge._handleMessageFromNative is not a function`。重启后桥在 ~28s 才 inited，恢复流程被拖长；Quick Login 成功本身不置 `isReady`，所以手动登录也解不开。
- **修法建议**: app-pwa 登录成功时补 `isReady=true`（或 `setUserInfo` 里置）；`onRehydrateStorage` 用 `setState` 而不是直接改 state；`connectWebViewJavascriptBridge` 补 `WVJBCallbacks`/轮询兜底；缩短 native 恢复的超时与次数。Android 侧可考虑更早注入 JS 桥。
- **验证**: CDP（`adb forward tcp:9333 localabstract:webview_devtools_remote_<pid>`）复现 116s+ 仍 `isReady=false`；正常重载后 `spBridge.inited=true`、`ping` 返回 pong。未改业务代码。
- **沉淀**: `30-Resources/troubleshooting/pwa-login-stuck-isready-bridge.md`。
