### 02:00 — 分析 koda Storylines 页 console 日志（663 行）

- **结论**：**R00220「like 与访客数据没接入」证伪**。三个接口 12 次请求全部 `code=1`，零失败：`GetMatchLikedList` totalLikedUserCount=31 + 真实用户；`GetVisitorList` visitorRecentCount=18 / repeatVisitorCount=3 + 32 KB 真实数据；`GetNewVisitorCount`=31。数据都在，只是被 `likedGated`/`visitorGated` 锁着（模糊 + Unlock），而解锁去的付费墙正是空的 R00218 → 三条 bug 一条根因链。
- **新发现（真问题，未修）**：**冷启动进 Storylines 会白拉一遍两个列表**。日志里 `limit:20` 的 GetMatchLikedList 和 GetVisitorList 各 2 次、成对出现（`useVibesLists.load` 的 `Promise.all` 顺序）。根因在 `hooks/use-vibes-refresh.ts:45-50`：`const previous = useRef(visitorUnread)`，冷启动时 store 初值是 0（`stores/vibes-unread.ts:56`），第一次轮询回填 31 → `31 > 0` 被判成「访客数上升」→ 触发 reload。注释说的「Skips the initial value」只挡住「挂载时就非 0」，挡不住「挂载是 0、首次轮询才填」。代价是 `getScouted` **无分页全量拉**（本次 32 KB）白跑一次。修法：`previous` 初始化为 `null`、首次赋值不比较，或用 store 的 `visitorLoaded` 做门。
- **坑：截断的日志不能用来证明字段缺失**。行尾是 `…(+41465 chars)`，而 `totalUnreadLikedUserCount` 是 `GetMatchLikedListResponse` 的**字段 6，排在 `likedUserInfos`(5) 之后** → 必然落在被截掉的部分。`isUnread`/`actionStats`/`lastVisitTime`/`isMatch` 同理（都是嵌套字段）。差点据此下「未读数没返回」的错误结论 —— **先查 proto 字段号再判断字段是真缺还是被截**。
- **其它**：`use-vibes-counts.ts` POLL_MS=10s，停在该页每 10 秒打 2 个请求；`rn-trtc` 的 `addCallRechargePresenterListener` 刷了 3 次 NativeEventEmitter 缺 `removeListeners` 警告。

### 02:30 — 修 koda Storylines 冷启动重复拉列表（分支 `fix/koda-vibes-cold-start-refetch`，未提交）

- **做了什么**：三处改动 + 1 个新测试。
  - 新增 `apps/koda/src/lib/vibes-refresh.ts`：纯函数 `visitorCountRose(previous: number | null, next)` = `previous !== null && next > previous`。
  - `apps/koda/src/stores/vibes-unread.ts`：加 `countsLoaded`（初值 false，`refresh()` 结束置 true，`clear()` 复位）。
  - `apps/koda/src/hooks/use-vibes-refresh.ts`：`previous` 改为 `useRef<number | null>(null)`，effect 先 `if (!countsLoaded) return;` 再比较。
  - 新增 `apps/koda/tests/lib/vibes-refresh.test.ts`（3 例）。
- **关键判断（一开始想错了）**：只把 `previous` 初始化成 `null` **修不好** —— 挂载那一次 effect 就会把占位的 `0` 记成基线，下一次轮询的 31 照样判定为上升。客户端单靠计数值**无法**区分「0 是还没拉」和「0 是真的没有」，**必须由 store 给一个『这个数是不是答案』的标志**。这是这次修复的全部要害。
- **失败读的取舍**：`refresh()` 里两个请求 `.catch` 后会保留旧值，此时仍然置 `countsLoaded: true`。代价是「首轮失败」的少见场景下多拉一次；反过来把占位当真值则是**每次冷启动**都多拉一次。选前者。
- **验证**：lint 0 / boundaries ✓ / typecheck Done / koda:test **362 passed, 1 failed**（仍是 `config.test.ts` appName pre-existing）。
- **文档**：`docs/` 里没有描述 Storylines 刷新触发器的章节，该行为的真源就是 hook 自己的 JSDoc，已同步更新。
