### 02:00 — 分析 koda Storylines 页 console 日志（663 行）

- **结论**：**R00220「like 与访客数据没接入」证伪**。三个接口 12 次请求全部 `code=1`，零失败：`GetMatchLikedList` totalLikedUserCount=31 + 真实用户；`GetVisitorList` visitorRecentCount=18 / repeatVisitorCount=3 + 32 KB 真实数据；`GetNewVisitorCount`=31。数据都在，只是被 `likedGated`/`visitorGated` 锁着（模糊 + Unlock），而解锁去的付费墙正是空的 R00218 → 三条 bug 一条根因链。
- **新发现（真问题，未修）**：**冷启动进 Storylines 会白拉一遍两个列表**。日志里 `limit:20` 的 GetMatchLikedList 和 GetVisitorList 各 2 次、成对出现（`useVibesLists.load` 的 `Promise.all` 顺序）。根因在 `hooks/use-vibes-refresh.ts:45-50`：`const previous = useRef(visitorUnread)`，冷启动时 store 初值是 0（`stores/vibes-unread.ts:56`），第一次轮询回填 31 → `31 > 0` 被判成「访客数上升」→ 触发 reload。注释说的「Skips the initial value」只挡住「挂载时就非 0」，挡不住「挂载是 0、首次轮询才填」。代价是 `getScouted` **无分页全量拉**（本次 32 KB）白跑一次。修法：`previous` 初始化为 `null`、首次赋值不比较，或用 store 的 `visitorLoaded` 做门。
- **坑：截断的日志不能用来证明字段缺失**。行尾是 `…(+41465 chars)`，而 `totalUnreadLikedUserCount` 是 `GetMatchLikedListResponse` 的**字段 6，排在 `likedUserInfos`(5) 之后** → 必然落在被截掉的部分。`isUnread`/`actionStats`/`lastVisitTime`/`isMatch` 同理（都是嵌套字段）。差点据此下「未读数没返回」的错误结论 —— **先查 proto 字段号再判断字段是真缺还是被截**。

### 05:40 — Widget 方案定案：状态图 + 点击换图，写回 PRD

- **决策**（用户定）：放弃"组件里播视频"，改为**按 App 内状态显示不同静态图 + 点击换一张**。已替换 PRD 第四章原来那段笼统的降级说明，新增三个小节（一期规格 / 动效 / 素材要求），rev 8，16404 字符。
- **规格**：状态三态（有未读→提醒姿势／无未读有推荐→招手·往下指／都没有→待机）+ 点击从反应池取一张（鼓掌·竖大拇指·歪头眯眼·挠头）显示数秒后回落。点击 = iOS 17+ `Button`+`AppIntent`，写回共享容器再 `reloadTimelines`；**iOS 16 及以下没有交互式组件**，降级为深链打开小崽对话页。
- **WidgetKit 里真能动的只有三样**（其余全是快照）：`Text(date, style: .relative)` 自更新逐秒跳（无版本要求、不吃刷新预算）、`.contentTransition(.numericText())` 数字滚动（iOS 17+）、entry 之间的过渡动画自动补间（iOS 17+）。⛔ Timeline 排几十帧做翻书**不可靠**（时间点无承诺 + 扩展内存上限紧），不能写进验收。
- **素材两套、方向相反（重要，容易联调才发现）**：
  - **组件要静态 PNG**，随包进 Widget target 的 asset catalog，不走网络（组件渲染时间与内存都紧）；图片数 × 三档尺寸直接进包体，要控量。
  - **App 内五处露出要带 alpha 的动画**。现有设计交付是 `.mp4`，**mp4 没有 alpha 通道**，叠在聊天页/划卡页上会是一块带底色的方块。带 alpha 的 HEVC 是 iOS 独有、Android 要 VP9，跨端两套编码不值得 → 结论：**出动画 WebP 或 APNG**，`expo-image`（仓库 catalog 锁 57.0.1）直接播；GIF 能播但 256 色有白边、体积更大，别用。开屏成片不叠 UI，继续 mp4。
- **写原生代码不改变 WidgetKit 的天花板**：Widget 是独立进程的受限渲染环境，纯 Swift 手写能力完全一样。仓库里已有 iOS extension 注入先例可抄：`packages/rn-tim-push/plugins/notification-service.js:182` 的 `project.addTarget(TARGET, "app_extension", ...)`。`ios/` 不入库，手改 Xcode 工程会被 prebuild 覆盖，必须走 config plugin；加 target 属原生面变更，**不能 OTA**。
