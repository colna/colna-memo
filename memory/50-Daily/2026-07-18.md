### P1-1（我 refactor 引入的回归）：编排挂错层

- **根因**：`useVideoTipsCall` 原挂在 chat 页（`ActiveChat` 内）。接通后 `useWebCall` 会 `navigate("/video-call")`，而 `/video-call` 是 `/chat` 的**对等 Route，会卸载整个 `/chat` 子树** → hook 随之卸载：60s 限时 timer 在接通瞬间被 effect cleanup 清、结束时 onEnd 已不在 → **web 仍不在 1min 自动挂、奖励也丢**。
- **修法**：hook 改成**自包含、无 chat 依赖、无参数**，随 `CallControllers` 常驻挂在 App 根（新增 `VideoTipsCallController`，和 `MockCallController` 同级——平台无关、通话中不卸载）。自订阅全部通话事件；接通记 `beginTime` + arm 60s timer→`WebCallManager.hangup()`；结束按自记时长 `≥ LIMITED_CALL_MIN_PAID_DURATION_S`(30s) 判发奖，金额取发起时 `centsPerMinute`（`/100` 转美元传 startCall），金币动画走全局 `modalStore`（不经 chat 的 mountedRef gate）；接通前失败（拒接/取消/未接）走 `onAbort` 只复位不发奖，防 activeRef 泄漏误判下一通。

### P1-2（既有严重 bug）：native 主叫漏复位 isEnded

- **根因**：native `isEnded` ref 只在**被叫入口**（`handleNativeCallInvited`）复位，**主叫入口**（`handleOutgoingStart`）漏了 → 第 2 通及以后主叫，上一通结束置的 `isEnded=true` 残留，`handleNativeCallEnd` 被 `if(isEnded.current) return` 直接吞 → 订单结钱了但结算/发奖/导航回退全丢。web 的 `beginCallLifecycle` 两个入口都复位、native 只做了一半。
- **修法**：`handleOutgoingStart` 拿到 targetUserId 后补 `isEnded.current = false`。

### 值得记的判断

- **⭐ 挂载层决定生命周期**：`CallControllers.tsx:40` 二选一挂 web/native controller，**挂在这里的 hook 通话全程不卸载**（它是 `<AppRouter/>` 的 sibling，不随路由变）；挂在 `/chat` 里的 hook 一旦 `navigate("/video-call")` 就连同 timer/监听一起没。**凡「跨接通、跨导航要活着」的编排，必须挂常驻层，不能挂随路由卸载的页面。** 这正是我 refactor 时踩的坑——把限时从常驻的 useWebCall 挪进了会卸载的 chat 页。
- **native 无 hangup**：到点 `WebCallManager.hangup()` 在 native 是 no-op（挂断归 APK）。native 的限时挂断本 hook 不负责，是独立缺口（已在昨日 #646 body 记为 follow-up）。
- **web/native 两个入口的对称复位**：web `beginCallLifecycle` 抽成一处两入口都调、不易漏；native 是两处手写 `isEnded=false`，天然容易只改一处——这次补的就是漏的那处。
