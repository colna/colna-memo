### 03:40 — koda 注册流程两权限现象排查：定位页不弹 + 通知启动就弹（结论=旧包，未改码）

- **问题**：用户报 Android 实机两现象——①注册到地理位置页，预期直接弹权限弹窗，实际没弹；②通知权限在刚打开 app 启动页就弹，预期第一次进 chat 列表才弹。用户确认平台 Android、包「旧包/不确定」。
- **排查结论：两个预期行为代码里都已实现，且都是近期才加的，Android 旧包不含**。
  - ①定位：`onboarding-location-picker.tsx` 有 mount `autoLocate`（`ensureLocationPermission` → `requestForegroundPermissionsAsync` 弹窗，store `location` 初值 null 会触发）。该逻辑是 **PR #376 `a49d92a9`（2026-09-04）** 才加的。9-4 前的包没有它 → 进页不弹、只能手输 ZIP。
  - ②通知：koda **不用** device-push（那是 iris），只用 TIMPush `registerTimOfflinePush`，仅 `(tabs)/chat.tsx` 的 `useFocusEffect`（status==="ready"）触发；默认落地 tab 是 `index` 不是 chat。原生侧 `rn-tim-push/plugins/timpush.js` 的 `wireTencentPushApplication` 往 MainApplication.kt 的 `attachBaseContext` 注入 `TIMPushConfig.getInstance().setAutoRegisterPush(false)` + `enableRequestPostNotificationPermission(false)`（挡 TIMPush ContentProvider 在 RN 前的 Android 13 自动请求）。JS 延迟逻辑 `efe96f56`「defer notification prompt to opening Chats」是 **2026-08-19** 加的。8-19 前的包是老逻辑（注册期就请求）。
- **一度以为的真 bug（已证伪）**：timpush.js 第 313 行 `if (businessIdAndroid) { withAndroidConfig(...) }`——Android 全部 disable 注入被 FCM businessId gate 住。但 koda `eas.json` 三个 profile 都配了 `EXPO_PUBLIC_TIM_PUSH_BUSINESS_ID_ANDROID=46740`，gate 通过、注入会执行。**证伪，配置无缺失。**（潜在加固点：若某 app 没配 Android FCM businessId，disable 注入会整段跳过 → 那个 app 启动会弹 Android 通知权限。koda 不受影响。）
- **给用户的路径**：基于最新 `feature/koda-android` 出 Android EAS 包（9-4 之后），两现象应消失；两者均原生层改动、**不能 OTA**。新包仍复现再要启动阶段 TIMPush 实机日志深挖。
