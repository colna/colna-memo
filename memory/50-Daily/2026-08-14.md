## 工作日志 — 02:05 social-post 自建 Chrome MV3 扩展(替代 Tampermonkey,Phase F)

**背景**:用户不想依赖 Tampermonkey,问「能不能自己写浏览器插件」。定:建自己的 MV3 扩展,采集逻辑复用。

**做了什么**(social-post `extension/`,commit 0f654d5,已 push main):
- `manifest.json`(MV3):content script 注入 `www.facebook.com/*`;`permissions:["storage"]`;`host_permissions:["http://localhost/*","http://127.0.0.1/*"]`。
- `content.js`:搬 `fb-collector.user.js` 全部采集/解析逻辑,GM_* → chrome.storage.local(配置)+ chrome.runtime.sendMessage(POST 转发)。
- `background.js`:service worker 收 `{type:'ingest'}` 做跨域 fetch。
- `popup.html/js`:配置 server API 基址 + ingest token,存 chrome.storage.local。
- docs/06 补 Phase F + 安装步骤。旧 userscript 保留作备选。

**结果**:node --check 三个 JS + manifest JSON 全过。server 零改动(DTO 已收 shareCount/externalId;whitelist 只剥离不报错)。

**关键机制/沉淀**:
- **content script 与页面同源**,同源 `fetch('/api/graphql/',{credentials:'include'})` 浏览器自动带 httpOnly cookie(httpOnly 只挡 JS 读 document.cookie,不挡网络附带)→ GraphQL 采集可在 content script 跑,不需注入页面。
- **唯一跨域** = 打本地 server:content script 直打会被 CORS 拦 → 交 background service worker,有 host_permissions 的扩展请求**绕过 CORS**,所以 server 无需开 CORS。
- 部署到远端 server 时需在 manifest `host_permissions` 加对应 host。
- 装法:chrome://extensions 开开发者模式 → 加载已解压 → 选 extension/ 目录。
