## 工作日志 — 02:5x 修复 PWA 语音在老 iOS「零时长首帧」拒播(方案 C:探测后条件转码)

**背景**:PWA 语音在老 iOS(15.x)偶发无法播放。此前已 debug 定位根因(见截图分析):部分 WebKit/MediaRecorder 产出的 fragmented MP4 会把第一个 AAC sample 的 `duration` 写成 `0` → DTS 重复;FFmpeg/新 iOS 能容错,iOS 15.8.4 的 `AVAudioPlayer` 拒播。发送端 `ChatFooter` 原逻辑对 MP4 **原样透传**,只有 webm 才转 WAV,坏文件一路直达 TIM。

**做了什么(方案 C:正常 MP4 保小体积、仅坏文件转码)**:
- `packages/web-util-media/src/audioUtils.ts` 新增 `hasZeroDurationFirstSample(blob)`:纯字节解析 ISO-BMFF,`moof→traf→trun` 读首个 sample 的 duration 是否为 0。只读不改;解析失败/非该结构/无 per-sample duration 一律 `false`(按正常处理)。附最小 box walker(`readMp4Boxes`/`findFirstTrun`)。
- `index.ts` 导出该函数。
- `ChatFooter.tsx:onSend`:webm/opus 仍转 WAV;MP4 家族先 `hasZeroDurationFirstSample` 探测,命中坏首帧才走 `convertWebMToWav` 转 WAV,正常 MP4 保持 AAC 原样发(不增体积)。
- `convertWebMToWav` doc 更新:说明它其实与容器无关(`decodeAudioData` 重编,丢弃原 sample table),故也用于规避坏 MP4。
- `index.test.ts` 加 3 个用例(合成 ftyp+moof(traf(trun)) 字节流):坏首帧=true / 正常=false / 非 MP4=false。

**结果**:`pnpm --filter @heyhru/web-util-media test` 11 passed;两包 `lint` Done 无 error。未提交(等用户)。

**沉淀**:坏首帧判据 = fragmented MP4 首个 trun sample `duration==0`(DTS 重复),不是扩展名/编码/下载问题;浏览器无可靠 AAC 编码器,发送端唯一普适的「重编规避」是 `decodeAudioData→WAV`。
