### 工作日志 — Snapchat DM 监听加去重键日志 + 上传 dev v111

- **背景**:排查一份 SC-Scraper 控制台日志(女号 `yy-668899` → 男号 `cc-bo88`,20 分钟)时,用户问「为什么最后一次没上报 NEW_MESSAGE」。
- **结论(机制,非 bug)**:`startDMListener.js` 的 NEW_MESSAGE 是**「会话未读边沿 + 跨 reload 去重」**触发,不是每条消息触发。
  - 未读判定按会话维度;`getChatMessages` 打开会话会把整会话标记已读 → 未读归 0。已未读、未读期间连发多条(日志见 `newMessages:3/4`)只算一次。
  - **跨 reload 去重**(`:290-345`):后端 `navigateToInbox` 整页刷新会清空内存快照,故把「已报未读标识」持久化到 `sessionStorage["__sc_dm_reported"]`,键 = `reportedKeyOf(t)= status + "|" + timestamp`;`reported[chatId] === key` 则跳过不报,专防「同一条挂着不清的 Snap 每次刷新被反复上报」。
  - **最后一次没报** = 该未读 `status|timestamp` 与上次已报相同(内容没变)→ 命中去重跳过(前 5 次同会话反复上报是因男号每次又发新消息、timestamp 变了 → 新键 → 视为新增)。**不是日志截断**:上报是同步的、会在「chatlist listener 已启动」之前打印。
  - **隐患**:去重键含 timestamp,`未接来电` 那条 timestamp 为空 `""` → 键退化成 `"未接来电|"`,同类型易撞键漏报。
- **改动**:`packages/app-ins-scripts/src/snapchat/actions/startDMListener.js` `diffAndReport()` 循环里,对每条未读打印 `未读 <nick> key=<status|timestamp> 已报=<旧key> → 跳过(去重命中)|新增`,让去重判断可观测(之前完全静音,库里存的键/命中都看不到)。
