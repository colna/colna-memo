### 10:15 评估「独立站埋点」25 个点位在 purevell-webapp 的可行性

- **来源**：飞书 sheet `H4wFs6L37hAalMtyNXqcmGAEnKd` / `ATO2yt`「独立站埋点」，共 25 个事件（10 个 P0）。
- **结论**：12 个可在主题内直接埋；4 个只能走 Shopify Web Pixel；3 个服务端 webhook 可埋；2 个只能部分映射；4 个当前拿不到（payment_method_select、payment_failure、payment_cancel、order_receipt_confirm）。
- **依据**：主题已有 `snippets/byteplus-analytics.liquid` + `assets/byteplus-events.js`；Horizon 标准事件 `productSelect` / `cartLinesUpdate` / `cartError` / `cart:view` 够用。结账页不执行主题脚本（README 已注明），店铺 Basic 计划无 Checkout UI 扩展；Web Pixel 标准事件只有 `checkout_started` / `checkout_contact_info_submitted` / `checkout_shipping_info_submitted` / `payment_info_submitted` / `checkout_completed`，没有支付方式选择、支付失败/取消。
- **缺口**：`autotrack: true` 已带自动 pageview/click，新增 `e_web_page_show` / `e_web_link_click` 会双计；现有事件名 `product_view` / `add_to_cart` 等与新 `e_*` schema 不一致；`category_id`、`creator` / `attribution_id`、`checkout_id`、`payment_attempt_id` 需补来源或后端映射。
- **未做**：未改代码，等确认范围后再实施。
- **追加（能否全走 BytePlus）**：可以，BytePlus 只作统一接收端，但 4 个无数据源点位仍拿不到；checkout 不能用现有 Web SDK，Custom Pixel 若要直报需确认采集端点是否只认 app_id，否则走自建代理（`X-MCS-AppKey` 不能进前端）；DataFinder 事件属性不支持对象/对象数组，`items[]` 需拍平或转 JSON 字符串；服务端 HTTP API 需 AppKey，且要确认账号已开通。另建议 Web 单独建 BytePlus 应用，不要都灌进 `Earning_Android`。
- **服务端实测（11:00）**：sg 区正确上报地址是 `https://mcs.tobsnssdk.com/v2/event/json`（从 Rangers SDK 解出；Johor 的 `gator...` 对 1089134 / 653834 返回 `invalid appid`）。只带 `app_id` 发测试事件返回 200 `{"e":0,"message":"success","sc":1}`，且 `user-profile` 能查到测试用户（`app_channel=server_verify`）；但 `list-events` / `user-flows` 没有测试事件、`app_launch` 计数未变，事件维度没落。带 `X-MCS-AppKey` 时无效 key 直接报 `header.app_id = -1`，确认 AppKey 是事件入库必需项，与 app_id 不是一回事。
- **顺带发现**：`snippets/byteplus-analytics.liquid` 把业务渠道 `purevell_web` 传给了 SDK 的 `channel`，而 SDK 的 `channel` 是区域参数（只接受 `cn|sg|va`），不合法会回退 `cn` 并上报到 `mcs.volceapplog.com`。这很可能是 1089134 只有 App 事件、没有 Web 事件的原因；修法是 `channel: 'sg'` + `app_channel` 或自定义公参放业务渠道。未改代码，等确认。
- **支付段核验（11:15）**：店铺 Basic / HKD / Asia/Singapore；`shop.paymentSettings.supportedDigitalWallets` = SHOPIFY_PAY / APPLE_PAY / GOOGLE_PAY（基本可判定 Shopify Payments；`shopifyPaymentsAccount` 缺 `read_shopify_payments` scope 读不到）。全店 0 订单、0 退款、0 条 webhook subscription；webhook topic 里 `ORDERS_PAID` / `REFUNDS_CREATE` / `ORDERS_CANCELLED` 存在。`payment_info_submitted` 可拿 `checkout.token` / lineItems / totalPrice / shippingLine，但 `transactions[].paymentMethod` 文档注明可能只在 `checkout_completed` 才有。结论：`e_payment_submit` 只能 pixel→自建代理→BytePlus；`e_order_pay_success` 走 `orders/paid`；`e_refund_success` 走 `refunds/create`；`e_checkout_payment_method_select` / `e_payment_failure` / `e_payment_cancel` 没有数据源，Shopify Payments 不提供失败/取消 webhook，不能用 abandoned checkout 推断。另：所有 variant `sku=null`、`category=null`，订单行参数会缺 SKU/类目。
- **webhook 接法（11:35）**：链路是 Shopify → 自建 HTTPS 接口 → BytePlus，不能直接填 BytePlus 地址。建议在 Shopify 后台建 custom app，scope `read_orders` + `write_webhooks`（订单类 topic 还要 protected customer data），拿 Admin token + API secret；用 `webhookSubscriptionCreate(topic, uri)` 注册 `ORDERS_PAID` / `REFUNDS_CREATE` / `ORDERS_CANCELLED` / `FULFILLMENTS_UPDATE`。接收端必须保留 raw body 验 `X-Shopify-Hmac-Sha256`，用 `X-Shopify-Webhook-Id` 去重，5 秒内回 200，重活异步；失败 Shopify 重试 8 次 / 4 小时，连续失败会自动删订阅。本地测试用 cloudflared/ngrok，Shopify 不接受 localhost。落点二选一：独立 `apps/purevell-webhooks`，或在 `hermes-server` 加 `@Public()` + `rawBody` + `@SkipThrottle()` 的 ShopifyWebhooksModule。未改代码。
- **非主题埋点教程（12:05）**：新增 `apps/purevell-webapp/docs/analytics-non-theme.md`（约 950 行），并在 README BytePlus 段落加入口。文档覆盖 13 个非主题点位：checkout pixel 4 个、webhook 3 个完整 + 2 个部分、4 个平台不支持；含 custom app/scopes、Fastify+Postgres 示例、raw body HMAC、`X-Shopify-Webhook-Id` 去重、orders/paid / refunds/create / orders/cancelled / fulfillments/update 映射、BytePlus HTTP API 发送、items 扁平化、测试清单和常见错误。未提交。
