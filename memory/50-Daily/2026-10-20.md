## 工作日志 — 11:26

**IG profile biolink 未登录抓取方案验证（shangbin2026 实测）**

- **做了什么**：跑通「预热 cookie + 随机 `ig_did` + 拉 profile HTML → 解析 bio_links」方案，目标 `wa.me/48888800000` 命中。
- **关键发现**：
  - 本机 Clash mixed port 是 `7897`（不是脚本里的 `7890`）；且不挂代理直连也能 200。
  - **必须先访问首页拿 cookie**：不带 jar 直接拉 profile 只返回 ~135KB 无 profile 数据的壳（`bio_links` 不存在）；带 jar 后 ~160KB 且含 `username/biography/bio_links`。
  - `"url":"(https:[^"]+)"` 全页正则太宽，会把 `static.cdninstagram.com/rsrc.php` 一堆资源算进来；应精确解析 `"bio_links":[...]`（数组元素含 `url` / `lynx_url`，`lynx_url` 里是 `\u00253A\u00252F` 二次转义）。
  - `external_url` 字段对 `instagram`/`nasa` 已为空，现在统一走 `bio_links`，兜底不要只依赖旧字段。
  - 判定要区分「抓取失败」与「未命中」：用 payload 里是否存在 `"username":"<u>"` 做成功校验，避免登录墙/429 被误报成没有链接。
  - 子串匹配有误判风险（`wa.me/48888800000` 会命中 `...0001`），应按 host+path 归一化后精确比较。
- **产物**：`/tmp/ig_bio_check.sh`、`/tmp/ig_probe.sh`（临时脚本，未入库）。

## 工作日志 — 11:45

**IG 同 IP 高频是否触发登录墙：实测否定，真正变量是请求头**

- **实测**（Clash 7897，同一 IP）：18 次 @1s、30 次 @0.15s、60 次全速（85s）、12 并发（完整浏览器头）→ 全部 `200` 且 SSR payload 正常，无 429 / 登录墙，累计约 130 次/10 分钟。
- **关键纠正**：`sec-fetch-dest/mode/site/user` + `accept` 缺失时，**同一账号顺序单发也会拿到 135KB 空壳**（无 payload）；补上后 12 并发全部 15.5w+ 正常。之前把 `nintendo`/`steam`/随机不存在账号的空壳误判成限流。
- **判定口径**：统一用 HTML 是否含 `"username":"<u>"` 判「抓到」，否则报「无 SSR/抓取失败」，不要报「无链接」。
- **脚本**：`/tmp/ig_burst.sh`（顺序压测）、`/tmp/ig_par2.sh`（并发压测）。
