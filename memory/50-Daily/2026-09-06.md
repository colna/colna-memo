## 工作日志 — 00:05 koda 聊天键盘改「一步抬升」不掉帧方案(放弃逐帧跟手)

- **背景**:真机上 koda 逐帧 transform(KeyboardStickyView)升降仍卡,即便加了 memo 隔离 + renderToHardwareTextureAndroid。用户看了 Kira-Android(原生,ADJUST_RESIZE 一步 resize、输入框先到位再键盘滑上来)问能否照用。**结论**:koda(Expo SDK 57 默认 edge-to-edge)用不了平台 adjustResize——koda docs/09-report.md 记录 R00272/R00278:edge-to-edge 下 Android adjustResize 不再压缩 RN 根视图、键盘避让全失效,才改用 keyboard-controller。Kira 能用是因它是原生非 edge-to-edge。用户确认要「不跟手但稳定不掉帧」。
- **做了什么**(commit `28a320df`,`feat/koda-ce`):在 keyboard-controller 体系内做「一步抬升」——① 去掉 `KeyboardStickyView`(逐帧 transform 是卡顿根源)② 用 `useKeyboardHandler({ onStart })`(键盘动画**开始**瞬间即带目标 height)+ `runOnJS(setKeyboardInset)` 一次性 setState ③ composer 外层包一个 `<View style={{ marginBottom: keyboardInset }}>`(Android),一次 layout 把 composer 顶到键盘上沿、列表 flex:1 随之收缩;iOS 不变(KAV padding,inset 恒 0)④ 列表 bottomPadding 去掉键盘项(列表真收缩了)⑤ 删 renderToHardwareTextureAndroid / stickyOffset / KEYBOARD_GAP import。
- **观感**:输入框在键盘动画开始时一步跳到位、键盘滑上来(≈Kira);因只一次 setState + 一次 layout、无逐帧 transform/重绘,**结构上不会掉帧**(代价:不跟手)。
- **结果**:biome/typecheck/boundaries 全过;koda test 294/295(唯一失败 config.test.ts 既有)。**必须 EAS 真机验证**升降是否真的顺、以及切 gift/more 面板与 exchange dialog 场景是否正常(键盘/面板互切)。
- **沉淀**:Expo SDK 57 edge-to-edge 下,RN 键盘避让**只能靠 keyboard-controller**,不能退回平台 adjustResize/softwareKeyboardLayoutMode:resize(Android 失效,记录见 koda docs/09-report R00272/R00278)。要「不跟手但不掉帧」:`useKeyboardHandler.onStart`(动画起点即给目标 height)+ 一次性 marginBottom,是逐帧 transform 卡顿的替代解;`onStart` 比 RN 原生 `keyboardDidShow`(动画结束才触发)更早,能得到「输入框先到位」的观感。

## 工作日志 — 00:20 koda 礼物弹窗加 loading 态(先弹后加载)

- **背景**:用户觉得礼物弹窗弹起卡顿,要求「先弹起 loading,不要等接口再弹」。核查后:GiftSheet **本就是先弹出、再异步 `fetchGifts`**(不等接口),`fetchGifts` 有模块级 `cachedGifts` 缓存,首屏用 `cachedGiftCatalog()` 初值;且 GiftSheet 是**常挂载**(visible 切换,非 lazy mount)。真正问题是:**首次打开无缓存时显示空态 "No keepsakes here yet",fetch 回来再跳成网格**,像"在等接口"。
- **做了什么**(commit `dbfaffc1`):`gift-sheet.tsx` 加 `loading` state——`visible` 变 true 时 `setLoading(cachedGiftCatalog() == null)`(只有从没缓存过才 true),fetch 完 `setLoading(false)`;ScrollView 内容改成 loading→`ActivityIndicator` / 空→文案 / 有→网格 三分支;加 `active` 标志防卸载后 setState。
- **效果**:首帧只画转圈(比首帧铺整个网格更轻,开屏也更顺);有缓存的后续打开仍瞬间出网格。
- **沉淀**:「弹窗弹起卡/像等接口」先分清两件事——①是否真的 await 接口后才弹(本例不是,已异步)②有没有 loading 占位(本例没有,空态被误读成等待)。加 loading 占位 + 首帧轻量化(不在开屏帧渲染重列表)通常就能解决「弹起卡顿」的观感。常挂载弹窗无 mount 成本,弹出动画归 heroui/gorhom。
