### 02:13 phone_call_message 按对端平台裁字段 → **PR [#693](https://github.com/presence-io/sitin-next/pull/693) 已 merge**（`personal/zz/pwa-callmsg-clienttype` → `feature/sitin4.0`，3 文件 +105 −45）

**需求**：安卓端解析 `phone_call_message` 不认 `status` / `duration`，对安卓对端不下发这两个字段，iOS 保持原样；平台取自 `FinishCallOrder` 响应的 `clientType`。

**⭐ 改动的难点不在裁字段，在时序**

原先 `finishCallOrder` 与 `sendCallEndedToPeer` 是**并行**的（关单 fire-and-forget，通话记录立即发）。而平台信息只有关单响应里才有 → 通话记录必须排到关单之后。新增 `takePeerClientType(finishing, 5000)`，**必须带超时**：`waitOrderClosed` 的注释早写明关单会挂起（弱网/后端不响应），而通话记录是会话里唯一的通话痕迹，**晚发可以、不发不行**。超时按「未知」处理 → 走 iOS 口径 = 改动前行为。

**⭐ `TYPE_UNKNOWN` 的枚举值是 0** —— 必须 `=== ClientType.ANDROID` 严格比较，写成 truthy 判断会把「未知」误判成安卓、把 iOS 的字段也裁掉。已用 7 条 payload 用例覆盖（ANDROID / IOS / PC / TYPE_UNKNOWN / undefined ×  taskId 有无）。

**连带影响**：videoTips 删卡（`VIDEO_TIPS_CALL_RECORDED` 在消息发送成功后 emit）随之延后，最坏 5s。另外 `takePendingVideoTipsTaskId` 是一次性取走，取走时机也推后了 5s —— 理论上存在「5s 内又发起一通 videoTips 通话导致 taskId 串号」的窗口，实际要用户关弹窗→回聊天→点卡片，不现实，未做防护。

**⚠️ 待后端确认的假设**：`FinishCallOrderResponse.clientType` 的生成注释写的是「**接口调用方**的 client_type」，而本 PR 按「**对端**平台」用它（需求如此）。本地 `.proto` submodule 里该响应还只有 `code`/`message`，比 `gen` 旧、对不上。已写进 PR 描述请后端确认。

**验证**：tsc + lint + circular 通过；payload 逻辑 7/7。**无运行时验证**，需真机确认安卓端收到的消息确实不含这两个字段。

### 07:23 browser-replay 修「自绘编辑器录不到输入、回放发空消息」（未提交）

用户发来一份 20:10 在 Snapchat Web 的真实录制（15 步）让我分析，结论是**这份录制回放不出来**，用户确认。修完两关。

**症状** —— 15 步里 `click×4 / focus×3 / blur×3 / scroll×3 / key×1 / navigate×1`，**一条 `input` 都没有**，可 `text` 字段明明从 `"hi"` 变成 `"hello"`。回放时**每一步都报成功、消息却是空的** —— 比报错更难发现。

**⭐ 根因一：`beforeinput` 被 preventDefault，浏览器就不再派发 `input`**

Lexical / Draft.js / SC 输入框这类自绘编辑器的标准做法：`beforeinput` 里 `preventDefault()` + 自己写 DOM。只监听 `input` 的录制器完全瞎掉。`content.js:84` 明明处理了 contenteditable，却从来没被调用过。

修法：加监听 `beforeinput`（**无论页面是否 preventDefault 都会派发**，是唯一还能观测到的输入信号）；并把「事件里读值」改成**结算时才读**（beforeinput 触发时内容还没落 DOM，当场读只能读到旧值）。再加一层 focusout 兜底：值 ≠ 聚焦时基线就补一条（覆盖表情面板这类纯 JS 塞值，连 beforeinput 都没有）。用 `WeakMap` 记「已录入的值」，顺带修掉一个既有毛病：点进点出、值没变也会记一步 input。

**⭐ 根因二：`execCommand('insertText')` 不派发 `beforeinput`**

回放侧原来是 `el.textContent = value` —— 自绘编辑器的真源是内部 model，DOM 只是渲染结果，直接写它收不到，发送时读的还是空 model。我先改成 `execCommand('insertText')`，**仍然失败**。写探针实测：

```
execCommand('insertText') → ret:true, text:"hi", fired:null   // beforeinput 没派发！
```

它直接改 DOM，效果等同直写 textContent。**正确通道是 `beforeinput` 本身** —— 编辑器就在那儿接管输入，所以合成一个喂给它：`dispatchEvent` 返回 false（被吃掉）= 编辑器接管了，此时**绝不能再碰 DOM**，否则两边状态打架。

**回归** —— 兜底逻辑把 `select` 的值变化也记成了 input（它本该只由 change 记成 `select` 步骤）。抽 `canRecordValue()` 给标记和兜底两处共用。

**验证** —— 新建自绘编辑器 fixture（`beforeinput` preventDefault + 内部 model 渲染 DOM + 发送读 model，与 SC 同构），独立录一段不动原有步骤序列。**45 条全过**（原 39 + 新增 6）。改前该 fixture 精确复现了两个失败。

**改了什么**：`src/content.js` +78/−18、`src/lib/executor.js` +51、`test/e2e.mjs` +54、`test/harness.html` +75。**未提交**（按约定等用户发话）。

**残留**
