### 工作日志 — 11:26 Luka 划卡刮层：预置清晰区不再「先整卡糊、再跳清晰」

- **现象**（用户报）：卡面预置的随机清晰形状出现得慢 —— 先看到完整模糊蒙层，过一会儿才跳出随机刮开的那块。
- **根因**（两处叠加）：
  1. 预置区的洞放 `useEffect` 里 `setHoles(cells)`：effect 在首帧画完之后才跑，必然先渲染一帧「整卡糊」再跳成清晰区。
  2. 清晰区是靠 `<SvgImage>` 在 SVG 里**另画一份照片副本**：react-native-svg 的图片管线与卡片的 `expo-image` 不共享缓存，冷卡要等第二次下载/解码回来，清晰区才真的可见 —— 这才是「有点慢」的主因。
- **改法**（`apps/luka/src/components/discovery/frosted-scratch.tsx`）：反转图层 —— `BlurView` 整层铺满，用 `@react-native-masked-view/masked-view` 按洞的 alpha 把模糊挖掉，露出的就是卡片自己那张已经在渲染的照片（零额外加载、洞与手刮同源）。预置格子改为首次渲染同步 seed（`seeded` ref），`holes` 初值即 `frostedShapeCells(shape)`，删掉 effect。mask 用「白底 + 黑洞」经 SVG 亮度遮罩换算成「洞处 alpha=0」。组件不再需要 `photo` prop（`candidate-card.tsx` 同步去掉）。
- **依赖**：`@react-native-masked-view/masked-view@0.3.2` 直接写进 `apps/luka/package.json`（本就是 expo-router 的传递依赖，Podfile.lock 里已有 `RNCMaskedView`，**不需要重出 dev client**）；`pnpm install --lockfile-only` 只 +3 行。
- **结果**：iPhone X 模拟器冷启动录屏逐帧验证 —— 卡片出现时是占位灰（照片在加载），照片到位的**同一帧**预置清晰区一起出现，不再有「整张糊 → 后跳清晰区」的中间态；`Kat`/`Hunter` 截图上模糊/清晰边界正常，手刮洞与预置洞同一套圆。`luka:typecheck`、biome、`pnpm boundaries` 全过；`frosted-scratch-shape.test.ts` 的覆盖面用例此刻红（28.6% < 30%）—— 是并行会话正在调模板（`frosted-scratch-shape.ts` mtime 11:26 仍在变），与本改动无关。
- **关键命令 / diff**：`xcrun simctl io booted recordVideo` + `ffmpeg -vf fps=30` 抽帧；`pnpm --filter luka exec vitest run tests/lib/frosted-scratch-shape.test.ts`；`pnpm install --lockfile-only`。
- **沉淀**：SVG 图与 expo-image 不同缓存 → 任何「同一张图叠两层」的视觉都要避免用 react-native-svg 再画一份；要挖洞就用 `MaskedView` 把上层（模糊）按 alpha 挖掉，透出底层真图。Android 未验（本机 AVD 已删），MaskedView 走 DST_IN 位图，风险低。
