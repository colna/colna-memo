## 工作日志 — AIGC-Studio 参考图：内联 base64 + 多图 + 粘贴（feature/aigc-dev）

**起因**：用户要「参考图不走 OSS（上传慢、也不需要存）、支持多张、能直接粘贴」。仓库 `AIGC-Studio` 本地是浅克隆单分支，先修 refspec + `--unshallow` 才看得到 `feature/aigc`，从它切 `feature/aigc-dev`。

**改了什么**（7 个文件，未 commit）

| 文件 | 改动 |
|---|---|
| `api-clients/src/types.ts` | `Constraints.refImages` 加 `inline?: boolean`，声明该模型以 multipart 收图、参考图可直接内联 |
| `api-clients/src/drivers/gpt-image.ts` | `refImages` 从 `{max:1}` 放到 `{max:4, inline:true}`；`buildSubmit` 改成 map 全部 `input.images`，单张用字段名 `image`、多张用重复的 `image[]`，多张时文件名带序号 |
| `web/components/aigc/create-workspace.tsx` | `RefImages` 加 `inline` 分路：内联走 `inlineRef()`（>2MB 先 canvas 缩到长边 2048 再 JPEG/PNG 重编码）不传 OSS；加 window 级 `paste` 监听收剪贴板图片 |
| `worker/src/generation.ts` | 出图成功后 `dropInlineRefs()` 把 params 里的 `data:` 参考图抹掉，只留 `refImageCount` |
| `web/lib/generation-view.ts` | 参考图张数优先读 `refImageCount`，兜底 `images.length` |
| `web/app/api/generations/route.ts` | 重新生成时若 `refImageCount > images.length` → 400「参考图未留存」 |
| `api-clients/src/drivers/golden.test.ts` | 补多图 `image[]` + 超 4 张拦截两条用例 |

**关键判断**

- **`inline` 必须做成 per-driver 开关，不能全局改**。视频 driver（kling / seedance / novita）是把 `input.images` 原样塞进 JSON body 交供应方按 URL 回拉，喂 data URI 直接炸。只有 gpt-image 走 `/images/edits` multipart 才吃得下 base64。
- **base64 必须用完即清**。`create/page.tsx` 和 `requirements/[id]/page.tsx` 的列表查询在服务端 `select` 了完整 `params`（一次 50 条），若每条压着 2MB base64，SSR 直接被拖垮。张数移到 `refImageCount` 才能保住列表上「参考图 ×N / 图生图」的标注。
- **清了就不能原样重发**，否则「重新生成」会静默退化成文生图 —— 所以在 API 层挡掉并提示重新选图。失败记录不清，留着重试。
- 粘贴用 window 级监听而不是放置区 `onPaste`：div 不可聚焦收不到事件；只处理 `clipboardData.files` 里的图片，粘贴纯文本不带 files，不会误伤提示词输入框。

**验证**：`api-clients` 105 tests 全过；`api-clients` / `web` / `worker` 三处 `tsc --noEmit` 干净；改动的 5 个文件 biome 干净（`golden.test.ts` 与 `worker/generation.ts` 各有 1 条格式错，`git show HEAD:` 验过是预存的，没去动免得生无关 diff）。

**未验证的风险**：中转 `callapi.top` 是否透传多图（`image[]`）**没有实测** —— 本地无 `.env`／`CALLAPI_API_KEY`。之前验过支持 `image[]` 的是 muskapi，不是 callapi。上线前必须真打一发双图请求。
