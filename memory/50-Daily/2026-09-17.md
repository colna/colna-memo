## 工作日志 — 12:05 Luka 亲密度主页：真机红屏根因 = 缺原生模块时 `try/catch` 是假兜底

用户连续两轮「一进 pet 页就报错」。先按「bundle 是否自洽」排查：从 Metro 拉整包做了静态链接检查
（自己写的小工具：逐模块比对「具名访问 vs 依赖导出表」），pet 页这条链**零缺失导出**；报错点名的
`petInteractionAvailability` 是 10:52 删掉的符号、且全包无裸引用 —— 一度判断是 Fast Refresh 残留。
用户后来按下 **Copy** 给出真栈，真因是这个：

```
Uncaught Error: Cannot find native module 'ExponentPedometer'
  <global> (expo-sensors/build/index.js:1)
  loadAccelerometer (use-shake.ts:58)      ← 明明包着 try/catch
```

- **根因**：Expo dev Metro 的 `guardedLoadModule`（`@expo/cli/build/metro-require/require.js`）
  对**首次**模块初始化异常是 `ErrorUtils.reportFatalError(e)`（红屏）**然后吞掉** ——
  调用方的 try/catch 只能拦「第二次 require」，红屏躲不掉。`expo-sensors` 的 barrel 第一行就
  `import ./Pedometer`，后者在模块作用域 `requireNativeModule('ExponentPedometer')`。
- **修法**：`use-shake.ts` 改成**先探测再 require** —— `requireOptionalNativeModule("ExponentAccelerometer")`
