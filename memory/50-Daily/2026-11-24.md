## 工作日志 — 11:05 OpenCode 桌面端升级 v2（为手机 pair 做准备）

- **做了什么**：把 `/Applications/OpenCode.app` 从 1.19.6 升到 2.4.1（arm64）；旧版先移到 `/Applications/OpenCode-v1.19.6.app` 作回滚备份。
- **为什么**：用户要和手机 OpenCode app 配对，`opencode pair` 是 V2 独有命令；CLI 1.19.6 与桌面端 1.19.6 都没有。
- **结果**：下载官方 2.4.1 dmg（345,340,005 B），`shasum` 与官方 `0d69386b…40cea` 一致；`ditto` 覆盖安装，`codesign` Identifier `ai.opencode.desktop`、Team `5NZ4Q7NXJ4`，`spctl` = Notarized Developer ID；启动后进程正常，`CFBundleShortVersionString` = 2.4.1。
- **关键命令**：
  - `curl -fL -o /tmp/opencode-desktop-2.4.1.dmg https://opencode.ai/files/bin/2.4.1/opencode-desktop-mac-arm64.dmg`
  - `shasum -a 256` → 比对官方更新 API JSON 里的 sha256
  - `hdiutil attach -nobrowse -readonly` → `ditto /Volumes/OpenCode/OpenCode.app /Applications/OpenCode.app` → `hdiutil detach`
  - `osascript -e 'quit app "OpenCode"'` 先正常退出
- **沉淀**：见 `30-Resources/troubleshooting/opencode-v1-to-v2-upgrade.md`（app 内「检查更新」永远拿不到 v2 的根因）。

## 工作日志 — 11:12 修复 V2 桌面端启动报 EACCES

- **现象**：升级到 2.4.1 后 App 报 `Desktop IPC handler failed`，内层 `Server process exited with code 1`，`PermissionDenied: FileSystem.writeFile /Users/colna/.local/state/opencode/service.json.*.tmp`。
- **根因**：`~/.local/state/opencode` 属主是 **root**（9月14 某次 sudo 运行遗留，目录为空），普通用户无法写入 service.json。
- **修复**：`osascript -e 'do shell script "chown colna:staff ~/.local/state/opencode" with administrator privileges'`（GUI 授权），再重启 App。
- **验证**：`service.json` 已由 colna 写入（版本 2.4.1、url `http://127.0.0.1:49374`）；带 Basic auth 请求 `/api/info` 返回 200。
- **沉淀**：升级/安装 App 后如果只报权限错，先 `ls -ld` 检查 `~/.local/state` 下子目录属主，root 遗留目录会导致后台服务起不来。
