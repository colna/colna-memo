## 工作日志 — 14:07 装 V2 CLI（@opencode/cli 2.4.1）并验证 `opencode pair --remote`

- **做了什么**：`mv ~/.nvm/.../bin/opencode ~/.nvm/.../bin/opencode-v1` 保留 V1，再 `npm i -g @opencode/cli@2.4.1`。现在 `opencode` / `opencode2` = V2 2.4.1，`opencode-v1` = 1.19.6。
- **为什么**：`opencode pair --remote` 是 V2 命令（OpenTunnel 一次性配对链接 + 二维码），V1 1.19.6 没有该子命令，`opencode pair` 会被当成项目目录报 `Failed to change directory`。
- **npm 冲突**：直接 `npm i -g @opencode/cli` 报 `EEXIST ~/.nvm/.../bin/opencode`（V1 的 native 二进制不是软链），必须先挪走。
- **pair 实测**：首次开 remote 会重启共享 server，把发起它的 agent 会话一起杀掉 —— 前两次 tool call 被 abort、输出丢失。改成 `nohup ... &!` 分离进程写文件才拿到链接与二维码。验证：带密码 `curl /api/info` → 200，无密码 → 401。
- **安全结论**：V2 默认权限 `{action:"*",effect:"allow"}`，认证后等同本机 shell（能读 `~/.ssh`、`auth.json`、`service.json` 里的明文密码）。密码是自动生成 43 字符随机串，够强；隧道常开需手动 `service set remote false`。长期远程建议 SSH 转发或 Tailscale，而非公网 OpenTunnel。
- **关键命令**：`opencode service get remote` / `opencode service set remote false`；`~/.local/state/opencode/service.json` 有当前端口与 pid。
