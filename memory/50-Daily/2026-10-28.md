## 工作日志 — 11:15 磁盘清理（macOS）

- **做了什么**: 磁盘满（`/System/Volumes/Data` 425G used，仅剩 1.6G）按既有排查笔记清理：ToDesk 崩溃转储 132G、Xcode DerivedData + iOS DeviceSupport 34G、pnpm store 12G、npm/gradle 缓存、`~/Library/Caches` 约 10G、删除旧 iOS 26.5 模拟器 runtime。
- **为什么**: 系统盘 100% 占用，影响正常使用。
- **结果**: 释放约 206G，磁盘回到 52%（208G avail）。发现 ToDesk CrashReport 进程仍在持续生成 `.dmp`（清理后约 10 分钟新增 38 个、43M），不处理会继续增长。`~/.npm/_cacache` 残留 1.3G root 属主文件，无 sudo 删不掉。
- **关键命令 / diff**:
  - `find "/Library/Application Support/Todesk/dumps" -maxdepth 1 -type f -name '*.dmp' -delete`
  - `rm -rf ~/Library/Developer/Xcode/DerivedData/* ~/Library/Developer/Xcode/iOS\ DeviceSupport/*`
  - `rm -rf ~/Library/pnpm/store/v10 ~/Library/pnpm/store/v11 ~/.gradle/caches`
  - `rm -rf ~/Library/Caches/{ccache,Google/Chrome,CocoaPods,com.microsoft.VSCode.ShipIt,pnpm}/*`
  - `xcrun simctl runtime delete ADCF0482-9684-4538-83C8-FACD4EFCB106`（iOS 26.5）
  - `df -h /System/Volumes/Data`
- **沉淀**: 已更新 `30-Resources/troubleshooting/macos-disk-cleanup.md`（新增 ToDesk dumps 坑与命令）。

## 工作日志 — 11:25 卸载 ToDesk

- **做了什么**: 按官方卸载机制卸载 ToDesk：先 pkill 用户进程，再把残留 app 同卷移到废纸篓触发 `UninstallerWatcher`，官方 uninstaller 自动清理 LaunchDaemons/LaunchAgents、PrivilegedHelperTools、Audio HAL 驱动；最后用管理员脚本删 `/Library/Application Support/Todesk`、`/Library/Logs/ToDesk`，Finder 删废纸篓副本。
- **为什么**: ToDesk CrashReport 持续堆积 `.dmp`，清理后 15 分钟又新增 53 个，根因在 ToDesk 自身。
- **结果**: 组件全部移除，`pgrep`/`launchctl` 均无 ToDesk；磁盘 209G avail（51%）。剩 1 个 ToDesk_Service 诊断报告和疑似无关的 `com.todesktop` 偏好（232K），未动。
- **关键命令 / diff**:
  - `mv /Applications/ToDesk.app ~/.Trash/ToDesk_removed.app`（直接 `rm -rf` 会因 root:admin 755 失败，mv 可触发 Watcher）
  - `osascript -e 'do shell script "sh cleanup.sh" with administrator privileges'`
  - `osascript -e 'tell application "Finder" to delete item "ToDesk_removed.app" of trash'`
- **沉淀**: 已更新 troubleshooting 笔记的 ToDesk 卸载流程。
