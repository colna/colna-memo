## 工作日志 — 远程排查另一台 Mac 的 brew install ccache 失败

- **做了什么**:远程指导排查另一台 Mac(用户 `colna`)`brew install ccache` 全量失败,最终装上 ccache 4.14。无代码改动,纯排错。
- **现象**:7 个包进度条走到 100% 后整齐报 `rb_sysopen - No such file or directory`,指向 `~/Library/Caches/Homebrew/downloads/` 下的 bottle。
- **根因**:`HOMEBREW_BOTTLE_DOMAIN` = 阿里云镜像,镜像缺 bottle → 回退官方域名下载,但缓存路径仍按镜像 URL basename 推导(单横杠 `name-version`),而实际保存是双横杠 `name--version` → 下载存 A、解压开 B。Homebrew 6.0.10 有此 bug(本机 6.0.22 无)。
- **定位关键**:比对 `downloads/` 文件名横杠数 + 时间戳(只有 manifest json 是新的,tar.gz 全是旧日期 → tar.gz 没落盘)。
- **结果**:`env -u HOMEBREW_BOTTLE_DOMAIN -u HOMEBREW_API_DOMAIN brew install ccache` 通过;中途遇 `Cannot link ca-certificates`,`brew unlink` 后继续。`ccache 4.14` 已就位。
- **踩的弯路**:第一轮误把日志里的 `/Users/colna/...` 当成本机环境变量污染(本机是 `max`,无 `colna` 用户),按"HOME 被 export 坏了"给了方案。实际是**另一台电脑**的日志。教训:用户贴日志时先确认是哪台机器,别拿本机 `whoami` / `dscl` 的结果去反推。
- **遗留**:那台机器 `brew` 仍是 6.0.10,建议 `brew update` 升到 6.0.22+;`df -h /` 显示容器剩余仅 3.8Gi/460Gi,需清理。
- **沉淀**:新建 `30-Resources/troubleshooting/homebrew-mirror-cache-mismatch.md`(镜像回退缓存名不匹配 / link 冲突 / `df -h /` 看的是只读系统卷)。
