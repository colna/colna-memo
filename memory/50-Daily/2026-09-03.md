### 03:40 — location 变 Add 真因(靠真机网络日志定位,并入 #366)

- **现象**:改 height 保存后 Location 行显示 Add。前几版 merge-preserve 修复仍复现。
- **靠 console.log(网络日志)一锤定音**:height 编辑段 `EditProfileRequest{height:72}` → `UserInfoRequest{}` 返回的 `geoLocation` = `{country:"", region:"Murphysboro, IL", province:"", city:"", zipCode:"62966"}`。**后端把地名放在 `region` 字段,`city`/`province` 是空的**。注册响应(UploadUserInfoResponse)同样：`region:"Murphysboro, IL"`、province/city 空。
- **真因**:`toProfile` 的 `locationName` 只用 `[city, province].filter(Boolean).join(", ")` → 两个都空 → `""` → Location 行显示 Add。不是「后端不回 location」,是「地名在 region 字段,前端没读」。
- **修法**:`lib/user-profile.ts` 的 `locationName` 在 city/province 都空时回退 `geoLocation.region`。另把 `region` 加进 user.ts 的 `refreshHasLocation`。加 region 回归测试。`koda:test` 285 passed。
- **注意**:对端(GetMatchFeedsV3 里别的用户)的 `geoLocation` 是 `province:"Illinois", city:"Chicago"` 正常填充——**只有 self 的 UserInfoRequest 把地名塞在 region**。iris/lumi 的 toProfile 同样只读 city+province,若接同款后端也会中招(本次只改 koda)。

### 坑（沉淀）

- **Expo Router `Stack.Protected` 登录态守卫下，跨守卫组的路由导航会被吞。** koda 根布局按 `status`(guest/authed) + `profileComplete` 分组挂载屏；`router.replace("/login")` 在 authed 态下无效（login 组已卸载）。**要回到 guest-only 的启动页，必须改状态（`logout()`）让守卫重挂，而不是导航到那条路由。** 判断：目标屏在哪个 `Stack.Protected` guard 下，当前 status 是否满足该 guard；不满足则导航不会到达。
- **判断某页是否导航栈根**：看进入它的是 `push` 还是 `replace`；栈根的 Android 硬件返回无处可退会退桌面。
- **非交互 autosquash**：`git commit --fixup=<sha>` 后 `GIT_SEQUENCE_EDITOR=: git rebase -i --autosquash <base>`（编辑器设 `:` 空操作），可在无 `-i` 交互环境下把 fixup squash 进目标 commit。base 用 merge-base 避免撞上目标分支的新提交。
