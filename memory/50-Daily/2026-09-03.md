- **三修订(用户反馈「到达刻度时深色竖线应和浅色重合」)**:Android `snapToInterval` 会停在非精确位 → 固定橙线与滚动浅刻度错位。`onScrollEndDrag`/`onMomentumScrollEnd` 时 `scrollTo(offsetForHeight(height), animated)` 精确吸附;并按卡片 1px `borderWidth` 修正 `sidePad` 中心偏移(`(width - 2*BORDER - STEP)/2`)。
- **四修订(用户反馈「滚动卡住」)**:上一步的手动 `settle`(`onScrollEndDrag`/`onMomentumScrollEnd` scrollTo)会打断原生惯性/吸附,滚动发涩发卡 → **移除手动 settle**,只靠原生 `snapToInterval` 精确吸附(配合边框修正即对齐)。教训:别在 ScrollView 滚动结束事件里手动 `scrollTo` 去和原生 snap 抢,会卡。
- **五修订(用户反馈「滚动越多偏移越大」)**:累积漂移。根因:N 个 `width:STEP_PX` 的 flex 槽依次堆叠,每槽宽度各自取整到设备整像素、误差**逐槽累加**,而 `snapToInterval`/取值用精确 `STEP`,越滚越错开。修法:每个刻度改**绝对定位** `left = innerHalf - STEP/2 + i*STEP`(从原点算,误差恒 <0.5px、不累积)+ 显式 `contentContainerStyle` 宽高。**教训:等距刻度尺不要用 flex 堆叠固定宽度格,要用绝对 left 从原点定位,否则设备像素取整会累积漂移。**
- **六修订(用户又反馈「数值越大偏移越大」)**:进一步把 `snapToInterval` 换成 **`snapToOffsets`**(显式列出每刻度精确偏移 `i*STEP`,与刻度绝对定位同源),让吸附点逐像素对齐刻度,消除平台 interval 吸附 + 像素取整的残留累积偏移。**注意**:该修复(43771eb7 绝对定位 + 684272aa snapToOffsets)可能未进测试同学当时的构建——「数值越大偏移越大」正是旧 flex 版症状,需出含这两个 commit 的新包验证。

- 反馈:①交换联系方式弹窗(Share your <平台>)Android 下被键盘遮住,要上移;②弹窗背后聊天输入框跟着键盘上移。
- 根因:①`koda-exchange-handle-dialog.tsx` 用 RN KeyboardAvoidingView,`behavior` 仅 iOS,RN Modal 内 + Android edge-to-edge 不动;②`chat/[id].tsx` 的 KeyboardAvoidingView(keyboard-controller)对任何键盘都避让,弹窗键盘也抬聊天 composer。
- 改法:①弹窗改 `Keyboard.addListener`(show/hide)+ `Animated` translateY,升起时上移半个键盘高(在键盘上方重居中),两端通用;②chat KAV 加 `enabled={!exchangeHandle}`,弹窗开时不避让。
- **既有失败**:`tests/config.test.ts`(appName 期望 koda、实际 koda_android)在 base 上就挂(stash 掉我的改动仍失败),非本 PR 引入——base feature/koda-android 有人把 appName 改成平台后缀但没更新测试。我没动 config,未修(超范围)。已在 PR 注明。
- **经验**:RN `<Modal>` 内做键盘避让,别指望 KeyboardAvoidingView(iOS-only/Android edge-to-edge 失效);用 `Keyboard` 事件驱动 Animated 最稳。居中弹窗上移半个键盘高即可在键盘上方重新居中。
- typecheck/boundaries 过,koda test 294 passed(1 既有失败)。
