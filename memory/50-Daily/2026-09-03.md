### 02:50 — koda Edit Profile 保存 height 清空 location（并入 #365）

- **现象**:刚注册完 profile 有 location；改 height 保存回来后 location 没了。
- **根因**:#364 的 merge-preserve 覆盖了 displayName/age/gender/occupation/education/bio/height/interests，**漏了 location/locationName/zip**。改 height 走 `editProfile → refreshSelfProfile()`(preserveLocation=false)，`...mapped` 直接铺 `toProfile` 的 location；后端 `UserInfoRequest` 不回 `geoLocation` 时 `toProfile` → `location:null / locationName:"" / zip:""`，把本地 location 覆盖清空。（`preserveLocation` 段只在 `editLocation` 路径开，救不了 editProfile 路径。）
- **修法**:`user.ts` 把 location/locationName/zip 也加入 merge-preserve，以 `info.geoLocation` 是否返回为准：`location: info.geoLocation ? mapped.location : (current?.location ?? mapped.location)`（zip/locationName 同理）。尾部 `preserveLocation` 段保留（true 时覆盖）。加回归测试「改 height 且 refresh 省略 geoLocation → location 保留」。
- **验证**:lint ✅ / `koda:test` 281 passed。已 squash 进 #365 的 Edit Profile commit（fixup+autosquash），force-push。
- **补强(15:53 截图反馈「还是有问题」)**:原 `info.geoLocation` 真值判断只挡「省略」，挡不住后端返回**空 `geoLocation` 对象**（present-but-empty）。改为算 `refreshHasLocation = Boolean(geo?.city||province||zipCode||lat||lng)`，两种情况都保留本地 location。回归测试用 `it.each`（undefined + `{}`）覆盖。`koda:test` 282 passed。⚠️ 该修复仅在 PR #365 分支，**未合并、未出新包**——测试同学看到的仍是旧构建，需重新出包才能验证。

### 坑（沉淀）

- **Expo Router `Stack.Protected` 登录态守卫下，跨守卫组的路由导航会被吞。** koda 根布局按 `status`(guest/authed) + `profileComplete` 分组挂载屏；`router.replace("/login")` 在 authed 态下无效（login 组已卸载）。**要回到 guest-only 的启动页，必须改状态（`logout()`）让守卫重挂，而不是导航到那条路由。** 判断：目标屏在哪个 `Stack.Protected` guard 下，当前 status 是否满足该 guard；不满足则导航不会到达。
- **判断某页是否导航栈根**：看进入它的是 `push` 还是 `replace`；栈根的 Android 硬件返回无处可退会退桌面。
- **非交互 autosquash**：`git commit --fixup=<sha>` 后 `GIT_SEQUENCE_EDITOR=: git rebase -i --autosquash <base>`（编辑器设 `:` 空操作），可在无 `-i` 交互环境下把 fixup squash 进目标 commit。base 用 merge-base 避免撞上目标分支的新提交。
