- **再修订(用户反馈「圆点没和竖线对齐、竖线跟着转盘走」)**:把「橙色中心竖线 + 圆点」从滚动条内**移到固定叠加层**(`centerTickRow` top:20 + `knobRow` top:4,都 `alignItems:center` → 恒居中对齐);滚动条只留淡色 idle 刻度 + 数字(选中数字变橙)。中心标记不再随转盘移动、knob 与竖线永远对齐。这是 ruler-picker 标准做法(固定中心指示器 + 刻度滚动)。
- **三修订(用户反馈「到达刻度时深色竖线应和浅色重合」)**:Android `snapToInterval` 会停在非精确位 → 固定橙线与滚动浅刻度错位。`onScrollEndDrag`/`onMomentumScrollEnd` 时 `scrollTo(offsetForHeight(height), animated)` 精确吸附;并按卡片 1px `borderWidth` 修正 `sidePad` 中心偏移(`(width - 2*BORDER - STEP)/2`)。
- **四修订(用户反馈「滚动卡住」)**:上一步的手动 `settle`(`onScrollEndDrag`/`onMomentumScrollEnd` scrollTo)会打断原生惯性/吸附,滚动发涩发卡 → **移除手动 settle**,只靠原生 `snapToInterval` 精确吸附(配合边框修正即对齐)。教训:别在 ScrollView 滚动结束事件里手动 `scrollTo` 去和原生 snap 抢,会卡。
- **五修订(用户反馈「滚动越多偏移越大」)**:累积漂移。根因:N 个 `width:STEP_PX` 的 flex 槽依次堆叠,每槽宽度各自取整到设备整像素、误差**逐槽累加**,而 `snapToInterval`/取值用精确 `STEP`,越滚越错开。修法:每个刻度改**绝对定位** `left = innerHalf - STEP/2 + i*STEP`(从原点算,误差恒 <0.5px、不累积)+ 显式 `contentContainerStyle` 宽高。**教训:等距刻度尺不要用 flex 堆叠固定宽度格,要用绝对 left 从原点定位,否则设备像素取整会累积漂移。**
- **六修订(用户又反馈「数值越大偏移越大」)**:进一步把 `snapToInterval` 换成 **`snapToOffsets`**(显式列出每刻度精确偏移 `i*STEP`,与刻度绝对定位同源),让吸附点逐像素对齐刻度,消除平台 interval 吸附 + 像素取整的残留累积偏移。**注意**:该修复(43771eb7 绝对定位 + 684272aa snapToOffsets)可能未进测试同学当时的构建——「数值越大偏移越大」正是旧 flex 版症状,需出含这两个 commit 的新包验证。

### 06:50 — R00278 feed 发帖页键盘遮挡上传区修复(PR #372)

- **现象**:feed 点 ➕ 进发帖页,自动聚焦拉起的键盘遮住下方照片上传区(➕),够不到。
- **根因**:`post/new.tsx` 的 `ScrollView` 没 `flex:1`、也没 `KeyboardAvoidingView`——iOS 完全不避让;Android 虽 `softwareKeyboardLayoutMode:"resize"`,但 ScrollView 未撑满剩余空间难滚到键盘上方;加上 `minHeight:390` 大文本框把照片区推很下。

- **修订(用户反馈「上传区没有随键盘往上」)**:光加 KAV 不够——上传区在 ScrollView **内部**、不在底部,键盘起时不跟随。**只有 KAV 列底部锚定的元素才会顶到键盘上方**(聊天输入栏就是这么工作的:`chat/[id].tsx` KAV 列 = Header + FlatList(flex:1) + 底部输入栏)。把照片 grid+➕+hint 移出 ScrollView、作为 KAV 列最底部的 `tray`,文本区在其上滚动。koda **无** `react-native-keyboard-controller`(见 `delete-account-sheet.tsx` 注释),只能靠 RN KAV + Android `softwareKeyboardLayoutMode:"resize"`。
- **再修订(用户反馈「还是没随键盘上升」)——真根因**:koda 是 edge-to-edge(SDK 57 默认),**Android edge-to-edge 下 `adjustResize` 不再真正 resize RN 根视图,RN 的 `KeyboardAvoidingView` 在 Android 完全失效**(bottom-anchored 也不动)。这就是 iris 用 `react-native-keyboard-controller` 的原因。**修法**:给 koda 接入 `react-native-keyboard-controller`(catalog dep)+ 根布局 `KeyboardProvider` + compose 改用其 `KeyboardAvoidingView`(`behavior="padding"` 两端生效)。**⚠️ 原生依赖,需重新出 EAS 包,不能 OTA。** **教训:Android edge-to-edge(SDK 57+)下 RN KeyboardAvoidingView 不可靠,键盘避让必须用 react-native-keyboard-controller(KeyboardProvider + 其 KAV/KeyboardStickyView)——iris 已是此方案。**
