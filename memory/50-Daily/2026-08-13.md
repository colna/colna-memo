**背景**:端组 CHAT_HISTORY 的 `creatorSocialId`/`manSocialId` 来自消息 `senderId`——端 refreshIdentity 取「最后一条 sender=me 的 senderId → selfUserId(creatorSocialId)」「最后一条 sender=them 的 senderId → peerUserId(manSocialId)」;空值不覆盖旧值。而脚本原来的 senderId 是 fiber 抽的 Snapchat 用户 UUID,不是后端想要的口径。

**改动**(commit `b477f6849`,已上传 v110):getChatMessages Collect 步提取后覆盖每条消息 senderId:
- `sender==="me"` → `senderId = 入参 womanSocialId`(ctx 新捕获 `params.womanSocialId||womanIGId`)
- `sender==="them"` → `senderId = ""`
- 不动消息 id(`conversationId:orderKey`),只改 senderId。

**效果**:端 `creatorSocialId` = womanSocialId(已知操作账号 handle);`manSocialId` = 空串(them senderId 空,端空值不覆盖故保持空);`manSocialNickname` 仍真名。用户确认后端认男方靠 chatId + manSocialNickname,不需要 manSocialId。

**链路参考(端 GraceChat p/ljb/snpachat)**:`BridgeSyncActions.uploadSnapMessages` selfUserId=`messages.lastOrNull{sender==SENDER_ME("me") && senderId非空}?.senderId` → `SnapChatStateDao.refreshIdentity`(newSelf=空则保留旧值)→ `ActionDispatcher.startUploadSnap` `creatorSocialId to state.selfUserId`。
