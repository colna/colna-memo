## 工作日志 — HH:MM 订正 T10303/T10316(超时邀请仍显示)真 bug + 修复上线到 test-admin

**背景**:张峥质疑 T10303(女用户超时未确认新人入池邀约,新人池仍显示)。核查发现我上一轮判「已实现免改」**有误**。

**根因**:`business-minerva-pwa-pool/src/pwa-pool.sql.ts` 池列表 `POOL_LIST_UNION` + 计数 `POOL_COUNTS` 的邀请分支只过滤 `status='PENDING'`,**未判 expires_at**;dora 过期 job(约每日 01:07 ET)才把 PENDING→EXPIRED,有延迟窗口 → 用户超时后、job 跑前,邀请仍 PENDING,后台照显。等 job 才消失,最长近 24h。

**修法**:两处邀请分支加 `AND i.expires_at > NOW()`,读侧即时排除已超时邀请,不等 job。lint 过(SQL 字符串改动、类型中性)。

**上线**:2 commit(`fix(business-minerva-pwa-pool)` c485dcc35 + docs 23412c88c)→ push origin @23412c88 → 合 release/test-admin(无冲突)→ push @c85e9394(仍 `--no-verify` 绕 payhub 无关包)。Base T10303/T10316(record recvtE9V4n2jUP / recvtGQJwRSFSu)状态 → 已解决待验证。

**残留(dora 侧,非本 repo,已告知张峥)**:「过期后无法再派发邀请」—— `PwaTierCandidateScanner` 排除「有 PENDING 邀请」用户,同因 flip 延迟,过期未翻状态前选不中,须等 job 翻 EXPIRED 后下轮才可重派。即时化需 dora 改(读时判过期 / 缩短 job 间隔)。

**教训**:「靠定时 job 翻状态」的字段,读侧展示不能只信状态列,要叠加时间条件(expires_at)即时判定,否则有 job 间隔的延迟窗口 bug。已并入 troubleshooting 思路(与读侧过滤同类)。
