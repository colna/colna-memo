## 工作日志 — 02:43 sitin-next 直播 GoLive 建房从 WS 改为普通 HTTP

- **做了什么**:在 `sitin-next2` 的 `personal/zz/live` 分支(直播需求,规范模式,未 commit/push),把「Go Live & Earn」的建房接口 `requestGoLive` 从 WS 长连接改成普通 HTTP。
  - 新增 `packages/app-pwa/src/http/liveApi.ts` 的 `requestGoLive()`,走 `httpClient.requestPost2(LiveGoLiveRequest, {hostUserId,title?,dateModeOn?}, LiveGoLiveResponse)`(与 chatApi/liveApi 其它接口同构,proto id 8002/8003 走 protoMap)。
  - `packages/app-pwa/src/utils/startHostLive.ts`:import 从 `@/network/ws/liveGoLive` 改为 `@/http/liveApi`。函数签名/返回 `LiveGoLiveResponse` 不变,`!resp.roomId` 守卫照旧。
  - 删除 `packages/app-pwa/src/network/ws/liveGoLive.ts`(旧 WS 建房,一次性 listener + 10s 超时包 Promise)。
- **为什么**:用户指出这个接口本就是普通接口、不该走 WS。排查「App 里点 Go Live & Earn 没反应」时定位到旧 WS 版所有失败路径都是静默(WS 没连上 → sendMessage 返回 false → requestGoLive reject → 被 `void startHostLiveStream()` 吞掉)。
- **结果**:改动 3 文件(2 改 1 删)。`liveApi.ts` + `startHostLive.ts` eslint 0 error;tsc grep 这俩文件无报错(裸跑 tsc 有一堆 `bff.ts` unknown 报错是未构建 proto dist 的既有环境噪声,与本次无关)。改 HTTP 后建房失败会走 httpClient 的 Sentry `[API Error]` 上报,好排查。
- **关键命令 / diff**:`npx eslint src/http/liveApi.ts src/utils/startHostLive.ts`(exit 0)。
- **沉淀**:`startHostLive` 仍缺 try/catch + 失败 toast + 建房中 loading,任意一步失败仍是「点了没反应」——已向用户提议补,待确认(follow-up)。GoLive 走 HTTP 而非 WS 的判断依据:该接口是一问一答的 RPC,不需要绑定在线长连接/服务端主动推(建房 8003 是同步响应)。
