## 工作日志 — Snapchat getChatMessages 增量拉取：现状定性 + fiber 探针

- **需求**：Snapchat 聊天记录没有唯一 id，想拼出每条记录的唯一 id 以支持增量拉取（客户端回传上次的最后一个 id，从那之后拉），且要处理**连续重复消息**。

### 查证结论（先定性，别急着写方案）

- **现有 id 完全不可用**：`messages[k].id = "sc_msg_" + k`（`src/snapchat/methods/getChatMessages.js:475`）是**纯位置**的，而且在 `maxCount` 截断**之后**才分配 —— maxCount 一变或新消息到达，同一条消息 id 就变。
- **DOM 里挖不到替代品**（逐项查证 `dom/snapchat/chat2-page.html`）：
  - per-message id：**无**。`li` 上无 id / 无 `data-*` / 无 `aria-labelledby`
  - per-message 时间戳：**无**。会话内只有日分隔符 `<time datetime="June 5">`，**日级精度且是本地化串**（中文 UI 变「6月5日」）
  - ISO 时间戳：有，但在**左侧会话列表**，`<time datetime="2026-06-05T08:52:03.755Z">` 配 `id="status-<uuid>"` —— 是**会话级** last-activity，不是消息级
  - 会话 id：有，`ul[id="cv-<uuid>"]`
- **IG 对照**：IG 有真 mid，从 `aria-labelledby="mid.$..."` 抠（`src/instagram/methods/getChatMessages.js:310`），增量逻辑 `extractNewMessages(lastMessageId)`（:625-693）直接按 id 定位。SC 无对应物 = 方案文档未决点 **R1**。
- **关键判断**：`cv-<uuid>` 说明前端**有 id 概念**，只是没渲染到 DOM 属性。SC web 是 React → **先探 fiber，挖得到真 id 整个合成方案就不用做**。

### 沉淀（值得记的判断）

- **头号候选是 `fiber.key`** —— 列表渲染必须给 key，key 通常就是业务 id。
- **`UNIQUE` 不等于「稳定」** —— 消息正文本身就是 UNIQUE 的，取值互不相同证明不了什么。必须：① 看 `samples` 形态（UUID/雪花 = 服务端 id 可用；`"0","1","2"` = 数组下标，和 `sc_msg_k` 一样没用；`"r_0.83..."` = 客户端随机，刷新即变）②**刷新页面**前后比对（fiber 不重建就测不出临时 id）③ 发新消息后确认老 id 不变。
- **fiber 走不通时的回落方案**（已想清，待验证后再落）：
  - `fp = sha1(sender | type | normalizedContent)`；`id = sha1(prevFp | fp | runIdx)`，`runIdx` = 连续同内容跑批内序号。
  - 这样「在吗/哈哈/哈哈/哈哈」三条哈哈的 `(prevFp, runIdx)` 分别是 `(在吗,0)`/`(哈哈,1)`/`(哈哈,2)` → id 全不同；被隔开的两条「哈哈」prevFp 不同 → 也不同；上游删一条**只影响紧邻下一条**，不像全链 hash 整段失效。
  - **fingerprint 里不能放 date** —— `datetime="June 5"` 是本地化串，中文 UI 下 id 就变了。
  - **游标别只存一个 id**，存尾部 3~5 条 fp 序列（对外编码成一个不透明字符串），**从尾部倒着匹配取最后一次命中**；miss → `cursorMissed: true` 回落全量，服务端按 id upsert 兜底。
- **⭐ 最大收益点其实不在 id**：DOM 全量扫描省不掉（消息就在 DOM 里），但 **Step 5 的 base64 转换**（`getChatMessages.js:662-702`）把所有 image/audio 的 blob 全转一遍，是最贵的一步 + 回传体积大头。**把 cursor diff 提到 base64 之前**，只转新消息的媒体，这才是「不每次拉全量」的实际落地。
- **媒体消息 contentKey 很弱**：图片 `text` 统一是 `"[Image]"`，`blob:` URL 每次刷新都变、不能入 fingerprint。同天两张不同图会撞 fp，只能靠 `prevFp`+`runIdx` 区分。多图气泡拆出的多条（:184-200）和贴纸那条 `_domIndex + 0.5`（:458）要带子序号，否则同气泡内互撞。可考虑把 `aspect-ratio` 值补进 contentKey。
